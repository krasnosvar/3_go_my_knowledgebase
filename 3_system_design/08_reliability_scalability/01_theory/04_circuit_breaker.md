# Circuit Breaker (предохранитель)

Circuit breaker («автоматический выключатель») защищает вызывающий сервис от зависимости, которая начала отказывать. Идея — как электрический предохранитель: при серии сбоев «размыкаем цепь» и перестаём слать запросы к падающей зависимости, давая ей восстановиться и не тратя ресурсы на заведомо провальные вызовы.

## Проблема, которую он решает

Когда зависимость (БД, соседний сервис) начинает тормозить или отдавать ошибки, наивный клиент продолжает слать запросы и ждать таймаутов. Это:

- копит зависшие горутины/соединения и **исчерпывает пулы**;
- добивает и без того больную зависимость;
- задержки распространяются вверх по цепочке вызовов — **каскадный отказ**.

Circuit breaker быстро отвечает ошибкой (fail fast), не нагружая зависимость, и периодически проверяет, ожила ли она.

## Три состояния

- **Closed (замкнут)** — нормальная работа: запросы идут к зависимости. Считаем сбои; при достижении порога (например, N ошибок подряд или доля ошибок > X%) переходим в **Open**.
- **Open (разомкнут)** — запросы к зависимости **не идут**, сразу возвращается ошибка (fail fast). По истечении таймаута восстановления переходим в **Half-Open**.
- **Half-Open (полуоткрыт)** — пробный режим: пропускаем ограниченное число «разведочных» запросов. Успех → зависимость ожила → **Closed** (счётчики сброшены). Провал → снова **Open** (таймаут перезапускается).

```
                  ошибок >= порога
      ┌───────────────────────────────────┐
      v                                     │
  ┌────────┐   таймаут истёк    ┌──────────┐│
  │ CLOSED │ ─────────────────> │HALF-OPEN │┘
  │        │                    │(пробный) │
  └────────┘ <───────────────── └──────────┘
      ^        success:            │
      │        закрыть             │ провал пробного запроса
      │                            v
      │                       ┌────────┐
      └────────── ... ────────│  OPEN  │  (fail fast, ждём таймаут)
                              └────────┘
```

## Ключевые параметры

- **Порог срабатывания** — сколько ошибок (подряд или доля за окно) размыкает цепь.
- **Open timeout** — как долго держим Open перед пробой (часто с backoff, если пробы снова падают).
- **Что считать сбоем** — таймауты, 5xx, ошибки соединения. Бизнес-ошибки (4xx, «нет такого пользователя») сбоем **не** считаются — иначе цепь размыкается на здоровой зависимости.
- **Half-open probes** — сколько пробных запросов пропускать и сколько успехов нужно для закрытия.

## Связь с соседними паттернами

- **Timeout** — без таймаута circuit breaker не увидит «зависшую» зависимость (вызов не завершится).
- **Retries** — ретраи *под* breaker'ом: если цепь разомкнута, повторять бессмысленно, breaker обрывает лавину повторов.
- **Fallback** — при Open можно вернуть кэш, значение по умолчанию или деградированный ответ вместо ошибки.
- **Bulkhead** — изоляция пулов ресурсов по зависимостям, чтобы одна падающая не съела ресурсы всех.

> ⚠️ Частый вопрос на собеседовании: зачем нужно состояние Half-Open? Чтобы проверить восстановление зависимости, не открывая ей сразу весь трафик. Пропускаем несколько пробных запросов: успех — закрываемся, провал — снова Open. Иначе пришлось бы либо гадать, либо разом обрушить на едва ожившую зависимость полную нагрузку.

> ⚠️ Частый вопрос на собеседовании: чем circuit breaker отличается от retry? Retry повторяет одиночный вызов, надеясь на временный сбой; circuit breaker — про общее состояние зависимости: он вовсе прекращает вызовы к явно неработающей зависимости (fail fast), предотвращая каскадный отказ. Их применяют вместе.
