# API Styles — шпаргалка

Подробности и объяснения — в [01_theory/](./01_theory/). ⚠️ — частая ловушка.

## Что выбрать

Подробно: [05_choosing.md](./01_theory/05_choosing.md).

| Критерий | REST | gRPC | GraphQL |
| :--- | :--- | :--- | :--- |
| Транспорт | HTTP/1.1, HTTP/2 | HTTP/2 | обычно HTTP/1.1 (`POST /graphql`) |
| Формат | JSON | Protobuf (бинарь) | JSON |
| Контракт | опционально (OpenAPI) | строгий (`.proto`) | строгий (SDL) |
| Форму ответа задаёт | сервер (эндпоинт) | сервер (метод) | клиент (запрос) |
| Стриминг | SSE / WebSocket | 4 типа вызовов | `Subscription` (поверх WS) |
| Браузер нативно | да | нет (gRPC-Web) | да |
| Отладка | `curl`, высокая | бинарь, низкая | средняя |
| HTTP-кэширование | простое (GET + ETag) | нет | сложное (один `POST`) |

| Потребитель | Стиль |
| :--- | :--- |
| Публичный API, интеграторы, браузер; «сомневаюсь» | REST + OpenAPI |
| Внутренние сервисы: латентность, стриминг, строгий контракт | gRPC + Protobuf |
| Много фронтендов с разными срезами данных | GraphQL |
| Внутренний сервис без особых требований | REST |
| Гибрид | REST/GraphQL наружу через gateway, gRPC внутрь; GraphQL как BFF; REST + вебхуки/SSE |

## REST

Подробно: [01_rest.md](./01_theory/01_rest.md).

| Правило | Пример |
| :--- | :--- |
| Существительные, не глаголы | `/users`, не `/getUsers` |
| Коллекции во множественном числе | `/users`, `/orders` |
| Иерархия вложенностью | `/users/42/orders/7` |
| Действие — методом | `DELETE /users/42` |

| Метод | Safe | Идемпотентный | Назначение |
| :--- | :--- | :--- | :--- |
| `GET` / `HEAD` / `OPTIONS` | да | да | чтение / без тела / методы |
| `PUT` | нет | да | заменить целиком (неприсланное затирается) |
| `DELETE` | нет | да | удалить |
| `PATCH` | нет | в общем случае нет (`+1`) | частично изменить |
| `POST` | нет | нет | создать / действие |

| Операция | Код |
| :--- | :--- |
| `GET /users/42` найден / нет | `200` / `404` |
| `POST /users` создан | `201` + `Location: /users/43` |
| `PUT /users/42` | `200` (или `204` без тела) |
| `DELETE /users/42` | `204` |
| Невалидное тело / дубликат | `400` / `409` (также `422`) |
| Асинхронно принято | `202 Accepted` |
| Не аутентифицирован / нет прав | `401` / `403` |
| Лимит запросов | `429` |

| Версионирование | Пример | Плюс / минус |
| :--- | :--- | :--- |
| В пути (самое частое) | `GET /v1/users` | явно, кэшируется, роутится |
| В заголовке | `Accept: application/vnd.example.v2+json` | чистый URL / сложнее отлаживать |
| В query | `GET /users?version=2` | просто / теряется при копировании ссылок |

| Пагинация | Запрос | Когда |
| :--- | :--- | :--- |
| offset/limit | `?limit=20&offset=40` | админки, прыжок на страницу; медленно на больших `OFFSET`, дубли/пропуски при вставках |
| cursor/keyset | `?limit=20&after=eyJpZCI6NDB9` | ленты, большие наборы; стабильно и быстро, без прыжков |

## gRPC

Подробно: [02_grpc.md](./01_theory/02_grpc.md).

| Тип вызова | `.proto` | Сценарий |
| :--- | :--- | :--- |
| Unary | `rpc Get(Req) returns (Resp);` | ~95% случаев |
| Server streaming | `returns (stream Resp)` | лента событий, выгрузка порциями |
| Client streaming | `rpc Up(stream Req) returns (Resp)` | загрузка чанками, батч телеметрии |
| Bidirectional | `(stream Req) returns (stream Resp)` | чат, live-обновления |

| Факт | Детали |
| :--- | :--- |
| Почему HTTP/2 | мультиплексирование, бинарные фреймы, двунаправленные streams, HPACK |
| Вызов на проводе | один RPC = один HTTP/2-поток; метаданные — заголовки, payload — DATA |
| Генерация | `protoc` + `protoc-gen-go` → `*.pb.go`; `protoc-gen-go-grpc` → `*_grpc.pb.go` |
| Вызов в Go | `client.GetUser(ctx, &GetUserRequest{Id: 42})` |
| Дедлайн | `context` с таймаутом на каждый вызов |

## Protobuf

Подробно: [03_protobuf.md](./01_theory/03_protobuf.md).

| Тема | Суть |
| :--- | :--- |
| `= 1` в поле | номер поля (field tag); на проводе только он, имени нет |
| Ключ поля | `(field_number << 3) \| wire_type` |
| wire_type | `0` varint, `1` 64-бит, `2` length-delimited (string/bytes/message), `5` 32-бит |
| Номера 1–15 | ключ в 1 байт → для частых полей |
| Отрицательные | `sint32`/`sint64` (zig-zag) |
| Размер | `{"id":42,"name":"Alice"}` ≈24 байта vs `08 2A 12 05 41 6C 69 63 65` = 9 байт |
| proto3 незаполненное поле | читается как `0` / `""` / `false` |

| Изменение схемы | Можно? |
| :--- | :--- |
| Добавить поле с новым номером | да (старый код пропустит) |
| Сменить номер поля | нет — ломает всех |
| Удалить поле | да + `reserved 3, 5 to 7;` и `reserved "email";` |
| Переиспользовать удалённый номер | нет |
| Переименовать поле | на проводе да, в коде — ломает |
| `int32` ↔ `int64` ↔ `bool` | совместимы (varint) |
| `int` → `string` | нет |

## GraphQL

Подробно: [04_graphql.md](./01_theory/04_graphql.md).

| Элемент | Синтаксис |
| :--- | :--- |
| Обязательное поле | `name: String!` |
| Непустой список ненулевых | `orders: [Order!]!` |
| Чтение | `query { user(id: "42") { name orders { total } } }` |
| Изменение | `mutation { createUser(name: "Bob") { id name } }` |
| Поток | `Subscription` (обычно WebSocket) |
| Ответ | `{"data": {...}}` — повторяет форму запроса |

| Проблема | Решение |
| :--- | :--- |
| Over-fetching (лишние поля) | клиент выбирает поля |
| Under-fetching (N запросов на клиенте) | связанные сущности одним запросом |
| N+1 к БД на сервере | DataLoader: батч `WHERE user_id IN (...)` + кэш в пределах запроса → 2 запроса |
| Дорогие вложенные запросы | лимит глубины/сложности |

## Корректность

Подробно: [06_use_cases.md](./01_theory/06_use_cases.md).

| Паттерн | Как |
| :--- | :--- |
| Retry POST | `Idempotency-Key`: сервер запоминает результат по ключу; или `PUT` по известному ID |
| Retry вообще | 4xx — не повторять; 5xx и 429 — с backoff |
| Таймауты | `context` с дедлайном; `http.Client{Timeout: ...}` |
| Коллекции | всегда пагинация |
| Эволюция | только новые опциональные поля; ломающее → `/v2` или новые номера полей |

## Ловушки

- ⚠️ `200` с `{"error": ...}` в теле ломает retry, кэши и мониторинг.
- ⚠️ POST без Idempotency-Key → дубликаты при retry.
- ⚠️ Список без пагинации → тяжёлые ответы и OOM.
- ⚠️ Смена номера поля в Protobuf тихо ломает совместимость.
- ⚠️ GraphQL без DataLoader и лимита сложности кладёт БД.
- ⚠️ gRPC в браузер без gRPC-Web не работает.
- ⚠️ Глаголы в URL (`/getUser`) — не REST.
