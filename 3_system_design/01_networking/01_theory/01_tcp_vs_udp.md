# TCP vs UDP

TCP и UDP — два основных транспортных протокола поверх IP. Оба работают с портами и адресуют приложения, но дают принципиально разные гарантии.

## TCP (Transmission Control Protocol)

Надёжный, ориентированный на соединение (connection-oriented) протокол.

- **Установка соединения** — трёхстороннее рукопожатие (three-way handshake): `SYN → SYN-ACK → ACK`.
- **Гарантия доставки** — потерянные сегменты переотправляются (retransmission).
- **Порядок** — байты приходят в том же порядке, в котором отправлены (за счёт sequence numbers).
- **Контроль потока (flow control)** — окно приёма (receive window), чтобы не завалить медленного получателя.
- **Контроль перегрузки (congestion control)** — slow start, congestion avoidance и т.п., чтобы не перегрузить сеть.
- **Поток байтов (stream)** — нет понятия «сообщения»; границы записей приложение задаёт само (длина, разделитель).

```
Клиент                      Сервер
  |------------ SYN -------->|
  |<-------- SYN-ACK --------|
  |------------ ACK -------->|
  |     соединение готово    |
  |==== обмен данными ======>|
  |<========================|
  |------------ FIN -------->|   (закрытие)
  |<----------- ACK ---------|
```

## UDP (User Datagram Protocol)

Ненадёжный, без установки соединения (connectionless) протокол.

- **Нет рукопожатия** — сразу отправляем датаграмму.
- **Нет гарантии доставки** — пакет может потеряться, и никто не переотправит.
- **Нет гарантии порядка** — датаграммы могут прийти не по порядку или продублироваться.
- **Сохранение границ сообщений** — одна отправка = одна датаграмма (message-oriented).
- **Минимальные накладные расходы** — заголовок 8 байт против 20+ у TCP; нет состояния соединения.

## Сравнение

| Характеристика        | TCP                          | UDP                        |
|-----------------------|------------------------------|----------------------------|
| Соединение            | да (handshake)               | нет                        |
| Доставка              | гарантирована                | best-effort                |
| Порядок               | сохраняется                  | не гарантируется           |
| Границы сообщений     | нет (поток байтов)           | есть (датаграммы)          |
| Контроль перегрузки   | есть                         | нет (реализуется в приложении) |
| Заголовок             | 20+ байт                     | 8 байт                     |
| Скорость/задержка     | выше задержка (ACK, retrans) | ниже задержка              |

## Когда что использовать

- **TCP** — HTTP/1.1, HTTP/2, gRPC, базы данных, любой обмен, где важна целостность и порядок.
- **UDP** — DNS-запросы, видео/аудио-стриминг, онлайн-игры, метрики/логи (statsd), QUIC (и поверх него HTTP/3). Там, где потеря отдельного пакета менее критична, чем задержка.

> ⚠️ Частый вопрос на собеседовании: почему DNS исторически использует UDP? Один короткий запрос-ответ помещается в одну датаграмму, а накладные расходы на установку TCP-соединения были бы неоправданно велики. При больших ответах (или zone transfer) DNS переключается на TCP.

> ⚠️ Частый вопрос на собеседовании: гарантирует ли TCP, что `Write` на стороне отправителя соответствует одному `Read` на стороне получателя? Нет. TCP — это поток байтов, границы сообщений не сохраняются; приложение должно само их разграничивать.
