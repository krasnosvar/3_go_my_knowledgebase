# HTTP и HTTPS

HTTP (HyperText Transfer Protocol) — прикладной текстовый протокол запрос-ответ поверх TCP. HTTPS — это тот же HTTP, но внутри защищённого канала TLS.

## Структура запроса и ответа (HTTP/1.1)

```
Запрос:
GET /users/42 HTTP/1.1          <- стартовая строка: метод, путь, версия
Host: api.example.com           <- заголовки (headers)
Accept: application/json
User-Agent: curl/8.0
                                <- пустая строка = конец заголовков
(тело запроса, если есть)       <- body (для POST/PUT)

Ответ:
HTTP/1.1 200 OK                 <- статусная строка: версия, код, причина
Content-Type: application/json  <- заголовки
Content-Length: 27

{"id":42,"name":"Alice"}        <- тело ответа
```

## Методы

- **GET** — получить ресурс. Безопасный (safe) и идемпотентный, без тела.
- **POST** — создать/отправить данные. Не идемпотентный.
- **PUT** — заменить ресурс целиком. Идемпотентный.
- **PATCH** — частично изменить ресурс.
- **DELETE** — удалить ресурс. Идемпотентный.
- **HEAD** — как GET, но без тела ответа (только заголовки).
- **OPTIONS** — узнать поддерживаемые методы/CORS.

**Идемпотентность** — повторный вызов даёт тот же результат на сервере (важно для retry). GET, PUT, DELETE идемпотентны; POST — нет.

## Коды статусов (категории)

| Диапазон | Категория      | Смысл                         | Примеры                         |
|----------|----------------|-------------------------------|---------------------------------|
| 1xx      | Informational  | промежуточный ответ           | 100 Continue, 101 Switching     |
| 2xx      | Success        | успех                         | 200 OK, 201 Created, 204 No Content |
| 3xx      | Redirection    | нужно перейти по другому адресу | 301 Moved, 302 Found, 304 Not Modified |
| 4xx      | Client Error   | ошибка на стороне клиента     | 400, 401, 403, 404, 429         |
| 5xx      | Server Error   | ошибка на стороне сервера     | 500, 502, 503, 504              |

## Важные заголовки

- **Host** — какой виртуальный хост запрашиваем (обязателен в HTTP/1.1).
- **Content-Type** — MIME-тип тела (`application/json`, `text/html`).
- **Content-Length** — размер тела в байтах.
- **Transfer-Encoding: chunked** — тело передаётся частями без заранее известной длины.
- **Authorization** — токен/креды (`Bearer ...`).
- **Cache-Control**, **ETag**, **If-None-Match** — управление кэшированием.
- **Connection: keep-alive** — переиспользовать TCP-соединение.

## Keep-Alive и переиспользование соединений

В HTTP/1.0 на каждый запрос открывалось новое TCP-соединение (и заново handshake + TLS). В HTTP/1.1 **keep-alive включён по умолчанию**: одно TCP-соединение переиспользуется для нескольких последовательных запрос-ответов. Это экономит рукопожатия и снижает задержку.

Ограничение HTTP/1.1 — **head-of-line blocking**: по одному соединению запросы обрабатываются строго по очереди; медленный ответ задерживает следующие. Браузеры обходят это, открывая несколько параллельных соединений; кардинально проблему решает HTTP/2 (см. `04_http2.md`).

## HTTPS = HTTP over TLS

HTTPS — это HTTP, обёрнутый в TLS (порт 443 по умолчанию). Он даёт:

- **Конфиденциальность** — трафик зашифрован.
- **Целостность** — подмена данных обнаруживается.
- **Аутентификацию сервера** — сертификат подтверждает, что вы говорите именно с example.com.

Детали установки защищённого канала — в `07_tls_handshake.md`.

> ⚠️ Частый вопрос на собеседовании: чем отличаются 401 и 403? 401 Unauthorized — не аутентифицирован (кто ты — неизвестно, залогинься). 403 Forbidden — аутентифицирован, но нет прав на ресурс.

> ⚠️ Частый вопрос на собеседовании: 502 vs 503 vs 504? 502 Bad Gateway — прокси получил невалидный ответ от upstream. 503 Service Unavailable — сервис временно недоступен/перегружен. 504 Gateway Timeout — upstream не ответил вовремя.
