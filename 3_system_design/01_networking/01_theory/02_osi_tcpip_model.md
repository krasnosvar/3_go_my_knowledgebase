# Модель OSI и стек TCP/IP

Сетевое взаимодействие принято описывать слоями (layers): каждый слой решает свою задачу и опирается на нижележащий. Есть две модели — теоретическая **OSI** (7 уровней) и практическая **TCP/IP** (4 уровня).

## Модель OSI (7 уровней)

```
+---+----------------------+---------------------------------------------+
| 7 | Application          | HTTP, DNS, FTP, SMTP — прикладные протоколы  |
| 6 | Presentation         | кодировки, сжатие, шифрование (TLS условно)  |
| 5 | Session              | сессии, диалоги между приложениями           |
+---+----------------------+---------------------------------------------+
| 4 | Transport            | TCP, UDP — порты, сегменты/датаграммы        |
| 3 | Network              | IP, ICMP — адресация, маршрутизация пакетов  |
| 2 | Data Link            | Ethernet, ARP, MAC — кадры внутри сегмента   |
| 1 | Physical             | биты по кабелю/радио                         |
+---+----------------------+---------------------------------------------+
```

## Стек TCP/IP (4 уровня) — как на практике

```
+------------------+----------------------------+   соответствие OSI
| Application      | HTTP, DNS, TLS, gRPC       |   ~ 5–7
| Transport        | TCP, UDP                   |   4
| Internet         | IP, ICMP                   |   3
| Link             | Ethernet, Wi-Fi, ARP       |   1–2
+------------------+----------------------------+
```

## Инкапсуляция

При отправке данные «оборачиваются» заголовками сверху вниз, при приёме — разворачиваются снизу вверх:

```
[ HTTP-данные ]
[ TCP-заголовок | HTTP-данные ]                 -> сегмент
[ IP-заголовок | TCP-заголовок | HTTP-данные ]  -> пакет
[ Ethernet | IP | TCP | HTTP | CRC ]            -> кадр (frame)
```

Каждый слой добавляет свой заголовок (и иногда трейлер) и не заглядывает в полезную нагрузку соседнего слоя — это и есть принцип инкапсуляции.

## Где живут привычные протоколы

- **HTTP / DNS / gRPC** — прикладной уровень (L7).
- **TLS** — формально между прикладным и транспортным; удобно думать о нём как о защищённой обёртке поверх TCP (L4).
- **TCP / UDP** — транспортный уровень (L4), работают с портами.
- **IP** — сетевой уровень (L3), работает с IP-адресами и маршрутизацией.
- **Ethernet / MAC / ARP** — канальный уровень (L2).

## Зачем это знать инженеру

Модель слоёв помогает локализовать проблему: «резолвится ли имя» — это DNS (L7 поверх UDP/L4); «доходят ли пакеты» — ICMP/ping (L3); «открывается ли порт» — TCP-connect (L4); «валиден ли сертификат» — TLS. Диагностику ведут снизу вверх: сначала IP-связность, потом порт, потом TLS, потом сам HTTP.

> ⚠️ Частый вопрос на собеседовании: на каком уровне работает балансировщик? L4-балансировщик распределяет по TCP/UDP-соединениям (по IP:port), не заглядывая в содержимое; L7-балансировщик понимает HTTP и может маршрутизировать по URL, заголовкам, cookie.
