# Networking: практические применения

Краткий обзор того, как сетевые основы всплывают в реальной инженерной практике и в задачах System Design.

## Выбор транспорта под задачу

- **TCP** — REST/gRPC API, работа с БД, передача файлов: важны целостность и порядок.
- **UDP** — телеметрия/метрики (statsd), VoIP, стриминг, игровые протоколы: важнее низкая задержка, потеря отдельного пакета терпима.
- **QUIC/HTTP/3** — мобильные клиенты с нестабильной сетью (connection migration) и высокие требования к latency.

## Выбор версии HTTP

- **HTTP/1.1** — простые сервисы, отладка вручную (текстовый протокол), внутренние вызовы без высокой конкурентности.
- **HTTP/2** — много параллельных запросов к одному хосту (браузер, gRPC), экономия за счёт мультиплексирования и HPACK.
- **HTTP/3** — публичные сервисы с мобильной аудиторией, где критична задержка и устойчивость к потерям пакетов.

## Correctness-паттерны в API

- **Идемпотентность и retry** — повторять безопасно только идемпотентные методы (GET, PUT, DELETE). Для POST — идемпотентные ключи (`Idempotency-Key`).
- **Коды статусов** — 4xx для ошибок клиента (не ретраить бездумно), 5xx/429 — кандидаты на retry с backoff.
- **Timeout и context** — всегда ограничивать время запроса (в Go — `context.WithTimeout` + `http.Client{Timeout}`), иначе висящее соединение исчерпает пул.
- **Connection pooling** — переиспользование keep-alive соединений (в Go — `http.Transport` с настройкой `MaxIdleConnsPerHost`).

## DNS в эксплуатации

- **Failover / миграция** — заранее снизить TTL, переключить запись, вернуть TTL.
- **Service discovery** — SRV-записи или внутренний DNS (например, Kubernetes CoreDNS: `svc.namespace.svc.cluster.local`).
- **Health-based routing** — DNS с проверками здоровья отдаёт только живые эндпоинты.

## TLS в эксплуатации

- **Терминация TLS** — обычно на балансировщике/ingress; дальше внутри — либо plaintext в доверенной сети, либо mTLS (service mesh).
- **Ротация сертификатов** — автоматизировать (ACME/Let's Encrypt, cert-manager), следить за сроком.
- **mTLS** — взаимная аутентификация клиента и сервера сертификатами, типична для zero-trust и межсервисного трафика.

## Диагностика (снизу вверх по слоям)

```
IP-связность   -> ping / traceroute        (L3)
порт открыт?   -> nc -vz host port / telnet (L4)
TLS валиден?   -> openssl s_client -connect (TLS)
HTTP отвечает? -> curl -v https://...        (L7)
имя резолвится?-> dig / nslookup             (DNS)
```

> ⚠️ Частый вопрос на собеседовании: что происходит, когда вы вводите URL в браузере и жмёте Enter? Ожидаемый ответ проходит через все подтемы раздела: DNS-резолвинг имени → TCP-handshake → TLS-handshake (для HTTPS) → HTTP-запрос → ответ и рендеринг. Умение развернуть эту цепочку по слоям — и есть проверяемый навык.
