# Наблюдаемость — шпаргалка

Подробности и объяснения — в [01_theory/](./01_theory/). ⚠️ — частая ловушка.

## Три столпа

Подробно: [01_three_pillars.md](./01_theory/01_three_pillars.md).

| Столп | Единица данных | Отвечает на вопрос | Объём / цена |
| :--- | :--- | :--- | :--- |
| Метрики | число во времени (ряд) | что и насколько (ошибки, задержка) | низкий, дёшево; враг — кардинальность |
| Логи | событие с полями | что именно произошло | высокий, дорого |
| Трейсы | путь запроса из spans | где в цепочке проблема | высокий, сэмплируют |

| Понятие | Суть |
| :--- | :--- |
| Мониторинг | заранее выбранные показатели и алерты — known unknowns |
| Наблюдаемость | ответы на непредусмотренные вопросы по телеметрии — unknown unknowns |
| Связка столпов | общий `trace_id` в логах, трейсах (и exemplar'ах метрик) |

## Логирование и log/slog

Подробно: [02_logging.md](./01_theory/02_logging.md).

| Уровень | Когда |
| :--- | :--- |
| DEBUG | подробности для отладки; в проде обычно выключен |
| INFO | штатные значимые события |
| WARN | подозрительно, но работает (ретрай, деградация) |
| ERROR | операция не удалась, нужно внимание |

| Задача | `log/slog` (Go 1.21+) |
| :--- | :--- |
| JSON-логгер | `slog.New(slog.NewJSONHandler(os.Stdout, &slog.HandlerOptions{Level: slog.LevelInfo}))` |
| Человекочитаемый | `slog.NewTextHandler(os.Stderr, nil)` |
| Запись с полями | `logger.Info("failed login", "user", "alice", "src_ip", "10.0.0.5")` |
| Дочерний логгер (корреляция) | `reqLogger := logger.With("request_id", "req-42")` |
| Передать `ctx` в handler (достать `trace_id`) | `logger.InfoContext(ctx, "msg", ...)` |
| Порог | `Level` в `HandlerOptions`: ниже порога записи отбрасываются |

```go
package main

import (
	"log/slog"
	"os"
)

func main() {
	logger := slog.New(slog.NewJSONHandler(os.Stdout, &slog.HandlerOptions{Level: slog.LevelInfo}))
	req := logger.With("request_id", "req-42")
	req.Info("failed login", "user", "alice")
	req.Debug("не попадёт: ниже порога")
}
// {"time":"...","level":"INFO","msg":"failed login","request_id":"req-42","user":"alice"}
```

Правило: `msg` — постоянная строка, всё переменное — в поля; `request_id` берут из `X-Request-Id` или генерируют на входе и несут в `context.Context`.

## Метрики

Подробно: [03_metrics.md](./01_theory/03_metrics.md).

| Тип | Поведение | Примеры | Как смотреть |
| :--- | :--- | :--- | :--- |
| Counter | только растёт (сброс в 0 при рестарте) | запросы, ошибки, байты | `rate(http_requests_total[5m])` |
| Gauge | растёт и падает | память, активные соединения, длина очереди | текущее значение, min/max/avg |
| Histogram | счётчики по bucket'ам + сумма + количество | задержка | перцентили p50/p90/p99 на сервере; агрегируется по инстансам |
| Summary | квантили на клиенте | задержка | между инстансами не складывается |

| Методика | Для чего | Сигналы |
| :--- | :--- | :--- |
| RED | сервисы (запросы) — симптомы | Rate, Errors, Duration |
| USE | ресурсы (CPU, диск, сеть, пулы) — причины | Utilization, Saturation, Errors |

| Prometheus | Суть |
| :--- | :--- |
| Модель | pull: Prometheus сам опрашивает `/metrics` раз в scrape interval |
| Плюсы pull | список целей у Prometheus (service discovery), `up == 0` — сигнал, клиент не заваливает коллектор |
| Формат | `http_requests_total{method="GET",status="200"} 1027` + строки `# HELP` / `# TYPE` |
| Ряд | имя + уникальная комбинация меток |
| Push | короткоживущие джобы → Pushgateway |
| Метки | только ограниченные множества: method, status, шаблон endpoint'а |

## Трейсинг

Подробно: [04_tracing.md](./01_theory/04_tracing.md).

| Понятие | Суть |
| :--- | :--- |
| Trace | история одного запроса, общий `trace_id` |
| Span | одна операция: `span_id`, `parent_span_id`, начало и длительность, имя, атрибуты (`http.method`, `db.statement`), статус |
| Propagation внутри процесса | `context.Context` |
| Propagation между сервисами | HTTP-заголовки / gRPC-метаданные |
| W3C Trace Context | `traceparent: 00-<trace_id>-<parent_span_id>-<flags>`; `flags` — бит сэмплирования |
| OpenTelemetry | вендор-независимые API/SDK (`Tracer.Start(ctx, "op")`), propagators, exporter по OTLP, Collector |
| Бэкенды | Jaeger, Tempo |

| Сэмплирование | Решение | Плюс | Минус |
| :--- | :--- | :--- | :--- |
| Head-based | в начале трейса (например, 1%), флаг в `traceparent` | просто, дёшево | может пропустить редкую ошибку |
| Tail-based | после завершения трейса (в коллекторе) | сохраняет все ошибочные и медленные | дороже |

## Пробы, SLO, алерты

Подробно: [05_health_alerting.md](./01_theory/05_health_alerting.md).

| Проба | Вопрос | Провал | Зависимости |
| :--- | :--- | :--- | :--- |
| Liveness | перезапустить контейнер? | убить и перезапустить | **не** проверять внешние |
| Readiness | слать трафик? | убрать из балансировки, без рестарта | можно: прогрев, БД, идёт graceful shutdown |
| Startup | закончился ли медленный старт? | liveness не убьёт во время запуска | — |

| Термин | Суть | Пример |
| :--- | :--- | :--- |
| SLI | измеримый показатель | доля успешных запросов; доля быстрее 300 мс |
| SLO | внутренняя цель по SLI | 99.9% успешных за 30 дней |
| SLA | внешнее соглашение с последствиями; обычно мягче SLO | компенсации клиенту |
| Error budget | `1 − SLO` | для 99.9% — 0.1% неуспеха; исчерпан → заморозка релизов |

| Хороший алерт | Как |
| :--- | :--- |
| На симптом, привязанный к SLO | доля 5xx, p99 сверх SLO, burn-rate error budget |
| Actionable | есть что сделать, иначе шум |
| Не флапает | окно / `for`-задержка: условие держится N минут |
| С контекстом | ссылка на дашборд / раннбук |
| Причины (CPU, диск, GC) | дашборды и вторичные предупреждения, не page |

## Разбор инцидента

Подробно: [06_use_cases.md](./01_theory/06_use_cases.md).

```
пользователю плохо?     -> RED-метрики (errors, p99)       (симптом)
где именно тормозит?    -> трейс запроса, критический путь (локализация)
что конкретно упало?    -> логи по trace_id                (детали)
почему ресурс не тянет? -> USE-метрики (saturation)        (причина)
жив/готов ли инстанс?   -> liveness / readiness пробы      (состояние)
```

## Ловушки

- ⚠️ Значения вклеены в `msg` (`"user alice failed"`) → записи не группируются и не агрегируются.
- ⚠️ `user_id`, `request_id`, полный URL в метках метрик → взрыв кардинальности, падение Prometheus.
- ⚠️ Задержка по среднему → хвост (p99) не виден; берите histogram и перцентили.
- ⚠️ Summary вместо histogram, когда нужно агрегировать по инстансам — клиентские квантили не складываются.
- ⚠️ Liveness, зависящий от БД → каскадные рестарты всего флота при недоступности БД.
- ⚠️ ERROR для того, что не проблема → алерты по ERROR превращаются в шум.
- ⚠️ Алерты на каждую причинную метрику → alert fatigue, пропуск настоящей аварии.
- ⚠️ Head-based сэмплирование 1% → редкие ошибочные трейсы теряются (нужен tail-based).
- ⚠️ Секреты и PII в логах.
