# Упражнения: архитектура сервисов, сеть и API в Go

Каждая задача — это `main.go` с функцией/методом-заготовкой (`TODO`) и
встроенной самопроверкой, печатающей `PASS` или `FAIL`. Заготовки компилируются
сразу (в стартовом состоянии тесты печатают `FAIL`) — ваша цель довести их до
`PASS`.

Запуск шаблона:

```bash
go run ./03_exercises/01_implement_repository/main.go
```

Запуск эталонного решения:

```bash
go run ./04_exercises_answers/01_implement_repository_answers/main.go
```

## Список задач

1. `01_implement_repository` — реализовать in-memory репозиторий, чтобы
   сервисный слой работал через интерфейс `UserRepository`.
2. `02_constructor_injection` — внедрить зависимость `PaymentGateway` в
   `OrderService` через конструктор `NewOrderService`.
3. `03_fix_dependency_direction` — развернуть зависимость (DIP): вынести узкий
   интерфейс на сторону потребителя.
4. `04_swap_adapter` — реализовать второй адаптер (`MemorySender`) для порта
   `Notifier` в гексагональной архитектуре.
5. `05_status_category` — классифицировать HTTP-код ответа по категориям
   (`1xx`–`5xx`).
6. `06_parse_url` — разобрать URL и извлечь схему, хост, порт по умолчанию и
   путь.
7. `07_tcp_line_protocol` — реализовать обработчик строкового протокола
   `UPPER <text>\n` поверх `net.Conn`.
8. `08_http_handler` — написать `http.Handler`, проверяющий HTTP-метод и
   query-параметры.
9. `09_udp_sum_server` — реализовать обработчик UDP-датаграмм, возвращающий
   сумму переданных чисел.
10. `10_method_semantics` — классифицировать HTTP-методы по безопасности
    (`Safe`) и идемпотентности (`Idempotent`).
11. `11_paginate` — реализовать безопасный срез страницы по `offset` и `limit`
    без выхода за границы слайса.
12. `12_rest_status` — выбрать корректный HTTP-статус по методу и доменной
    ошибке.
13. `13_parse_filter` — разобрать и провалидировать параметры фильтрации
    списка (`status`, `limit`).
