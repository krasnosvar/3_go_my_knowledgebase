## Оценки на салфетке

Подробно: [02_estimations.md](./01_theory/02_estimations.md).

| Степень 2 | ≈ | Байты |
| :--- | :--- | :--- |
| 2^10 | тысяча (K) | 1 KB |
| 2^20 | миллион (M) | 1 MB |
| 2^30 | миллиард (G) | 1 GB |
| 2^40 | триллион (T) | 1 TB |
| 2^50 | квадриллион (P) | 1 PB |

| Интервал | Секунд |
| :--- | :--- |
| сутки | 86 400 ≈ **10^5** |
| месяц | ~2.6 × 10^6 |
| год | ~3.15 × 10^7 |

| Что считаем | Формула |
| :--- | :--- |
| Запросов в сутки | `DAU × действий_на_пользователя` |
| Средний QPS | `запросов_в_сутки / 10^5` |
| Пиковый QPS | `средний × 2..3` |
| Хранилище | `размер_записи × записей_в_сутки × дней_хранения` |
| Bandwidth | `QPS × размер_ответа`; `1 Gbps ≈ 125 MB/s`, `1 байт = 8 бит` |
| Кэш (80/20) | `0.2 × уникальных_объектов × размер_записи` |

| Пример | Результат |
| :--- | :--- |
| DAU 10 млн × 20 запросов | 2 × 10^8 / 10^5 = 2000 QPS, пик ~4000 |
| 10^8 ссылок/сутки × 500 байт, 5 лет | 50 GB/сутки, ≈ 91 TB |
| 5000 QPS × 1 KB | 5 MB/s — легко; × 2 MB = 10 GB/s — работа для CDN |
| 0.2 × 2 × 10^7 × 200 байт | ≈ 0.8 GB — один узел Redis/Valkey |

| Операция (порядок) | Задержка |
| :--- | :--- |
| L1 cache | ~1 нс |
| Mutex lock/unlock | ~17 нс |
| RAM reference | ~100 нс |
| Send 1 KB по 1 Gbps | ~10 мкс |
| Read 1 MB из RAM | ~100 мкс |
| Round trip в дата-центре | ~500 мкс |
| Read 1 MB с SSD | ~1 мс |
| Disk seek (HDD) | ~10 мс |
| Round trip CA ↔ Netherlands | ~150 мс |

## Строительные блоки

Подробно: [03_building_blocks.md](./01_theory/03_building_blocks.md).

| Блок | Сигнал «пора добавить» | Что обсудить | Раздел |
| :--- | :--- | :--- | :--- |
| Load Balancer | > 1 инстанса | L4/L7, round-robin / least-conn / consistent hashing | [08](../08_reliability_scalability/CHEATSHEET.md) |
| Stateless app-серверы | масштабировать API | состояние — в Redis/БД | [06](../06_architecture/CHEATSHEET.md) |
| Кэш (Redis/Valkey) | read-heavy, повторные чтения | cache-aside, LRU, TTL, инвалидация, stampede | [03_caching](../03_caching/) |
| Read replicas | read ≫ write | репликационный лаг, read-after-write | [04_data_scaling](../04_data_scaling/) |
| Шардинг | объём/запись не влезают в ноду | ключ без hotspot, consistent hashing, кросс-шардовые запросы | [04_data_scaling](../04_data_scaling/) |
| Очередь | async-работа, пики, доставка событий | at-least-once vs exactly-once, идемпотентность, порядок, backpressure | [05_messaging](../05_messaging/) |
| CDN | медиа/статика, глобальная аудитория | GB/s на медиа — не для origin | [01_networking](../01_networking/) |

Порядок: минимум (LB → app → БД) → read-heavy: кэш, затем реплики → объём/запись: шардинг → async/пики: очередь → медиа: blob + CDN.

## URL shortener

Подробно: [04_example_url_shortener.md](./01_theory/04_example_url_shortener.md).

| Решение | Выбор и почему |
| :--- | :--- |
| Нагрузка | write ~1000 QPS, read ~100 000 QPS (100:1), ~91 TB за 5 лет, ~1.8 × 10^11 ключей |
| Длина кода | base62: 62^6 ≈ 5.7 × 10^10 (мало), 62^7 ≈ 3.5 × 10^12 → **7 символов** |
| Генерация | инкрементный ID → base62 (биекция, без коллизий); хэш URL — коллизии и повторы |
| Счётчик как SPOF | диапазоны ID на app-сервер или Snowflake-подобный 64-битный ID |
| Редирект | `302` (каждый клик через сервис → аналитика); `301` кэшируется браузером |
| Хранение | key-value по `short_code`, шардирование по нему, read replicas |
| Чтение | cache-aside: hit → `302 Location`, miss → реплика → кэш с TTL |
| Stampede на горячей ссылке | request coalescing, TTL с jitter |
| Лаг реплики после создания | читать создателя с мастера или сразу писать в кэш |
| base62 vs base64 | в base64 есть `+` и `/` — нужно URL-кодирование |

```go
package main

import "fmt"

const alphabet = "0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ"

func encode(id uint64) string {
	if id == 0 {
		return "0"
	}
	var b []byte
	for ; id > 0; id /= 62 {
		b = append([]byte{alphabet[id%62]}, b...)
	}
	return string(b)
}

func main() {
	fmt.Println(encode(61), encode(62), encode(12345), encode(3_521_614_606_207)) // Z 10 3d7 ZZZZZZZ
}
```

## News feed

Подробно: [05_example_news_feed.md](./01_theory/05_example_news_feed.md).

| Подход | Чтение | Запись | Когда |
| :--- | :--- | :--- | :--- |
| Fanout on write (push) | быстро: лента готова в `feed_cache` | дорого: 1 пост → N вставок | обычные авторы |
| Fanout on read (pull) | дорого: сбор и merge при запросе | дёшево | звёзды (> ~100 тыс подписчиков), неактивные пользователи |
| Гибрид | push-часть + pull звёзд, merge и сортировка | — | ответ на интервью |

| Деталь | Решение |
| :--- | :--- |
| Пагинация | курсорная (keyset), не offset |
| `feed_cache` | списки `post_id` в Redis/Valkey, первые 500–800, старое — из БД |
| Posts DB | шард по `author_id`, read replicas |
| Fanout | очередь + воркеры, eventual consistency |
| Медиа | blob storage + CDN, в `posts` — `media_ids` |

## Другие задачи: центральное решение

Подробно: [06_more_problems.md](./01_theory/06_more_problems.md).

| Задача | Центральное решение | Ещё обсудить |
| :--- | :--- | :--- |
| Сокращатель ссылок | base62 от уникального ID | 302 vs 301, кэш, шардинг |
| Лента новостей | гибридный fanout | celebrity problem, курсоры |
| Чат | WebSocket + реестр `user_id → connection` (Redis) | офлайн-инбокс, at-least-once + дедуп по message_id, шард по `chat_id` |
| Rate limiter | алгоритм + распределённые счётчики в Redis | `429` + `Retry-After`, fail-open vs fail-closed |
| Платежи | `Idempotency-Key` + ACID / saga | double-entry, outbox, reconciliation, деньги в минорных единицах |
| Файловое хранилище | метаданные в БД, байты в S3 + chunking (~4 MB) | дедуп по хэшу блока, дельта-синхронизация, конфликты версий |

## Ловушки

- ⚠️ Рисовать до уточнения требований — проектируете несуществующую задачу.
- ⚠️ Молчать: интервью — диалог, проговаривайте ход мысли.
- ⚠️ Kafka/Kubernetes/микросервисы там, где хватит монолита и одной БД.
- ⚠️ Компоненты без прикидки нагрузки — выбор ничем не обоснован; кэш «на всякий случай».
- ⚠️ Шардинг «на всякий случай» до вертикального масштабирования и реплик.
- ⚠️ Не проговорить компромиссы: у любого решения есть цена.
- ⚠️ Путать биты и байты: сеть в Gbps, данные в байтах.
- ⚠️ Последовательные ID предсказуемы — перемешивать перед кодированием, если важно.
- ⚠️ Деньги во `float`.
