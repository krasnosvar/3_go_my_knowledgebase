# Гарантии доставки

Гарантия доставки описывает, сколько раз сообщение может быть **доставлено и обработано** при сбоях (падение консьюмера, потеря сети, таймаут ack). Есть три уровня.

## At-most-once (не более одного раза)

Сообщение доставляется 0 или 1 раз. Потери допустимы, дублей нет.

- Обычно: консьюмер **сначала подтверждает** (ack / коммитит оффсет), **потом обрабатывает**. Упал после ack, но до обработки → сообщение потеряно.
- Быстро, просто, без дедупликации.
- **Когда:** метрики, телеметрия, логи, живые дашборды — потерять один сэмпл не страшно.

```
получил -> ack/commit -> обработал
                      ^ упал здесь = сообщение потеряно (но не задублировано)
```

## At-least-once (не менее одного раза)

Сообщение доставляется 1 или более раз. Потерь нет, но **возможны дубли**.

- Обычно: консьюмер **сначала обрабатывает**, **потом** подтверждает (ack). Упал после обработки, но до ack → брокер не увидел подтверждения и **пришлёт сообщение снова**.
- Самый распространённый режим в реальных системах (Kafka, RabbitMQ, SQS, NATS JetStream).
- **Требует идемпотентности** на стороне консьюмера, иначе повтор = двойной эффект (например, списали деньги дважды).

```
получил -> обработал -> ack
                     ^ упал здесь = ack не отправлен -> брокер пришлёт повтор (дубль)
```

## Exactly-once (ровно один раз)

Каждое сообщение обрабатывается **ровно один раз** — ни потерь, ни дублей.

- В распределённой системе в чистом виде **недостижимо на уровне сети** (нельзя одновременно гарантировать «не потерять» и «не задублировать» при произвольных сбоях — следствие проблемы двух генералов).
- На практике достигается как **at-least-once + идемпотентность/дедупликация**, то есть «effectively-once»: сообщение может прийти дважды, но **эффект применяется один раз**.
- Kafka предлагает «exactly-once semantics» для потоковой обработки Kafka→Kafka через идемпотентного продюсера + транзакции, но это работает внутри Kafka, а не «до внешней БД или API».

```
at-least-once  +  дедуп по message-id  =  effectively-once
(сеть может дублировать)   (эффект применяется однократно)
```

## ack / nack и повторы

- **ack (acknowledge)** — «обработал успешно, можно удалять / двигать оффсет».
- **nack (negative ack) / reject** — «не смог обработать»; сообщение возвращается в очередь (requeue) или уходит в **dead-letter queue (DLQ)** после N попыток.
- **visibility timeout / ack deadline** — если консьюмер не ack за отведённое время, брокер считает его упавшим и передаёт сообщение другому → отсюда и берутся дубли.
- **retry с backoff** — при ошибке повторяем с нарастающей паузой; DLQ спасает от «ядовитых» (poison) сообщений, зацикливающих обработку.

## Дедупликация

Раз at-least-once даёт дубли, консьюмер должен их отсеивать:

- **По message-id / ключу идемпотентности.** Каждое сообщение несёт уникальный id; консьюмер хранит множество/таблицу `seen` уже обработанных id и пропускает повторы.
- **Окно дедупликации.** Хранить все id вечно дорого → держат id за окно времени (TTL) или полагаются на естественную идемпотентность операции.
- **Идемпотентная операция.** Лучше, когда сама операция идемпотентна: `SET balance=100` вместо `balance += 10`; `INSERT ... ON CONFLICT DO NOTHING` по натуральному ключу.

Подробнее про транзакционную дедупликацию — в [05_outbox_inbox.md](./05_outbox_inbox.md).

## Сравнение

| Гарантия | Потери | Дубли | Порядок ack/обработки | Требует дедупа |
|---|---|---|---|---|
| at-most-once | возможны | нет | ack → обработка | нет |
| at-least-once | нет | возможны | обработка → ack | да |
| exactly-once (эффект) | нет | нет (эффект) | at-least-once + дедуп | да (сама суть) |

> ⚠️ Частый вопрос на собеседовании: возможна ли настоящая exactly-once доставка? Строго на уровне сети — нет. На практике её эмулируют как at-least-once + идемпотентность/дедупликация: сообщение может прийти повторно, но эффект применяется один раз («effectively-once»).

> ⚠️ Частый вопрос на собеседовании: откуда берутся дубли в at-least-once? Консьюмер обработал сообщение, но упал/затормозил до отправки ack. Брокер по истечении ack-таймаута считает его недоставленным и присылает повторно.
