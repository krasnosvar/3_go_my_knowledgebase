## Очередь vs лог

Подробно: [01_queues_brokers.md](./01_theory/01_queues_brokers.md).

| | Очередь (queue) | Журнал (log) |
| :--- | :--- | :--- |
| Сообщение — это | задача | событие |
| После чтения + ack | удаляется | остаётся до retention |
| Позицию хранит | брокер | консьюмер (оффсет) |
| Перечитать историю | нельзя | сдвинуть оффсет |
| Несколько независимых читателей | нужен fan-out/копия | естественно |
| Примеры | RabbitMQ, SQS, ActiveMQ | Kafka, NATS JetStream, Redpanda, Pulsar |

| Термин (лог) | Суть |
| :--- | :--- |
| Topic | именованный поток (`orders`) |
| Partition | отдельный упорядоченный лог; единица параллелизма |
| Offset | номер сообщения внутри партиции |
| Key | `partition = hash(key) % N` → порядок в пределах ключа; без ключа — round-robin |

| Брокер нужен | Брокер не нужен |
| :--- | :--- |
| ответ не нужен сразу; неравномерная нагрузка; fan-out; получатель может лежать; развязка деплоя | нужен синхронный ответ → HTTP/gRPC |

## Kafka vs RabbitMQ vs NATS

Подробно: [02_kafka_rabbit_nats.md](./01_theory/02_kafka_rabbit_nats.md).

| Свойство | Kafka | RabbitMQ | NATS core / JetStream |
| :--- | :--- | :--- | :--- |
| Модель | лог | очередь + маршрутизация (AMQP) | pub/sub / стрим |
| Персистентность | да (retention) | да (до ack) | нет / да |
| Реплей | да | нет | нет / да |
| Маршрутизация | ключ → партиция | exchange + binding | subject-иерархия |
| Порядок | в партиции | в очереди | в стриме (JetStream) |
| Throughput | очень высокий | средний–высокий | очень высокий |
| Задержка | средняя | средняя | очень низкая |
| Эксплуатация | сложная | средняя | низкая–средняя |

| Задача | Брать |
| :--- | :--- |
| Event streaming, event sourcing, аудит, ETL, реплей | Kafka |
| Очереди задач, RPC-over-MQ, приоритеты, сложная маршрутизация, DLQ | RabbitMQ |
| Быстрый внутренний обмен, request-reply, IoT | NATS (+ JetStream для гарантий) |
| Облако без своей инфры | SQS / Pub/Sub |

| RabbitMQ exchange | Маршрут |
| :--- | :--- |
| `direct` | точный routing key |
| `topic` | шаблон `logs.*.error` |
| `fanout` | во все привязанные очереди |
| `headers` | по заголовкам |

## Гарантии доставки

Подробно: [03_delivery_guarantees.md](./01_theory/03_delivery_guarantees.md).

| Гарантия | Порядок | Потери | Дубли | Когда |
| :--- | :--- | :--- | :--- | :--- |
| At-most-once | ack/commit → обработка | возможны | нет | метрики, логи, дашборды |
| At-least-once | обработка → ack/commit | нет | возможны → идемпотентность | по умолчанию в проде |
| Exactly-once (эффект) | at-least-once + дедуп | нет | эффект однократен | «effectively-once» |

| Механизм | Суть |
| :--- | :--- |
| ack | обработал → удалить / двигать оффсет |
| nack / reject | requeue или DLQ после N попыток |
| visibility timeout / ack deadline | нет ack вовремя → сообщение другому → дубль |
| retry с backoff + DLQ | защита от poison-сообщений |
| Дедуп | `seen` по message-id в окне TTL |
| Идемпотентная операция | `SET balance=100` вместо `balance += 10`; `INSERT ... ON CONFLICT DO NOTHING` |
| Kafka EOS | идемпотентный продюсер + транзакции; только Kafka→Kafka |

## Consumer groups

Подробно: [04_consumer_groups.md](./01_theory/04_consumer_groups.md).

| Правило | Следствие |
| :--- | :--- |
| Партицию в группе читает ровно один консьюмер | консьюмеров > партиций → лишние простаивают |
| Число партиций | потолок параллелизма группы |
| Разные группы независимы | fan-out: группа на сервис |
| Партиции можно только добавить | `hash % N` меняет раскладку → ломается порядок по ключу; планировать заранее |
| Коммит до / после обработки | at-most-once / at-least-once |
| После ребаланса | чтение с последнего закоммиченного оффсета → дубли |

| Триггер ребаланса | Смягчение |
| :--- | :--- |
| консьюмер пришёл/ушёл/упал (heartbeat, session timeout) | static membership |
| добавили партиции | — |
| долгая обработка батча (`max.poll.interval`) | укоротить батч, достаточный таймаут |
| stop-the-world пауза всей группы | cooperative / incremental rebalancing |

## Outbox и inbox

Подробно: [05_outbox_inbox.md](./01_theory/05_outbox_inbox.md).

| Порядок dual write | Сбой между шагами |
| :--- | :--- |
| БД → брокер | данные есть, события нет |
| брокер → БД | фантомное событие |
| 2PC БД + брокер | дорого, хрупко, часто недоступно |

| Паттерн | Где | Как | Решает |
| :--- | :--- | :--- | :--- |
| Transactional outbox | продюсер | `INSERT outbox` в той же tx; relay (polling или CDC/Debezium) публикует, ставит `published=true` | атомарность «БД + событие»; publish at-least-once |
| Inbox | консьюмер | `INSERT inbox(message_id)` с UNIQUE в той же tx, что эффект; дубль → откат | дубли at-least-once |
| Идемпотентная операция | консьюмер | `SET status='paid'`, upsert по натуральному ключу | повторы без хранения состояния |

Цепочка: outbox → брокер (at-least-once) → inbox/дедуп → effectively-once.

```go
package main

import "fmt"

type Msg struct {
	ID     string // ключ идемпотентности
	Amount int
}

func main() {
	ch := make(chan Msg, 2) // буфер 2: продюсер обгонит максимум на 2 → backpressure

	go func() {
		defer close(ch)
		// at-least-once: брокер повторил m1
		for _, m := range []Msg{{"m1", 10}, {"m2", 5}, {"m1", 10}} {
			ch <- m // блокируется, если буфер полон
		}
	}()

	seen := map[string]bool{} // в проде — таблица inbox с UNIQUE(message_id)
	balance := 0
	for m := range ch {
		if seen[m.ID] {
			continue // дубль: эффект не применяем
		}
		seen[m.ID] = true
		balance += m.Amount
	}
	fmt.Println(balance) // 15, а не 25
}
```

## Backpressure

Подробно: [06_backpressure.md](./01_theory/06_backpressure.md).

| Реакция на «продюсер быстрее» | Когда |
| :--- | :--- |
| Ограниченный буфер + блокировка продюсера | по умолчанию, безопасно |
| Drop / load shedding | только неважные данные (метрики) |
| Буфер на диск (Kafka) | сдвигает проблему, retention конечен |

| Где | Механизм |
| :--- | :--- |
| Go | `make(chan T)` — шаг в шаг; `make(chan T, N)` — обгон максимум на N |
| Go | фиксированный пул воркеров читает из канала |
| Kafka | pull через `poll()`; следить за consumer lag |
| RabbitMQ | prefetch (QoS) — лимит неподтверждённых на консьюмера |
| TCP | receive window |

| | Push | Pull |
| :--- | :--- | :--- |
| Задержка | ниже | чуть выше |
| Backpressure | нужен явно (prefetch, credits) | встроен |

## Паттерны и диагностика

Подробно: [07_use_cases.md](./01_theory/07_use_cases.md).

| Паттерн | Суть |
| :--- | :--- |
| Work queue | competing consumers; в Kafka ≤ числа партиций |
| Pub/Sub | одно событие → многим; в Kafka — разные группы |
| Event sourcing | состояние = поток событий |
| Saga | цепочка событий + компенсации вместо 2PC |
| CQRS | запись командами, чтение из проекции |
| DLQ | poison-сообщения после N ретраев |

| Симптом | Причина / действие |
| :--- | :--- |
| Растёт lag / глубина очереди | добавить консьюмеров (≤ партиций), ускорить, проверить ребалансы |
| Дубли эффектов | сломан дедуп; когда коммитится оффсет/ack |
| Потеря сообщений | ack до обработки; dual write без outbox |
| Поток встал на одном сообщении | poison message → DLQ, лимит ретраев |

## Ловушки

- ⚠️ Kafka — не очередь: сообщения не удаляются при чтении.
- ⚠️ Глобального порядка в топике нет — только в партиции; события сущности — с одним ключом.
- ⚠️ Core NATS без подписчика теряет сообщение (at-most-once).
- ⚠️ At-least-once без идемпотентности → двойное списание.
- ⚠️ «Сначала БД, потом publish» — потеря событий; нужен outbox.
- ⚠️ Outbox — at-least-once, не exactly-once.
- ⚠️ Безграничный буфер в памяти → OOM.
- ⚠️ Консьюмеров больше, чем партиций, — лишние простаивают.
