# DRY / KISS / YAGNI

Три коротких принципа, направленных против главного врага кода — ненужной сложности. Все три — про баланс: их легко довести до абсурда.

## DRY — Don't Repeat Yourself

Каждый кусок **знания** должен иметь единственное представление в системе. Дублируется не текст, а *решение*: если одно бизнес-правило продублировано в трёх местах, при изменении легко забыть одно из них.

```go
// Плохо: правило «скидка 10% при сумме > 1000» размазано по коду.
// Хорошо: одно место истины.
func DiscountRate(total float64) float64 {
	if total > 1000 {
		return 0.10
	}
	return 0
}
```

**Осторожно с ложным DRY.** Две случайно похожие строки кода — не дублирование знания. Преждевременное «обобщение» ради устранения совпадения часто создаёт неправильную абстракцию. В Go-сообществе это формулируют так: *«a little copying is better than a little dependency»* — иногда скопировать 5 строк лучше, чем тянуть лишнюю зависимость или абстракцию.

## KISS — Keep It Simple, Stupid

Предпочитай простое решение сложному. Простой код читается, отлаживается и меняется дешевле. В Go это часть культуры языка: явное лучше неявного, мало ключевых слов, простые управляющие конструкции.

```go
// Излишне «умно»: рефлексия и обобщения там, где не нужно.
// Просто и ясно:
func Max(a, b int) int {
	if a > b {
		return a
	}
	return b
}
```

Признаки нарушения KISS: слои абстракции «на будущее», хитрая рефлексия/кодогенерация ради экономии пары строк, «универсальные» функции с десятком флагов.

## YAGNI — You Aren't Gonna Need It

Не реализуй функциональность, пока она реально не понадобилась. Код «про запас» — это стоимость (поддержка, тесты, баги) без выгоды, а предсказание будущих требований почти всегда ошибочно.

```go
// YAGNI-нарушение: конфиг под 5 «будущих» БД, а используется одна.
// Правильно: сделать под текущую задачу, расширить, когда потребуется.
type Config struct {
	DatabaseURL string
}
```

## Как они соотносятся

- **KISS** — про то, *как* писать: проще.
- **YAGNI** — про то, *что* писать: только нужное сейчас.
- **DRY** — про то, чтобы знание не дублировалось (но не любой ценой).

Иногда они конфликтуют: устранение дублирования (DRY) может усложнить код (против KISS). Разрешение — здравый смысл: убирать дублирование *знания*, а не гнаться за нулём повторов.

> ⚠️ Частый вопрос на собеседовании: DRY против «немного дублирования лучше немного зависимости» — противоречие? Нет. DRY запрещает дублировать *знание/решение*, а не любые похожие символы. Если два фрагмента совпали случайно и меняются по разным причинам — насильно объединять их вредно (создаётся неправильная связанность).

> ⚠️ Частый вопрос на собеседовании: приведите пример нарушения YAGNI. Плагинная архитектура, фабрики и интерфейсы «на вырост» под гипотетические требования, которых нет в бэклоге. Это увеличивает сложность и стоимость без текущей пользы.
