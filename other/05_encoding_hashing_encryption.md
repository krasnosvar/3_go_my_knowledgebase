# Encoding vs Hashing vs Encryption

Три слова, которые постоянно путают на собеседованиях: «закодировать», «захешировать», «зашифровать». Звучат похоже, но решают **разные задачи**. Разберёмся раз и навсегда.

Быстрая шпаргалка:

| Операция    | Обратимо?              | Нужен секрет/ключ? | Зачем нужно                         |
|-------------|------------------------|--------------------|-------------------------------------|
| Encoding    | Да (тривиально)        | Нет                | Совместимость, транспорт данных     |
| Hashing     | Нет (односторонне)     | Нет (соль ≠ ключ)  | Целостность, индексы, пароли        |
| Encryption  | Да, но только с ключом | Да                 | Конфиденциальность (тайна данных)   |

Главное правило: **если что-то легко раскодировать без секрета — это НЕ защита.**

---

## 1. Кодирование (Encoding)

Кодирование — это обратимое преобразование **представления** данных из одной формы в другую. Секрета здесь нет: любой, кто знает алгоритм, может раскодировать обратно.

Цель — не спрятать, а сделать данные **совместимыми** с каналом передачи или форматом хранения. Например, передать бинарные данные (картинку) там, где разрешён только текст (email, JSON, URL).

Примеры:
- **base64** — бинарные данные в набор из 64 печатных ASCII-символов.
- **hex** (шестнадцатеричное) — каждый байт как две цифры `00`–`ff`.
- **URL-encoding / percent-encoding** — спецсимволы в `%XX` (пробел → `%20`).

Важно про base64: он **увеличивает** размер примерно на треть (~33%), потому что кодирует 3 байта в 4 символа. Это **не сжатие и не шифрование** — данные читаются любым, кто их получит.

```go
import (
    "encoding/base64"
    "encoding/hex"
    "fmt"
)

data := []byte("Привет")

// base64: обратимо, без ключа
s := base64.StdEncoding.EncodeToString(data)
fmt.Println(s) // 0J/RgNC40LLQtdGC
back, _ := base64.StdEncoding.DecodeString(s)
fmt.Println(string(back)) // Привет

// hex: тоже просто представление
fmt.Println(hex.EncodeToString(data)) // d09fd180d0b8d0b2d0b5d182
```

Типичная ошибка: «я передаю пароль в base64, значит он защищён». Нет — это то же самое, что написать его открытым текстом.

## 2. Хеширование (Hashing)

Хеш-функция берёт вход **любой длины** и выдаёт результат **фиксированной длины** (дайджест). Операция **односторонняя**: по хешу нельзя восстановить исходные данные.

Ключевые свойства:
- **Детерминированность** — один и тот же вход всегда даёт один и тот же хеш.
- **Лавинный эффект** — изменение одного бита входа меняет ~половину битов выхода.
- **Коллизии** — теоретически два разных входа могут дать один хеш (выходов конечное число, входов бесконечно). У хороших крипто-функций найти коллизию практически невозможно.

Зачем нужно:
- **Контроль целостности** — сравнить хеш файла до и после передачи (совпал → не повреждён/не подменён).
- **Индексы / hash-таблицы** — быстрый доступ по ключу (`map` в Go внутри использует хеширование).
- **Хранение паролей** — хранить не пароль, а его хеш.

### Криптографические vs некриптографические

| Тип                    | Примеры          | Для чего                          |
|------------------------|------------------|-----------------------------------|
| Криптографические      | SHA-256, SHA-3   | Целостность, подписи, безопасность |
| Некриптографические    | FNV, xxHash, CRC | Hash-таблицы, чек-суммы (быстро)  |

Некриптографические — быстрые, но их легко «сломать» (подобрать коллизию). В hash-таблицах это ок, в безопасности — нет.

### Пароли: не «голый» SHA

Хранить пароль как `sha256(password)` — плохо: SHA очень быстрый, а значит перебор миллиардов вариантов в секунду реален (плюс rainbow-таблицы). Правильно — специальные **медленные** функции с солью:

- **bcrypt**, **scrypt**, **argon2** — намеренно медленные и настраиваемые по «стоимости».
- **Соль (salt)** — случайные данные, добавляемые к паролю перед хешированием. Делает одинаковые пароли разными в хранилище и убивает rainbow-таблицы. Соль — **не секрет и не ключ**, её хранят рядом с хешем.

```go
import "golang.org/x/crypto/bcrypt"

hash, _ := bcrypt.GenerateFromPassword([]byte("qwerty"), bcrypt.DefaultCost)
// hash содержит соль и cost внутри себя
err := bcrypt.CompareHashAndPassword(hash, []byte("qwerty")) // err == nil → пароль верный
```

## 3. Шифрование (Encryption)

Шифрование — **обратимое** преобразование, но раскодировать (расшифровать) можно **только зная ключ**. Цель — конфиденциальность: данные видны, но нечитаемы без ключа.

### Симметричное шифрование

Один и тот же ключ и шифрует, и расшифровывает.

- Пример: **AES**.
- Плюс: быстро, подходит для больших объёмов.
- Минус: обе стороны должны как-то безопасно обменяться одним секретным ключом.

```
данные + ключ K ──[AES]──► шифртекст
шифртекст + ключ K ──[AES]──► данные
```

### Асимметричное шифрование

Пара ключей: **публичный** (можно раздавать всем) и **приватный** (держится в секрете). Что зашифровано публичным — расшифровывается только приватным (и наоборот — основа цифровых подписей).

- Пример: **RSA**, а также схемы на эллиптических кривых (ECC).
- Плюс: не нужно заранее обмениваться общим секретом.
- Минус: медленнее симметричного.

```
данные + публичный ключ ──[RSA]──► шифртекст
шифртекст + приватный ключ ──[RSA]──► данные
```

На практике их **комбинируют**: асимметрией безопасно передают одноразовый симметричный ключ, а сам трафик шифруют быстрым AES. Так, например, устроен TLS (HTTPS).

## Как не перепутать

Спросите себя:

1. **Могу ли я вернуть исходные данные без всякого секрета?** → да → это **encoding**.
2. **Данные нельзя вернуть вообще?** → это **hashing**.
3. **Данные можно вернуть, но только с ключом?** → это **encryption**.

Классический разбор путаницы:
- base64 «шифрует» пароль → **нет**, это encoding, защиты ноль.
- SHA-256 «шифрует» пароль → **нет**, это hashing, и в чистом виде для паролей плохо (нужен bcrypt/argon2 + соль).
- AES «хеширует» файл → **нет**, это encryption (обратимо с ключом).
