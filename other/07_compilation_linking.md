# Компиляция и линковка

## Компиляция vs интерпретация vs JIT

Программа написана на языке, понятном человеку, а процессор исполняет только машинный код. Способы преодолеть эту пропасть:

- **Компилятор** — переводит исходник в машинный код **заранее** (ahead-of-time), один раз. Итог — готовый исполняемый файл. Примеры: Go, C, C++, Rust.
- **Интерпретатор** — читает и выполняет программу **построчно** во время запуска, без отдельного бинарника. Примеры: Python, Ruby, «классический» JS.
- **JIT** (Just-In-Time) — **гибрид**: сначала работает как интерпретатор/байткод, но «горячие» участки на лету компилирует в машинный код. Примеры: JVM (Java), V8 (JavaScript).

| Подход        | Когда переводится в машкод | Скорость запуска | Скорость работы | Портируемость артефакта |
|---------------|----------------------------|------------------|-----------------|--------------------------|
| Компиляция    | Заранее                    | Быстрый          | Высокая         | Под конкретную платформу |
| Интерпретация | Во время выполнения        | Мгновенный старт | Ниже            | Нужен интерпретатор      |
| JIT           | На лету, по мере работы     | Медленный прогрев| Высокая после прогрева | Нужна виртуальная машина |

## Этапы компиляции

Для компилируемого языка путь от исходника к бинарнику обычно такой:

```
исходный код
    │
    ▼
[ Лексер ]          → поток токенов (ключевые слова, идентификаторы, числа...)
    │
    ▼
[ Парсер ]          → AST (абстрактное синтаксическое дерево)
    │
    ▼
[ Семантический     → проверка типов, областей видимости, правил языка
  анализ ]
    │
    ▼
[ Генерация кода ]  → машинный код (объектные файлы .o)
    │
    ▼
[ Линковка ]        → единый исполняемый файл
```

- **Лексер (lexer / tokenizer)** — разбивает текст на токены.
- **Парсер (parser)** — строит из токенов дерево (AST), проверяя синтаксис.
- **Семантический анализ** — проверяет смысл: типы совпадают, переменные объявлены и т.п.
- **Генерация кода** — превращает дерево в машинные инструкции (часто с оптимизациями).

## Что делает линкер

Компилятор обрабатывает файлы по отдельности и выдаёт **объектные файлы** с «дырами» — ссылками на функции/переменные из других файлов и библиотек. **Линкер (linker)** сшивает всё вместе:

- разрешает символы (находит, где на самом деле лежит `printf`, ваша функция и т.д.);
- подставляет реальные адреса;
- собирает финальный исполняемый файл.

### Статическая vs динамическая линковка

| | Статическая | Динамическая |
|---|---|---|
| Библиотеки | Вшиваются **внутрь** бинарника | Подгружаются при запуске (`.so`/`.dll`) |
| Размер файла | Больше | Меньше |
| Зависимости на целевой машине | Не нужны | Нужны нужные версии библиотек |
| Обновление библиотеки | Пересобрать программу | Обновить общую библиотеку отдельно |
| Переносимость | Высокая | Ниже (риск «работает у меня») |

## Особенности Go

Go — компилируемый язык с несколькими приятными свойствами:

- **Один статический бинарник.** По умолчанию Go линкует всё статически и собирает **один исполняемый файл без внешних зависимостей**. Его удобно копировать на сервер или класть в минимальный (даже `scratch`) Docker-образ.
- **Быстрая компиляция.** Язык спроектирован так, чтобы сборка была быстрой (простая модель зависимостей пакетов, отсутствие тяжёлых заголовков-как-в-C).
- **Кросс-компиляция из коробки.** Через переменные окружения `GOOS` (ОС) и `GOARCH` (архитектура) можно собрать бинарник под другую платформу прямо со своей машины.

*(Нюанс: если используется cgo, появляется зависимость от C-библиотек и «чисто статический» бинарник уже не гарантирован — это выключают через `CGO_ENABLED=0`.)*

Команды:

```bash
# Обычная сборка под текущую платформу
go build -o app ./cmd/app

# Кросс-компиляция под Linux/amd64
GOOS=linux GOARCH=amd64 go build -o app-linux ./cmd/app

# Под Windows/arm64
GOOS=windows GOARCH=arm64 go build -o app.exe ./cmd/app

# Посмотреть список поддерживаемых пар GOOS/GOARCH
go tool dist list
```

Именно статический бинарник и кросс-компиляция делают Go таким удобным для контейнеров и CLI-утилит: собрал один файл — и он просто запускается где нужно.
