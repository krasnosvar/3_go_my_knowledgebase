# Порядок байтов (endianness)

Когда число не влезает в один байт (например, 32-битное `0x12345678`
занимает 4 байта), возникает вопрос: **в каком порядке разложить эти байты в
памяти** — от старшего к младшему или наоборот. Это и есть endianness.

## Big-endian vs little-endian

Возьмём число `0x12345678`. Оно состоит из байтов:

```
старший → 0x12  0x34  0x56  0x78 ← младший
```

**Big-endian** («тупоконечный») — старший байт по младшему адресу, «как читаем
слева направо»:

```
адрес:  +0    +1    +2    +3
байт:  0x12  0x34  0x56  0x78
```

**Little-endian** («остроконечный») — младший байт по младшему адресу,
задом наперёд:

```
адрес:  +0    +1    +2    +3
байт:  0x78  0x56  0x34  0x12
```

```
Число:        0x12345678

Big-endian:   [12][34][56][78]
Little-endian:[78][56][34][12]
```

Little-endian используют большинство современных CPU (x86, x86-64, а также
ARM в обычном режиме). Big-endian встречается в некоторых архитектурах и — что
важнее на практике — в сетевых протоколах.

## Где это важно

Внутри одной программы на одной машине endianness обычно не заметен — процессор
сам знает свой порядок. Он становится важен там, где байты **пересекают границу**
одной машины или формата:

- **сеть**: «сетевой порядок байтов» (network byte order) — это **big-endian**.
  Заголовки TCP/IP, номера портов и т. п. передаются в big-endian, и стороны
  договариваются об этом заранее;
- **бинарные форматы файлов**: многие форматы фиксируют порядок байтов в
  спецификации (некоторые — big, некоторые — little);
- **обмен данными между машинами** с разной архитектурой: если одна пишет числа
  в своём «родном» порядке, а другая читает в своём, получится мусор.

Поэтому при сериализации чисел в байты порядок задают **явно**.

## В Go: encoding/binary

Пакет `encoding/binary` предоставляет `binary.BigEndian` и
`binary.LittleEndian` — не нужно вручную сдвигать байты.

```go
import "encoding/binary"

buf := make([]byte, 4)

binary.BigEndian.PutUint32(buf, 0x12345678)
// buf = [0x12 0x34 0x56 0x78]

binary.LittleEndian.PutUint32(buf, 0x12345678)
// buf = [0x78 0x56 0x34 0x12]

// Чтение обратно тем же порядком:
x := binary.BigEndian.Uint32(buf)
```

Правило: сериализуя числа в байты (файл, сетевой протокол), всегда выбирайте
порядок явно и читайте тем же порядком, каким писали. Для сети по умолчанию —
big-endian.
