# Как компьютер хранит числа

Все числа в памяти — это фиксированное количество битов. От того, как эти биты
интерпретируются, зависит и диапазон значений, и поведение при переполнении.

## Целые без знака (unsigned)

Все биты используются для величины числа. Для `n` бит диапазон `0 … 2ⁿ−1`.

```
uint8:  8 бит  →  0 … 255
uint16: 16 бит →  0 … 65535
uint32: 32 бита → 0 … 4 294 967 295
```

Пример: `uint8` со значением `0000_0101` = 5.

## Целые со знаком (signed) и дополнительный код

Для знаковых чисел нужно хранить и знак. Почти все процессоры используют
**дополнительный код** (two's complement).

Идея: старший (левый) бит имеет **отрицательный** вес. Для 8 бит веса такие:

```
бит:    b7    b6   b5  b4  b3 b2 b1 b0
вес:  -128    64   32  16   8  4  2  1
```

Примеры для `int8`:

```
0000_0001 =  1
0111_1111 =  127          (максимум)
1111_1111 = -128+64+...+1 = -1
1000_0000 = -128          (минимум)
```

Диапазон `int8`: `−128 … 127`. В общем случае для `n` бит: `−2ⁿ⁻¹ … 2ⁿ⁻¹−1`.

### Почему именно дополнительный код

- **ноль единственный**: нет отдельных `+0` и `−0`;
- **сложение и вычитание работают одинаково** для знаковых и беззнаковых чисел —
  процессору не нужна отдельная логика для знака. Чтобы получить `−x`,
  инвертируют все биты и прибавляют 1:

```
 5 = 0000_0101
~5 = 1111_1010
+1 = 1111_1011 = -5
```

## Переполнение (overflow) и wraparound

Разрядность фиксирована, поэтому результат, не влезающий в биты, «заворачивается»
по модулю `2ⁿ`.

```
uint8:  255 + 1 = 0        (переполнение вверх)
uint8:    0 - 1 = 255      (переполнение вниз)
int8:   127 + 1 = -128     (знаковое переполнение)
```

В Go переполнение целых **не паникует** — значение молча заворачивается. Это
частый источник багов: например, счётчик или индекс может внезапно стать
отрицательным или огромным.

## Числа с плавающей точкой (IEEE 754)

Дробные числа хранятся в формате **IEEE 754**. Число раскладывается на три части
(как «двоичная научная запись» `± мантисса × 2^экспонента`):

```
знак | экспонента |        мантисса
-----+------------+-------------------------
float32:  1 бит |  8 бит   | 23 бита
float64:  1 бит | 11 бит   | 52 бита
```

- **знак** — плюс или минус;
- **экспонента** — порядок (степень двойки), задаёт масштаб;
- **мантисса** — значащие цифры числа.

Такой формат покрывает огромный диапазон, но с **ограниченной точностью**:
хранится лишь фиксированное число значащих двоичных цифр.

### Почему `0.1 + 0.2 != 0.3`

Дроби хранятся в **двоичной** системе. Число `0.1` в двоичной записи —
бесконечная периодическая дробь (как `1/3 = 0.333…` в десятичной). Его
приходится **округлять** до доступных бит. Складываются уже неточные
приближения, и результат чуть отличается от `0.3`:

```
0.1 + 0.2 = 0.30000000000000004   (float64)
```

Отсюда правило: **никогда не сравнивайте float на строгое равенство** (`==`).
Сравнивайте с допуском (epsilon):

```go
if math.Abs(a-b) < 1e-9 {
    // считаем равными
}
```

### Потеря точности

- очень большие и очень маленькие числа вместе теряют младшие разряды
  (`1e16 + 1 == 1e16` в float64);
- накопление ошибок при многих операциях подряд.

## Деньги — не во float

Из-за неточности float **деньги нельзя хранить в `float64`**. Варианты:

- хранить в **целых числах наименьшей единицы** — копейках/центах (`int64`),
  а делить на 100 только при выводе;
- использовать **decimal**-тип (например, библиотеку
  `github.com/shopspring/decimal`) с точной десятичной арифметикой.

```go
price := 1099   // int64, это 10.99 в валюте (центы)
```
