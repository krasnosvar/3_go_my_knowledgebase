# Время и часовые пояса

Работа со временем кажется простой, но полна ловушек: часовые пояса, переход на
летнее время, разные форматы записи. Разберём базовые понятия.

## UTC и местное время

- **UTC** (Coordinated Universal Time) — единое опорное время, не привязанное к
  какому-либо региону. Часовые пояса задаются как смещение от UTC.
- **Местное время** = UTC + смещение пояса.

```
UTC:              12:00
Москва (UTC+3):   15:00
Нью-Йорк (UTC-5): 07:00
```

Одному моменту времени соответствует одно значение UTC, но разные местные
времена в разных поясах.

## Unix timestamp

**Unix timestamp** — число секунд, прошедших с **1970-01-01 00:00:00 UTC**
(эпоха Unix). Это компактное и однозначное представление момента времени: одно
число, не зависящее от пояса.

```
1720000000 → 2024-07-03 09:46:40 UTC
```

Timestamp всегда считается в UTC — в этом его удобство: он не зависит от того,
где находится наблюдатель.

## Часовые пояса и DST

Смещение пояса — это не всегда постоянная величина. Во многих странах есть
**переход на летнее время** (DST, Daylight Saving Time): весной часы переводят
на час вперёд, осенью назад.

Последствия, о которых легко забыть:

- смещение пояса меняется в зависимости от даты (летом UTC+2, зимой UTC+1);
- некоторые местные времена **не существуют** (при переводе вперёд час
  «пропадает») или **существуют дважды** (при переводе назад);
- правила DST меняются политическими решениями, поэтому их хранят в базе
  часовых поясов (**tzdata**, она же IANA time zone database), а не вычисляют
  формулой.

## Почему хранить время в UTC

Общее правило: **храните и передавайте время в UTC**, а в местное переводите
только при отображении пользователю.

- UTC однозначен и не зависит от DST;
- разные части системы (сервер, БД, клиенты в разных странах) понимают одно и
  то же значение одинаково;
- избегаете багов на переходах DST и при смене правил поясов.

Пояс пользователя — это отдельная информация для отображения, а не то, как надо
хранить сам момент.

## Монотонные часы vs wall-clock

Есть два разных понятия «времени»:

- **Wall-clock** («настенные часы») — календарное время (дата, час, минуты). Его
  можно **перевести назад**: синхронизация по NTP, ручная правка, переход DST.
- **Монотонные часы** (monotonic clock) — счётчик, который только **растёт** и
  не прыгает назад. Он не привязан к календарю, но идеально подходит для
  **измерения длительности**.

Для измерения интервала («сколько заняла операция») берут **монотонное** время.
Если использовать wall-clock, интервал может получиться отрицательным или
скачком измениться, если в этот момент часы подкрутил NTP или сработал DST.

```
Длительность операции  → монотонные часы
"Который сейчас час?"   → wall-clock (обычно в UTC)
```

## Форматы записи: ISO 8601 / RFC 3339

Для текстовой записи времени есть стандарт **ISO 8601**; его строгое
подмножество, удобное для обмена данными, — **RFC 3339**:

```
2026-07-09T14:30:00Z          — UTC (суффикс Z = "Zulu" = +00:00)
2026-07-09T17:30:00+03:00     — то же время с явным смещением пояса
```

Такой формат: год-месяц-день, `T`, время, затем `Z` или смещение. Он однозначен
и хорошо сортируется как обычная строка.

## В Go: пакет time

`time.Time` в Go хранит **и календарное (wall-clock), и монотонную
составляющую** одновременно. Это сделано специально: сравнения и вычитание
(`time.Since`, `t2.Sub(t1)`) используют монотонную часть и потому корректно
измеряют длительность, а форматирование и календарные операции — wall-clock
часть. `t.UTC()`, `t.In(loc)`, `t.Local()` и `t.Round(0)` снимают монотонную
составляющую, поэтому длительность меряйте от исходного `time.Now()`.

```go
now := time.Now()          // содержит и wall, и monotonic
utc := now.UTC()           // то же время в UTC, но без монотонной части

start := time.Now()
// ... работа ...
elapsed := time.Since(start) // использует монотонные часы

// RFC 3339:
s := now.UTC().Format(time.RFC3339) // "2026-07-09T14:30:00Z"
t, _ := time.Parse(time.RFC3339, s)
```

Практические советы:

- в БД и API храните время в UTC (`t.UTC()`), в RFC 3339 или как Unix timestamp;
- для длительностей используйте `time.Since` / `Sub`, а не вычитание вручную;
- часовой пояс подключайте через `time.LoadLocation("Europe/Moscow")` и
  применяйте только при отображении.
