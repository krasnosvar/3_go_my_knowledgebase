# ТОП-20 вопросов по ClickHouse для Go-разработчика бэкенда

## Простые вопросы (Junior уровень)

### 1. Что такое ClickHouse и для каких задач он используется?
**Что ожидают услышать:**
- Колоночная СУБД для аналитики (OLAP)
- Высокая скорость обработки больших объемов данных
- Оптимизирована для аналитических запросов и агрегаций
- Примеры использования: логи, метрики, аналитика событий

### 2. В чем основное отличие колоночного хранения от строкового?
**Что ожидают услышать:**
- В колоночных БД данные одной колонки хранятся вместе
- Лучшее сжатие однотипных данных
- Быстрее читать несколько колонок из большой таблицы
- Медленнее вставлять отдельные строки

### 3. Какие основные движки таблиц (table engines) в ClickHouse вы знаете?
**Что ожидают услышать:**
- MergeTree (основной для аналитики)
- ReplicatedMergeTree (репликация)
- Distributed (распределенные запросы)
- Memory, Log, Buffer (вспомогательные)

### 4. Как подключиться к ClickHouse из Go приложения?
**Что ожидают услышать:**
- Использование официального драйвера `github.com/ClickHouse/clickhouse-go/v2`
- HTTP или Native протокол
- Пример кода подключения:
```go
conn, err := clickhouse.Open(&clickhouse.Options{
    Addr: []string{"127.0.0.1:9000"},
    Auth: clickhouse.Auth{
        Database: "default",
        Username: "default",
        Password: "",
    },
})
```

### 5. Что такое партиционирование (partitioning) в ClickHouse?
**Что ожидают услышать:**
- Разделение данных на части по определенному ключу
- Обычно по времени (день, месяц)
- Ускоряет удаление старых данных
- Помогает в оптимизации запросов

## Средние вопросы (Middle уровень)

### 6. Объясните концепцию PRIMARY KEY в ClickHouse. Чем он отличается от PRIMARY KEY в PostgreSQL?
**Что ожидают услышать:**
- PRIMARY KEY в ClickHouse не гарантирует уникальность
- Используется для индексирования и сортировки данных
- Создает разреженный индекс (sparse index)
- Влияет на производительность запросов с фильтрами

### 7. Как правильно вставлять данные в ClickHouse из Go приложения?
**Что ожидают услышать:**
- Батчевые вставки вместо одиночных
- Использование batch API:
```go
batch, err := conn.PrepareBatch(ctx, "INSERT INTO table")
for _, row := range rows {
    batch.Append(row.field1, row.field2)
}
batch.Send()
```
- Асинхронные вставки (async_insert)
- Использование Buffer таблиц для буферизации

### 8. Что такое materialized view в ClickHouse и зачем они нужны?
**Что ожидают услышать:**
- Автоматическое преобразование и агрегация данных при вставке
- Хранят результат SELECT запроса
- Используются для предвычисления агрегаций
- Пример: предвычисление метрик по часам из событий

### 9. Какие типы данных в ClickHouse вы используете для работы с датами и временем?
**Что ожидают услышать:**
- Date, Date32 (дни)
- DateTime, DateTime64 (секунды/подсекунды)
- Часовые пояса в DateTime('Europe/Moscow')
- Маппинг в Go: time.Time

### 10. Как организовать репликацию данных в ClickHouse?
**Что ожидают услышать:**
- Использование ReplicatedMergeTree движка
- Настройка ZooKeeper/ClickHouse Keeper
- Пример:
```sql
CREATE TABLE table_name (...)
ENGINE = ReplicatedMergeTree('/clickhouse/tables/{shard}/table_name', '{replica}')
```
- Автоматическая синхронизация между репликами

## Продвинутые вопросы (Senior уровень)

### 11. Объясните, как работает сжатие данных в ClickHouse и какие кодеки вы использовали?
**Что ожидают услышать:**
- LZ4 (по умолчанию, быстрое)
- ZSTD (лучшее сжатие)
- Delta, DoubleDelta (для временных рядов)
- Gorilla (для float значений)
- T64 (для целых чисел)
- Возможность указания на уровне колонки: `CODEC(Delta, ZSTD)`

### 12. Как оптимизировать запросы в ClickHouse? Какие метрики вы анализируете?
**Что ожидают услышать:**
- EXPLAIN запросы для анализа плана
- system.query_log для анализа производительности
- Метрики: read_rows, read_bytes, memory_usage, elapsed
- Оптимизация ORDER BY (должен совпадать с PRIMARY KEY)
- Использование PREWHERE вместо WHERE
- Правильное использование индексов

### 13. Что такое sharding в ClickHouse и как организовать распределенную систему?
**Что ожидают услышать:**
- Горизонтальное разделение данных между серверами
- Distributed таблицы для работы с шардами
- Ключ шардирования (sharding key)
- Балансировка данных
- Пример архитектуры: 3 шарда × 2 реплики

### 14. Как обрабатывать ошибки при работе с ClickHouse в Go? Какие специфические ситуации нужно учитывать?
**Что ожидают услышать:**
- Retry логика для временных сбоев
- Обработка context.Timeout
- Too many simultaneous queries ошибка
- Memory limit exceeded
- Circuit breaker pattern
- Graceful degradation (переключение на реплику)
- Логирование и мониторинг ошибок

### 15. Расскажите про TTL (Time To Live) в ClickHouse. Как его использовать?
**Что ожидают услышать:**
- Автоматическое удаление/перемещение старых данных
- TTL на уровне колонки и таблицы
- Перемещение в холодное хранилище
- Пример:
```sql
TTL created_at + INTERVAL 90 DAY DELETE
TTL created_at + INTERVAL 30 DAY TO DISK 'cold'
```
- Настройка расписания очистки

### 16. Как реализовать connection pooling для ClickHouse в Go приложении?
**Что ожидают услышать:**
- Использование встроенного пула в clickhouse-go
- Настройка MaxOpenConns, MaxIdleConns
- Connection lifetime
- Health checks для соединений
- Пример конфигурации:
```go
conn, err := clickhouse.Open(&clickhouse.Options{
    MaxOpenConns: 10,
    MaxIdleConns: 5,
    ConnMaxLifetime: time.Hour,
})
```

### 17. Объясните концепцию "Parts" в MergeTree. Как происходит merge и почему это важно?
**Что ожидают услышать:**
- Данные хранятся в иммутабельных частях (parts)
- Фоновое слияние частей (merge)
- Настройка merge_max_block_size
- Too many parts проблема
- OPTIMIZE TABLE для ручного слияния
- Влияние на производительность запросов

### 18. Как мониторить производительность ClickHouse из Go приложения?
**Что ожидают услышать:**
- Использование system таблиц (system.metrics, system.events)
- Query ID для трейсинга запросов
- Сбор метрик: query duration, rows read, memory usage
- Интеграция с Prometheus/Grafana
- Алерты на аномалии
- Пример экспорта метрик в формате Prometheus

### 19. Какие антипаттерны при работе с ClickHouse в Go приложениях вы знаете?
**Что ожидают услышать:**
- Одиночные INSERT вместо батчей
- Частые UPDATE/DELETE (использовать ReplacingMergeTree)
- JOIN больших таблиц без денормализации
- Отсутствие партиционирования для больших таблиц
- Использование SELECT * вместо конкретных колонок
- Игнорирование ORDER BY при создании таблиц
- Отсутствие timeout'ов в context

### 20. Опишите архитектуру высоконагруженной системы с ClickHouse. Как бы вы спроектировали систему для хранения и анализа 1TB логов в день?
**Что ожидают услышать:**
- Многоуровневая архитектура: Kafka → ClickHouse
- Шардирование по user_id или time
- Репликация для отказоустойчивости
- Партиционирование по дням
- TTL для старых данных (перемещение в S3)
- Materialized views для предвычислений
- Distributed таблицы для запросов
- Отдельные кластеры для write и read нагрузки
- Мониторинг и алертинг
- Backup стратегия
- Пример архитектуры:
  - 6 шардов для записи
  - 2 реплики на шард
  - Отдельный query cluster для тяжелых аналитических запросов
  - Kafka для буферизации
  - Go сервис для батчевой записи (10k записей/батч)
