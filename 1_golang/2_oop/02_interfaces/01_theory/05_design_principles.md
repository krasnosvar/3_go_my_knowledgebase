# Принципы дизайна интерфейсов в Go

## 1. Маленькие интерфейсы

«The bigger the interface, the weaker the abstraction» — Rob Pike.

Хороший интерфейс — 1–3 метода. Большие интерфейсы сложно реализовывать и мокать, и они обычно совмещают несколько ответственностей.

Идеальные примеры stdlib:

```go
type Reader interface { Read(p []byte) (n int, err error) }
type Writer interface { Write(p []byte) (n int, err error) }
```

## 2. Интерфейс — у потребителя, не у реализатора

В Java/C# интерфейс обычно живёт рядом с классом. В Go — наоборот: интерфейс объявляется там, **где им пользуются**.

```go
// в пакете service
type UserRepo interface {
    Get(ctx context.Context, id int) (User, error)
}

type Service struct{ repo UserRepo }
```

Реализатор (например, `postgresRepo`) не знает про `UserRepo` и просто имеет нужные методы. Это даёт слабую связность.

## 3. Accept interfaces, return structs

```go
func NewService(repo UserRepo) *Service { /* ... */ }
```

Функция принимает интерфейс (гибкость: любой совместимый тип), а возвращает конкретный тип (понятность, стабильное API).

## 4. Не вводи интерфейс «на будущее»

Одна реализация — одна абстракция это уже хорошо. Заводи интерфейс, когда:

- есть минимум две реальные реализации, или
- нужны моки для тестов, или
- разные модули должны договориться о контракте.

Интерфейс ради интерфейса раздувает API.

## 5. Имя интерфейса

Короткие имена на `-er`: `Reader`, `Writer`, `Saver`, `Notifier`. Для одного метода имя часто совпадает с методом + суффиксом. Для нескольких методов — собирательное существительное (`http.Handler`).

## 6. Композиция

Большой интерфейс = композиция маленьких:

```go
type ReadWriter interface {
    Reader
    Writer
}
```

Это удобнее, чем один «толстый» интерфейс.

## 7. Не привязывай интерфейс к конкретным типам полей

Интерфейс описывает **поведение**, не внутреннее устройство. Не пиши сеттеров и публичных полей в структурах, которые реализуют интерфейс — через него всё равно не доступно.

## 8. Empty interface (any)

Используй `any` только когда реально не знаешь тип (парсинг JSON в `map[string]any`, generic-коллекции до Go 1.18). С Generics большую часть случаев `any` заменяется типовым параметром.
