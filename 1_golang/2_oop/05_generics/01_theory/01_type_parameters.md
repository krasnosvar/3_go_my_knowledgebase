# Type parameters

Generics в Go появились в версии 1.18. Они позволяют писать функции и структуры, работающие с разными типами, сохраняя типобезопасность.

## Синтаксис

Type parameter записывается в квадратных скобках до обычных параметров:

```go
func Identity[T any](v T) T {
    return v
}

Identity(10)        // T выведется как int
Identity("hello")   // T выведется как string
```

Имена T, V, K — конвенция, но можно писать и `Element`, `Item`.

## Несколько параметров

```go
func Pair[K, V any](k K, v V) (K, V) { return k, v }

func Get[K comparable, V any](m map[K]V, k K) (V, bool) {
    v, ok := m[k]
    return v, ok
}
```

Разные параметры могут иметь разные ограничения.

## Инстанцирование

Компилятор подставляет конкретные типы при вызове. Чаще всего тип выводится из аргументов, но можно явно:

```go
Identity[int](10)
Get[string, User](users, "alice")
```

## Взаимные ограничения типов

Параметры могут зависеть друг от друга:

```go
func First[S ~[]E, E any](s S) E {
    return s[0]
}
```

`~[]E` означает «любой тип, чей underlying type — `[]E`». Это полезно для пользовательских типов-слайсов.

## Generic функции как значения

```go
f := Identity[int]
fmt.Println(f(5))
```

Имеется смысл, когда тип уже зафиксирован.

## Инстанцирование на этапе компиляции

Go не имеет reflection-generics (как в Java) и не делает monomorphization по всем типам (как в C++). Компилятор использует подход «stenciling by GCShape» — коды генерируются по «формам» типов. Для пользователя это прозрачно, но знать полезно при анализе производительности.

## Ограничения

- Параметры только для типов, не для значений: `func F[N int]()` не работает.
- Нет variadic type parameters: `func F[T... any]()` нельзя.
- Нет перегрузки по типу.
