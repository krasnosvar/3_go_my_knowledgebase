# Pitfalls generics

## 1. Нет generic-методов

Методы не могут иметь **собственные** type parameter'ы, только те, что у типа-носителя:

```go
// нельзя
func (s *Stack[T]) Map[U any](f func(T) U) []U { ... }
```

Обход: свободная функция `func StackMap[T, U any](s *Stack[T], f func(T) U) []U`.

## 2. Сложно выразить «одно из двух значений»

`T | error` в Go нет. Option/Result — делается руками:

```go
type Result[T any] struct { V T; Err error }
```

## 3. Premature genericization

```go
func First[T any](xs []T) T { return xs[0] }
```

Хорошо, если реально используется с разными типами. Плохо, если в проекте у тебя везде `First[User]` — проще `func firstUser(xs []User) User`.

## 4. Ограничения ломают очевидность

```go
func Sum[T ~int | ~float64](xs []T) T
```

В сложных сигнатурах приходится протягивать ограничения через всю цепочку. Поддержка страдает, если constraint не выделен в именованный тип.

## 5. Бесполезные дженерики

Если внутри функции нельзя ничего делать с `T` без дополнительных ограничений — значит, constraint слишком слабый. `any` редко полезен сам по себе; чаще нужен `comparable`, `cmp.Ordered` или свой union.

## 6. Generic структуры теряют `==`

Структуры с полями типа `T` можно сравнивать только если `T` — comparable. Если структура generic — компилятор не может утверждать comparable в общем случае. Храни отдельные методы `Equal(other Pair[K,V]) bool`, если нужно.

## 7. Generic на интерфейсе

`interface{ Foo[T any](v T) }` не разрешён. Пиши типизированный контракт на уровне всего интерфейса, не метода.

## 8. Стоимость кода

Каждая «форма» (gcshape) — отдельная копия сгенерированного кода. На сотни инстанцирований это может заметно увеличить бинарник.

## 9. Константы и generics

```go
func Min[T cmp.Ordered](a, b T) T { if a < b { return a }; return b }

Min(1, 2.0) // Go 1.21+: T = float64, результат 1; до 1.21 — ошибка вывода типа

var a int = 1
var b float64 = 2
Min(a, b) // ошибка: разные типы int и float64
```

С Go 1.21 нетипизированные константы разных видов приводятся к одному типу (как в обычном выражении `1 + 2.0`). Типизированные аргументы разных типов не сводятся никогда — приведи явно: `Min(float64(a), b)`.

## 10. Imports

`constraints.Ordered` жил в `golang.org/x/exp/constraints`, с Go 1.21 — `cmp.Ordered`. Путают и используют оба — выбирай один, соответствующий версии Go в проекте.
