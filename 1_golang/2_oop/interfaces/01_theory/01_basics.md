# Interfaces: основы

Интерфейс в Go — это набор методов. Тип реализует интерфейс **неявно**: достаточно иметь нужные методы, ключевое слово `implements` не требуется.

## Синтаксис

```go
type Speaker interface {
    Speak() string
}

type Dog struct{}

func (Dog) Speak() string { return "woof" }

type Cat struct{}

func (Cat) Speak() string { return "meow" }
```

Любой тип с подходящим методом автоматически реализует интерфейс:

```go
func Shout(s Speaker) { fmt.Println(strings.ToUpper(s.Speak())) }

Shout(Dog{}) // WOOF
Shout(Cat{}) // MEOW
```

## Внутреннее устройство

Интерфейсное значение содержит два слова:

- dynamic type — информация о конкретном типе внутри;
- dynamic value — указатель на данные.

Размер интерфейса — 16 байт на 64-битной платформе.

## Пустой интерфейс

`interface{}` (или `any` с Go 1.18) — это интерфейс без методов. Любое значение удовлетворяет ему.

```go
var a any = 42
var b any = "hello"
```

Использовать с осторожностью: теряется типобезопасность, часто нужны type assertion или type switch.

## Почему это важно

- **Слабая связность**: модуль зависит от контракта, а не от реализации.
- **Подмена**: в тестах и интеграциях легко поставить другую реализацию.
- **Расширяемость**: новый тип сразу совместим со всеми интерфейсами, у которых есть нужные методы.

## Отличие от Java/C#

- Нет `class implements Interface` — проверка компиляторная, по сигнатурам.
- Интерфейс обычно определяется в пакете-потребителе, не в пакете-реализаторе.
- Нет «абстрактных классов» — есть только интерфейсы и структуры.

## Проверка реализации на этапе компиляции

Идиома «ассертить реализацию»:

```go
var _ Speaker = (*Dog)(nil)
```

Если `*Dog` перестанет удовлетворять `Speaker`, код не скомпилируется. Полезная страховка.
