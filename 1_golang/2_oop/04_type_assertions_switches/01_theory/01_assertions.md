# Type assertions

Type assertion — извлечение конкретного типа из интерфейсного значения.

## Синтаксис

```go
var i interface{} = "hello"

s := i.(string)     // если тип не совпал — panic
s, ok := i.(string) // безопасная форма
```

- Без `ok` — рискованно: паника, если ассерт не удаётся.
- С `ok` — всегда. В реальном коде почти всегда нужна эта форма.

## Проверка реализации интерфейса

Assertion работает не только на конкретные типы, но и на интерфейсы:

```go
var w io.Writer = &bytes.Buffer{}

rw, ok := w.(io.ReadWriter)
if ok {
    _ = rw // можно использовать как ReadWriter
}
```

Полезно для **опциональных интерфейсов**: «если эта реализация умеет X, используем».

## Отличие от type switch

- `assertion` — проверка на **один** тип.
- `switch .(type)` — проверка на **несколько**.

## Стоимость

Assertion — не бесплатно. Runtime ищет совпадение по таблице типов. В hot path сотен миллионов операций это заметно, в обычном коде — нет.

## Чего assertion НЕ делает

- Не конвертирует значение. Если `i = 42`, `i.(string)` всегда провалится.
- Не работает на не-интерфейсных значениях: нельзя написать `x.(int)` для переменной типа `int`.

## Типичная ошибка

```go
s := i.(string)
```

без проверки в коде, который принимает пользовательские данные. Получится паника в рантайме на кривом входе. Всегда — форма с `ok` или `switch`.

## Когда assertion уместен

- Разовая проверка конкретного типа.
- Опциональный интерфейс (необязательное расширение).
- Внутри функции, где тип гарантирован логикой выше.

## Когда не стоит

- Массовое ветвление по многим типам — возьми type switch.
- Универсальные utility-функции — используй generics или интерфейс с методом.
