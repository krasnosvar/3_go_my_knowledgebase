# Value receiver vs Pointer receiver

## Value receiver

Метод получает **копию** значения.

```go
type Counter struct{ N int }

func (c Counter) Value() int { return c.N }
func (c Counter) Inc()       { c.N++ } // изменит копию
```

```go
var c Counter
c.Inc()
fmt.Println(c.N) // 0, изменения не увидели
```

Уместен для:

- маленьких значений без состояния;
- неизменяемых «value objects» (координата, money, color);
- чистых функций: на вход — data, на выход — data.

## Pointer receiver

Метод получает **адрес** значения, изменения видны снаружи.

```go
func (c *Counter) Inc() { c.N++ }
```

```go
var c Counter
c.Inc()
fmt.Println(c.N) // 1
```

Уместен, если:

- метод меняет receiver;
- тип большой (структура с десятками полей);
- в типе есть поле, которое нельзя копировать (`sync.Mutex`, `sync.WaitGroup`);
- хочешь единый стиль (см. «Консистентность»).

## Автовызов

Go сам умеет взять адрес, если вызов метода `*T` делается на addressable-значении:

```go
c.Inc() // OK, даже если c: Counter и Inc на *Counter
```

Но на неадресуемом выражении (например, элемент map) автоприведения нет:

```go
m := map[string]Counter{"a": {}}
// m["a"].Inc() // ошибка
v := m["a"]
v.Inc()
m["a"] = v
```

Для таких случаев храним `*Counter` или выносим инкремент наружу.

## Консистентность в типе

Правило: **все методы одного типа должны быть одного вида** — либо все pointer, либо все value. Смешение приводит к:

- ошибкам «тип не реализует интерфейс»;
- путанице: «а это вообще меняется?»

Если есть хоть один метод с pointer receiver — делай все остальные тоже pointer.

## Итог

- Небольшой immutable тип → value receiver.
- Любое состояние/мутация/крупная структура → pointer receiver.
