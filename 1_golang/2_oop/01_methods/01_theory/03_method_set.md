# Method set

Набор методов типа — это список методов, к которым можно обращаться через переменную этого типа. Именно method set определяет, реализует ли тип интерфейс.

## Правила method set

Для типа `T`:

- method set содержит **методы с receiver `T`** (value receiver).

Для типа `*T`:

- method set содержит **методы с receiver `T`** и **методы с receiver `*T`** (оба).

Это несимметрично: `*T` включает в себя method set `T`, но не наоборот.

```go
type S struct{}

func (s S)  A() {}
func (s *S) B() {}

var v S
v.A() // OK
v.B() // OK (автоматически взят &v, если v addressable)

var p *S = &v
p.A() // OK
p.B() // OK
```

## Важно для интерфейсов

```go
type Doer interface{ B() }

var d Doer
d = &S{} // OK
// d = S{}  // ошибка: S не реализует Doer (B на *S, а не на S)
```

Метод с pointer receiver есть **только** у `*S`, не у `S`. Это — классическая причина ошибок «тип X не реализует интерфейс».

## Addressability

Для автоматического взятия адреса значение должно быть adressable:

- локальная переменная — да;
- поле struct — да;
- элемент слайса — да;
- возвращаемое значение из функции — да (если присвоено);
- элемент map — **нет**;
- возвращённое из функции «на лету» — нет.

```go
m := map[string]S{"a": {}}
// m["a"].B() // ошибка: нельзя взять адрес
```

Поэтому в map часто хранят `*T`, если у типа есть методы на указателе.

## Практика

- Смотри, где твой тип используется как интерфейс. Если передаётся значение — нужны value-методы, если указатель — можно оба.
- Если ставишь метод с pointer receiver, консистентно пиши pointer-методы для всего типа.
- Если нужен стабильный набор интерфейсов — делай все методы на `*T`, и передавай `*T` везде.
