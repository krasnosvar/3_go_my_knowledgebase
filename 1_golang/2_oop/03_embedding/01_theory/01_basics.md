# Embedding: основы

Go не поддерживает наследование. Вместо этого есть **embedding** — встраивание одного типа в другой. Это форма композиции, при которой внешний тип автоматически получает поля и методы встроенного.

## Синтаксис

```go
type Engine struct {
    Power int
}

func (e Engine) Start() {
    fmt.Println("start")
}

type Car struct {
    Engine           // встроенный тип (анонимное поле)
    Brand string
}
```

Поле называется по имени типа: `car.Engine`.

## Доступ к полям и методам

```go
c := Car{
    Engine: Engine{Power: 150},
    Brand:  "Toyota",
}

c.Start()              // метод встроенного типа
fmt.Println(c.Power)   // поле встроенного типа
fmt.Println(c.Engine.Power) // то же через явную форму
```

Методы и поля **promoted** (продвигаются) — их можно вызывать напрямую через внешнюю структуру.

## Как работает «под капотом»

Это не наследование: `Car` и `Engine` — разные типы, между ними нет is-a связи. Компилятор просто переписывает обращения:

```go
c.Start() // эквивалент c.Engine.Start()
```

Никакой runtime-магии, только синтаксический сахар.

## Зачем

- Удобно подключать готовые «миксины» (Logger, Metrics, Clock).
- Можно собрать тип из нескольких независимых частей.
- Код внешней структуры становится плоским и читаемым.

## Отличие от наследования

- Нельзя переопределить метод и вызвать «родительский» через `super`. Можно определить одноимённый метод и вызывать его через явное поле: `c.Engine.Start()`.
- Нет иерархии: `Car` не считается `Engine`, даже если встраивает его.
- Не работает полиморфизм «через базовый тип». Полиморфизм в Go — через интерфейсы.

## Когда применять

- Часто: обёртки, декораторы, композиция маленьких поведений.
- Редко: если логика явно «is-a», и ты хочешь наследование — Go плохо подходит, возможно, нужен другой язык или другой дизайн.
