# Embedding указателя (`*T`)

Во встраивании можно использовать не только `T`, но и `*T`.

```go
type Engine struct{ Power int }
func (e *Engine) Start() {}

type Car struct {
    *Engine
    Brand string
}
```

## Разница с обычным embedding

| Вариант | Хранит | Методы |
|---|---|---|
| `T` | значение | value и pointer через addressable receiver |
| `*T` | указатель | value и pointer сразу, без addressability |

## Что это даёт

1. **Ленивая/общая инициализация.** Несколько Car могут указывать на один Engine:

```go
e := &Engine{Power: 150}
c1 := Car{Engine: e}
c2 := Car{Engine: e}
```

Изменение `e.Power` увидят оба.

2. **Nil-поле допустимо.** `Car{}` без присвоенного `*Engine` — валидное значение. Но вызов `car.Start()` приведёт к nil-panic, если встроенный метод разыменует `nil`.

3. **Выбор интерфейса.** Встраивание `*T` даёт внешнему типу доступ ко всем методам `T` и `*T` без заботы об addressability.

## Когда использовать

- Embedding существующего внешнего объекта, которым владеет другой модуль (`*http.Client`, `*sql.DB`).
- Когда встроенная структура большая и копировать нецелесообразно.
- Обёртка для логирования/метрик: нужно делегировать к внутреннему `*T`, не переустанавливая его.

## Когда осторожно

- Если внешний тип создаётся как zero value, `*T` будет `nil`. Документируй контракт «нельзя использовать без инициализации».
- Конкурентный доступ: одно и то же `*Engine` разделяется между `Car`-ами — нужны мьютексы, если пишем.
- Стоимость разыменования — обычно нулевая, но в мега-хот-коде может проявиться.

## Рецепт

Если тип — «кусок инфраструктуры» (клиент, логгер, репо) — встраивай `*T`. Если это value object — встраивай `T`.
