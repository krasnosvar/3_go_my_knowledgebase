# Table-driven: pitfalls

## 1. Loop variable capture в горутинах

```go
for _, tt := range tests {
    tt := tt        // обязательно для версий < 1.22
    t.Run(tt.name, func(t *testing.T) {
        t.Parallel()
        // ...
    })
}
```

Без локального копирования при `t.Parallel()` все подтесты увидят последний `tt`.

С Go 1.22+ переменная цикла создаётся новая на каждой итерации, копирование не нужно. Но для совместимости версии — пиши явно.

## 2. Слишком много полей в одной таблице

Когда struct случая разрастается до 10+ полей, тест становится не читаемым:

```go
{name:"x", a:1, b:2, c:3, d:nil, ctx:ctx, mock:m, want:..., wantErr:..., setup:..., teardown:...}
```

Вариант: вынести setup в helper, оставить в структуре только семантически разные поля.

Иногда лучше — несколько отдельных тестов вместо одной мегатаблицы.

## 3. Шумная проверка

```go
if got != tt.want {
    t.Errorf("test %d: %s: input=%v, got=%v, want=%v", i, tt.name, tt.input, got, tt.want)
}
```

В условии `t.Run(tt.name, ...)` имя кейса уже выводится — повторять его не нужно. Сообщение проще.

## 4. Общее состояние между кейсами

```go
db := newDB()
for _, tt := range tests {
    t.Run(tt.name, func(t *testing.T) {
        db.insert(tt.input) // мутация общего state
        // ...
    })
}
```

Если кейсы влияют друг на друга — порядок становится частью теста. Делай чистый state на каждый `t.Run` или используй `t.Cleanup`.

## 5. Слишком много кейсов одинаковой природы

15 кейсов «ровно такая же арифметика, чуть другие числа» — это шум. Достаточно 3-5: типичный, граничный, ошибочный.

## 6. Игнорирование части ошибок

```go
got, _ := Parse(tt.in)  // ошибку игнорируем
```

Так теряется покрытие error-веток. Всегда проверяй `err` явно — даже если он должен быть `nil`.

## 7. Скрытая логика в want

```go
want: time.Now().Add(time.Second),
```

`time.Now()` в инициализации таблицы вызовется один раз при объявлении, не в каждом подтесте — будет flaky. Двигай в setup внутрь `t.Run`.

## Правило

Table-driven — это структура для **похожих** кейсов. Когда таблица превращается в свалку — разбей на несколько Test-функций.
