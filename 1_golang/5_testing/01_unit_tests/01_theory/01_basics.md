# Unit tests: основы

Unit-тесты в Go — встроены в язык, без сторонних фреймворков. Это сильная сторона: запустил `go test` — и работает.

## Структура

- Файл с тестами называется `*_test.go`.
- Лежит в **том же пакете**, что и тестируемый код (или в `pkg_test` для black-box).
- Функция начинается с `Test`: `func TestXxx(t *testing.T)`.

```go
// math.go
package math

func Add(a, b int) int { return a + b }

// math_test.go
package math

import "testing"

func TestAdd(t *testing.T) {
    if got := Add(2, 3); got != 5 {
        t.Fatalf("Add(2,3) = %d; want 5", got)
    }
}
```

## Запуск

```
go test ./...
go test -v ./...                # подробный вывод
go test -run TestAdd ./...      # фильтр по имени
go test -race ./...             # с race detector
go test -count=1 ./...          # отключить кэш
go test -cover ./...            # покрытие
```

`-count=1` — лекарство от тестов, которые «прошли в кэше» и не запустились заново. Часто кладут в Makefile.

## t.Error vs t.Fatal

- `t.Error/Errorf` — отметить тест провалившимся, **продолжить** выполнение.
- `t.Fatal/Fatalf` — отметить и **остановить** функцию.

В цепочке assert'ов после первой ошибки часто бессмысленно продолжать → `Fatal`. Когда хочется собрать все ошибки → `Error`.

## Имена и стиль

```go
func TestAdd_Positive(t *testing.T) { ... }
func TestAdd_NegativeNumbers(t *testing.T) { ... }
```

Подчёркивание после `Test` — типовая практика для подкатегорий. Но `TestAddPositive` тоже ок.

## Что тестировать

- **Бизнес-логика**: услуги, валидация, преобразования.
- **Граничные случаи**: пустой ввод, nil, переполнение, лимиты.
- **Ошибочные пути**: каждая ветка `return err` должна быть покрыта.
- **Регрессии**: после каждого исправленного бага — тест, который зафиксирует поведение.

## Что не тестировать

- Тривиальные геттеры/сеттеры без логики.
- Внешний код (`fmt`, `strings`) — он уже протестирован.
- Точные форматы логов, если они не часть контракта.

## Где не использовать

- Интеграцию с реальной БД, сетью, файлами — в integration tests, не в unit (или с моками/in-memory FS).
- Параллельный код без `-race` — гонки скрываются.
