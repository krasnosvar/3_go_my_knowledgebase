# Частые ошибки и покрытие

## 1. Ассерт без сообщения

```go
if got != want {
    t.Fatal("error") // что именно не так?
}
```

Лучше:

```go
if got != want {
    t.Fatalf("Add(2,3) = %d; want %d", got, want)
}
```

В большом тестрана сообщение помогает понять причину без отладчика.

## 2. Сравнение через `==` для slices/maps/struct с reference-полями

`==` для слайсов запрещён, для map — тоже. Используй:

- `slices.Equal(a, b)`;
- `maps.Equal(m1, m2)`;
- `reflect.DeepEqual(a, b)` — универсально, но медленно;
- `cmp.Diff(want, got)` из `github.com/google/go-cmp` — лучшие сообщения об отличиях.

## 3. Тесты, зависящие от порядка выполнения

```go
var counter int

func TestA(t *testing.T) { counter++ /* ... */ }
func TestB(t *testing.T) { /* uses counter */ }
```

Тесты должны быть независимы. Если `TestB` падает после `TestA` — это баг теста.

## 4. Глобальное состояние

Любая глобальная переменная между тестами — мина. С `t.Parallel()` это сразу гонка.

## 5. Тесты на конкретные сообщения ошибок

```go
if err.Error() != "user not found" { ... }
```

Завязка на текст ошибки — хрупкая. Лучше `errors.Is(err, ErrNotFound)`.

## 6. Тесты «всё или ничего»

Один большой тест, проверяющий пять сценариев → при первом падении остальные не выполнились. Разбивай на отдельные `Test*` или используй table-driven (см. `02_table_driven_tests`).

## Покрытие

```
go test -cover ./...
go test -coverprofile=cover.out ./...
go tool cover -html=cover.out
```

- `-coverprofile` пишет файл, который можно визуализировать.
- HTML-вид показывает, какие строки не покрыты.

## Покрытие — индикатор, не цель

- 100% покрытие легко достижимо тестами без assert'ов и не значит «качество».
- Покрытые ветки — лучше, чем покрытые строки.
- Низкое покрытие на критичных сервисах — повод разобраться. Высокое — само по себе ничего не гарантирует.

Реалистичный диапазон для backend-сервисов: 60–80% линейного покрытия с осмысленными тестами.

## Тесты как документация

Хороший тест читается как «вот что эта функция делает». Это альтернатива комментариям. Если в тесте 100 строк — не документация, а проблема.

## Правило

- Сообщения в `t.Fatalf` — всегда содержательные.
- Сравнения сложных типов — `cmp.Diff` или `slices.Equal`.
- Никакого глобального state.
- Ошибки сравниваются через `errors.Is/As`, не по тексту.
