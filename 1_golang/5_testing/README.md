# 5. Testing

Тестирование в Go: стандартный пакет `testing`, без сторонних фреймворков.

**Уже знакомы с темой?** → [CHEATSHEET.md](./CHEATSHEET.md) — общая шпаргалка раздела: флаги `go test`, методы `t`, table-driven, подтесты, бенчмарки (`b.Loop` 1.24+), моки, интеграционные тесты.

## Зачем

Тесты — способ доказать, что код работает, и не бояться его менять.
В Go всё нужное встроено: `go test`, табличные тесты, подтесты,
бенчмарки, `httptest`, `t.TempDir`. Этот раздел учит писать тесты так,
как это принято в Go-проектах.

## Как запускать

Раздел — часть корневого модуля репозитория (`go.mod` лежит в корне).
Из корня:

```bash
go test ./1_golang/5_testing/...                 # всё (упражнения-заготовки упадут — это нормально)
go test ./1_golang/5_testing/.../02_examples/... # только примеры
go test ./1_golang/5_testing/.../04_exercises_answers/... # только эталоны
go test -short ./1_golang/5_testing/...          # без медленных тестов
```

Или из папки раздела: `cd 1_golang/5_testing && go test ./...`.

## Самопроверка

Самопроверка в этом разделе — сам `go test`:

- **«напишите тест»** (большинство задач): рядом с кодом лежит `*_test.go`
  с заглушкой `t.Fatal("TODO ...")`, поэтому в стартовом состоянии
  `go test` печатает `FAIL`. Напишите проверки, удалите `t.Fatal` — тест
  должен стать `ok`. Чтобы убедиться, что тест действительно что-то ловит,
  временно сломайте код под тестом: тест обязан упасть.
- **«почините код»** (задачи 02–04 в `04_benchmarks`): тест уже написан и
  падает, править нужно только код под тестом.
