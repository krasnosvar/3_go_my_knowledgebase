# Как читать результаты

Бенч сам по себе ничего не говорит — нужно уметь читать и сравнивать.

## Структура вывода

```
BenchmarkParse-8    1234567    96.4 ns/op    24 B/op    1 allocs/op
```

- `BenchmarkParse-8` — имя + GOMAXPROCS, на котором был запущен.
- `1234567` — сколько раз бенч был выполнен (`b.N`).
- `96.4 ns/op` — среднее время на одну операцию.
- `24 B/op` — байт аллоцировано в среднем на операцию.
- `1 allocs/op` — количество аллокаций на операцию.

## benchstat

`golang.org/x/perf/cmd/benchstat` — обязательный инструмент для сравнения.

```
go test -bench=. -count=10 ./... > before.txt
# меняем код
go test -bench=. -count=10 ./... > after.txt
benchstat before.txt after.txt
```

Вывод:

```
name        old time/op    new time/op    delta
Parse-8     96.4ns ± 2%    52.1ns ± 1%   -45.95%  (p=0.000 n=10+10)
```

`delta` — изменение, `p` — статистическая значимость. `p < 0.05` — реальное изменение, не шум.

`-count=10` (или больше) обязателен: один прогон ничего не говорит.

## Шум

Источники нестабильности:

- Турбобуст / частота CPU.
- Фоновые процессы (Slack, антивирус).
- Тепловой троттлинг.
- GC между итерациями.

В CI результаты часто шумнее, чем локально. Изолированная виртуалка с фиксированной частотой — лучший вариант, если бенч важен для проекта.

## Аллокации

`B/op` и `allocs/op` часто важнее `ns/op`:

- 0 allocs/op — функция не давит на GC, работает стабильно под нагрузкой.
- N allocs/op в hot path → `sync.Pool`, `strings.Builder`, переиспользование буферов.

## Что НЕ выводить

- Сравнение «`fmt.Sprintf` vs `strconv.Itoa`» — все знают, что `strconv` быстрее. Бенч ради бенча.
- Сравнение разных алгоритмов на нерепрезентативных данных. Бенч на 5 элементах не покажет ничего про 5 миллионов.
- Сравнение бенчей **разных версий Go** — runtime может изменить базовые цифры.

## Бенч + профайл

Бенч измеряет, профайл показывает почему:

```
go test -bench=. -cpuprofile=cpu.out
go tool pprof cpu.out
```

Из бенч можно сразу собрать flamegraph и посмотреть, где реально тратится время.

## Правило

- `-count >= 5` (лучше 10) и `benchstat` для сравнения.
- `-benchmem` всегда.
- Бенч под профайл, не для красивых цифр в README.
