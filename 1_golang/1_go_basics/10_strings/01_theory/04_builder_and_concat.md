# Оптимизация сборки строк: strings.Builder

Конкатенация строк через оператор `+` в цикле — антипаттерн:

```go
// ПЛОХО: на каждой итерации выделяется новый массив памяти
var s string
for i := 0; i < 1000; i++ {
    s += "data"
}
```

Поскольку строки неизменяемы, каждая операция `+=` создаёт новую строку и копирует в неё всё накопленное ранее содержимое.

## Идиоматический способ: `strings.Builder`

`strings.Builder` накапливает данные во внутреннем буфере (слайсе байт). При завершении сборки метод `String()` возвращает строку без копирования данных (используя `unsafe` под капотом).

```go
var builder strings.Builder
builder.Grow(4000) // Заранее выделяем память под 4000 байт!

for i := 0; i < 1000; i++ {
    builder.WriteString("data")
}
result := builder.String() // 0 аллокаций при получении строки!
```

## Метод Grow()

Всегда используйте `Grow()` перед началом записи, если примерный итоговый размер строки известен заранее. Это снижает количество переаллокаций памяти до одной.

> ⚠️ Частый вопрос на собеседовании: почему `strings.Builder` быстрее конкатенации через `+`? Потому что он пишет в один переиспользуемый буфер, а `+` в цикле аллоцирует и копирует новую строку на каждой итерации.
