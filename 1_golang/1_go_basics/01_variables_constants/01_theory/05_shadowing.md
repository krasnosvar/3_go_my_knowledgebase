# Shadowing (затенение переменных)

Shadowing — это когда внутри блока объявляется новая переменная с тем же именем, что у внешней. Внутренняя «затеняет» внешнюю, пока блок не завершится.

```go
x := 1
if true {
    x := 2        // новая x, затеняет внешнюю
    fmt.Println(x) // 2
}
fmt.Println(x)    // 1
```

## Частая ловушка с err

```go
err := doA()
if err != nil {
    return err
}

if ok := check(); ok {
    err := doB()         // <-- новая err, не та же
    fmt.Println(err)      // обрабатывается локально
}
// здесь err всё ещё от doA()
```

Если хотел обновить внешнюю `err`, пиши `err =` или убедись, что нет `:=` с тем же именем.

## Ещё один случай — возврат из замыкания

```go
result := 0
doStuff(func() {
    result := compute() // shadow! внешняя не изменится
    _ = result
})
fmt.Println(result) // 0
```

Правильно:

```go
doStuff(func() {
    result = compute()
})
```

## Как найти

- `go vet -shadow` на старых версиях, `staticcheck` / `govet` в современных линтерах.
- golangci-lint включает проверку по умолчанию.

## Как избежать

- Давать переменным разные имена, когда смысл разный (`err`, `errSave`, `errLoad`).
- Держать функции короткими — shadowing реже прячется.
- Следить за `:=` во вложенных блоках, особенно вместе с `err`.

## Когда shadowing полезен

- Временная переменная внутри `if`, `for`, `switch` — явно ограниченная по scope.
- Копия слайса в цикле, чтобы не затереть внешнюю.

В остальных случаях — сигнал, что стоит переименовать.
