# nil и безопасность

## nil — нулевое значение указателя

```go
var p *int
p == nil // true
*p       // panic: invalid memory address
```

Перед разыменованием защищайся проверкой, если источник ненадёжный.

## Когда указатель может быть nil

- ещё не присвоен;
- вернулся из функции, которая «не нашла»;
- поле структуры, которое иногда задано, иногда нет;
- элемент map, которого там нет (для map-а указателей).

## Безопасный доступ через метод

Метод с pointer receiver **можно вызвать на nil**, если внутри он этот случай обрабатывает. Это идиома для «линзы»:

```go
type List struct{ head *Node }

func (l *List) Len() int {
    if l == nil {
        return 0
    }
    // ...
}
```

## nil-интерфейс vs интерфейс с nil-значением

Это классическая ловушка.

```go
var p *MyErr // nil
var e error  // nil интерфейс

e = p        // теперь e не nil!
// e == nil  // false, но e содержит nil-указатель
```

Интерфейс равен `nil`, только если **и** тип, **и** значение внутри равны нулю. Если тип известен, а значение `nil` — интерфейс всё ещё «не nil».

Правило: возвращай `nil` как конкретный nil-интерфейс, не как типизированный указатель, если ошибки нет.

```go
// плохо
func do() error {
    var e *MyErr
    return e // вызывающий получит e != nil
}

// хорошо
func do() error {
    return nil
}
```

## Инвариант: «nil значит отсутствует»

Если в структуре есть `*T`, чётко зафиксируй документацией, что значит `nil`: «не задано», «значение по умолчанию», «неинициализировано». Иначе код становится угадайкой.
