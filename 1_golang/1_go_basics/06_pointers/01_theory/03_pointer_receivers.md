# Receivers: значение vs указатель

Метод в Go привязывается к типу через receiver. Receiver бывает по значению или по указателю.

## Receiver по значению

```go
type Rectangle struct{ W, H float64 }

func (r Rectangle) Area() float64 { return r.W * r.H }
```

Метод получает **копию** структуры. Изменения внутри метода не видны снаружи.

## Receiver по указателю

```go
func (r *Rectangle) Scale(k float64) {
    r.W *= k
    r.H *= k
}
```

Метод получает **указатель** на оригинал. Модификации видны снаружи.

## Правила выбора

Выбирай pointer receiver, если хотя бы одно верно:

- метод изменяет receiver;
- структура большая и копирование затратно;
- в типе есть `sync.Mutex`, `sync.WaitGroup` и т.п. — их нельзя копировать;
- у типа уже есть другие методы с pointer receiver (для консистентности).

Value receiver уместен для:

- маленьких неизменяемых значений;
- типов, где копирование — это нормально (`time.Time`, `image.Point`).

## Набор методов и интерфейсы

Это тонкий момент:

- Если метод объявлен на `T`, его имеют и `T`, и `*T`.
- Если метод объявлен на `*T`, его имеет **только** `*T`.

```go
type Speaker interface{ Say() }

type Dog struct{}
func (d *Dog) Say() { fmt.Println("woof") }

var s Speaker
s = &Dog{} // ok
// s = Dog{}   // ошибка: Dog не реализует Speaker
```

Поэтому при работе с интерфейсами обычно передают указатель.

## Консистентность в одном типе

Плохо, когда часть методов на `T`, часть на `*T`. Это путает читателя и провоцирует баги. Придерживайся одного стиля для одного типа.
