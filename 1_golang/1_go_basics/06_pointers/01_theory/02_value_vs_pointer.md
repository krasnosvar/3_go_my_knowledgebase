# Значение vs указатель

В Go аргументы и поля **всегда копируются**. Разница в том, что именно копируется: данные или адрес.

## Копируется значение

```go
func inc(x int) { x++ }

a := 1
inc(a)
fmt.Println(a) // 1 — x был копией
```

Для int/bool/struct-копия — копия данных целиком.

## Копируется указатель

```go
func inc(p *int) { *p++ }

a := 1
inc(&a)
fmt.Println(a) // 2 — правили исходное значение через указатель
```

Сам указатель тоже копируется, но оба указателя ведут в один адрес.

## Slices, maps, channels

Это ссылочные заголовки: сам заголовок копируется, но данные под ним общие. Поэтому функции **могут** модифицировать элементы, не получая указатель:

```go
func set0(s []int) { s[0] = 99 }

nums := []int{1, 2, 3}
set0(nums)       // nums == [99 2 3]
```

Важный нюанс: `append` может аллоцировать новый массив — тогда внешний слайс не увидит добавленных элементов. Чтобы увидел, возвращай слайс обратно или передавай `*[]T`.

## Когда брать указатель

- **Большая структура.** Копия в каждом вызове — лишняя работа и память.
- **Метод должен изменить получатель.**
- **Ты хочешь различать «нет значения» и «ноль».** `*int == nil` ≠ `int == 0`.
- **Идентичность объекта важна.** `*User` — это один пользователь, `User` — это копия состояния.

## Когда НЕ брать указатель

- Маленькие значения (примитивы, мелкие struct) — копия дешевле разыменования и escape-аллокаций.
- Неизменяемые данные — передавай по значению для ясности.
- `time.Time`, `net/url.URL` — обычно передаются по значению.
