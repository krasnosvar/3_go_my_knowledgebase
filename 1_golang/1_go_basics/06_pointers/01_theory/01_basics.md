# Основы указателей

Указатель хранит **адрес** области памяти, где лежат фактические данные. Тип указателя на значение типа `T` записывается как `*T`.

## Два оператора: `&` и `*`

- **`&` (взятие адреса)** — возвращает адрес переменной в памяти.
- **`*` (разыменование)** — получает доступ к значению, лежащему по адресу.

```go
x := 42
p := &x         // p имеет тип *int и хранит адрес переменной x
fmt.Println(*p) // 42 — разыменование: значение по адресу p

*p = 100        // меняем значение в ячейке памяти x через указатель
fmt.Println(x)  // 100
```

Схема:

```text
   x                 p
+------+          +--------+
|  42  | <------- | 0xc000 |
+------+          +--------+
 0xc000            *p == 42
```

## Нулевое значение указателя — nil

Необъявленный/непроинициализированный указатель равен `nil`. Разыменование `nil` — это panic:

```go
var p *int
fmt.Println(p == nil) // true
fmt.Println(*p)       // panic: invalid memory address
```

Подробно про `nil`-безопасность и ловушку типизированного `nil` в интерфейсах — в [04_nil_and_safety.md](./04_nil_and_safety.md).

## Создание указателей: `&` и `new`

```go
x := 42
p := &x          // указатель на существующую переменную

q := new(int)    // new(T) выделяет нулевое значение T и возвращает *T
*q = 7           // q указывает на int со значением 7
```

## Авто-разыменование у структур

Для полей структуры Go автоматически разыменовывает указатель — писать `(*p).Field` не нужно:

```go
type User struct{ Name string }

u := &User{Name: "Ann"}
fmt.Println(u.Name) // не (*u).Name — Go делает это сам
u.Name = "Bob"      // тоже работает через указатель
```

## Арифметика указателей запрещена

В отличие от C/C++, в обычном Go нельзя сдвигать указатель (`p++`, `p+1`). Это часть гарантий безопасности памяти. Обойти можно только через пакет `unsafe` (`unsafe.Pointer`, `uintptr`), что отключает эти гарантии и может привести к порче памяти или segfault — применяется крайне редко и только с бенчмарками.

## Зачем нужны указатели

1. **Изменять аргумент/получатель из функции** — без указателя функция работает с копией.
2. **Не копировать большие структуры** — передаётся адрес, а не все поля.
3. **Различать «нет значения» и «ноль»** — `*int == nil` ≠ `int == 0`.
4. **Идентичность объекта** — `*User` это один и тот же пользователь, а не копия состояния.

Как именно копируются значения и указатели — в [02_value_vs_pointer.md](./02_value_vs_pointer.md). Подробные сценарии применения — в [06_use_cases.md](./06_use_cases.md).

## Stack vs heap: Escape Analysis

В C++ программист сам решает, где выделить память: на стеке (локально) или в куче. В Go это решает компилятор с помощью **Escape Analysis** (анализ «побега» переменной).

Переменная «убегает» в кучу (escapes to heap), если:

- **Возвращается указатель наружу.** Локальная переменная не может жить на стеке функции, который очищается после возврата:

  ```go
  func getPointer() *int {
      x := 42       // компилятор аллоцирует x в куче
      return &x
  }
  ```

- **Значение передаётся в `interface{}` / `any`** (например, в `fmt.Println`).
- **Слишком большой размер** (огромные массивы не помещаются на стек).

> [!TIP]
> Аллокации в куче нагружают сборщик мусора (GC). Для небольших структур предпочитайте семантику значений (копирование на стеке), чтобы снизить нагрузку на GC.

Проверить решения компилятора можно так:

```bash
go build -gcflags='-m' ./...
```

## ⚠️ Частый вопрос на собеседовании

- **Чем `&` отличается от `*`?** `&x` берёт адрес, `*p` разыменовывает (читает/пишет значение по адресу).
- **Что будет при разыменовании `nil`-указателя?** Паника `invalid memory address`.
- **Есть ли в Go арифметика указателей?** Нет (кроме `unsafe`).
- **Где живёт переменная, на которую вернули указатель из функции?** В куче — из-за Escape Analysis.
