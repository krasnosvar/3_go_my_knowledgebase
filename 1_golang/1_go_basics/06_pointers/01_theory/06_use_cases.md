# Use-cases указателей

## 1. Модификация из функции

Любая функция, которая должна изменить значение аргумента, берёт указатель.

```go
func inc(x *int) { *x++ }
```

Для полей структуры — то же самое через pointer receiver:

```go
func (u *User) Rename(name string) { u.Name = name }
```

## 2. Большие структуры

Копировать структуру, в которой десятки полей (например, конфиг сервиса), дорого. Передаёшь `*Config`, и разыменование делается само.

## 3. Опциональность поля

`*int` внутри структуры говорит «значение может отсутствовать». Это часто лучше, чем sentinel-значение `-1` или «магическая» 0.

```go
type UpdateUser struct {
    Name *string // если nil — имя не меняем
    Age  *int
}
```

## 4. Идентичность объекта

Когда важно, что это «один и тот же» объект, а не «с такими же полями» — передаёшь `*T`. Типичный пример: репозитории и кеши в backend.

## 5. Интерфейсы и методы с модификацией

Если метод меняет receiver, он должен быть на `*T`. Чтобы значение типа реализовало такой интерфейс, передаётся именно `&Val`, не `Val`.

## 6. Zero-copy чтение/запись

В перформанс-критичных местах (`io.Reader`, binary-парсеры) указатели позволяют избежать копирования буферов. Делать это стоит с бенчмарками.

## Когда указатель не нужен

- Примитивы, маленькие значения.
- Immutable-данные без идентичности (`time.Time`, `url.URL`).
- Возвращаемые сразу значения, а не состояния.
