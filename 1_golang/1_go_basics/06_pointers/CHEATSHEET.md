# Указатели — шпаргалка

Подробности и объяснения — в [01_theory/](./01_theory/). ⚠️ — частая ловушка.

## Синтаксис

Подробно: [01_basics.md](./01_theory/01_basics.md).

| Задача | Код |
| :--- | :--- |
| Тип «указатель на T» | `*T` |
| Взять адрес | `p := &x` |
| Прочитать / записать по адресу | `v := *p`; `*p = 100` |
| Zero value | `var p *int` → `nil` |
| Новый объект с нулевым значением | `q := new(int)` (`*int` → `0`) |
| Новый объект с начальным значением (1.26+) | `r := new(7)`; до 1.26: `v := 7; r := &v` |
| Указатель на литерал структуры | `u := &User{Name: "Ann"}` |
| Поле через указатель | `u.Name` (авто-разыменование, не `(*u).Name`) |
| Изменить аргумент в функции | `func inc(p *int) { *p++ }` → `inc(&a)` |
| Указатель на указатель | `pp := &p`; `**pp = 42` |
| Арифметика указателей | нет (только через `unsafe`) |
| Посмотреть escape analysis | `go build -gcflags='-m' ./...` |

| Переменная уходит в кучу, если | Пример |
| :--- | :--- |
| Указатель на неё возвращается из функции | `func f() *int { x := 42; return &x }` |
| Значение передаётся в `any` | `fmt.Println(x)` |
| Слишком большая для стека | огромный массив |

## Значение vs указатель

Подробно: [02_value_vs_pointer.md](./01_theory/02_value_vs_pointer.md).

| Что передали | Что копируется | Изменения видны снаружи |
| :--- | :--- | :--- |
| `int`, `bool`, `struct`, массив | данные целиком | нет |
| `*T` | адрес | да, через `*p` / `p.Field` |
| `[]T` | заголовок (ptr, len, cap) | элементы — да; `append` — нет (вернуть слайс или `*[]T`) |
| `map`, `chan` | указатель | да |

| Брать `*T` | Брать `T` |
| :--- | :--- |
| нужно изменить значение / получатель | маленькие значения, примитивы |
| большая структура (конфиг) | неизменяемые данные |
| «нет значения» ≠ ноль (`*int`, PATCH-поля `Name *string`) | `time.Time`, `url.URL` — по значению |
| важна идентичность объекта (репозиторий, кеш) | значения, которые сразу возвращаются |

## Receivers

Подробно: [03_pointer_receivers.md](./01_theory/03_pointer_receivers.md).

| Receiver | Метод видит | Когда |
| :--- | :--- | :--- |
| `func (r T) M()` | копию | маленькие неизменяемые типы (`time.Time`, `image.Point`) |
| `func (r *T) M()` | оригинал | меняет получатель; большая структура; внутри `sync.Mutex`/`WaitGroup`; у типа уже есть `*T`-методы |

| Метод объявлен на | Есть в наборе методов `T` | Есть в наборе методов `*T` |
| :--- | :--- | :--- |
| `T` | да | да |
| `*T` | нет | да |

`func (d *Dog) Say()` → `var s Speaker = &Dog{}` компилируется, `= Dog{}` — нет.

## nil и интерфейсы

Подробно: [04_nil_and_safety.md](./01_theory/04_nil_and_safety.md).

| Ситуация | Результат |
| :--- | :--- |
| `*p` при `p == nil` | panic `invalid memory address or nil pointer dereference` |
| Метод с `*T`-receiver на nil | работает, если внутри `if l == nil { return 0 }` |
| `var e error = (*MyErr)(nil)` | `e != nil` — тип в интерфейсе задан |
| Интерфейс `== nil` | только если и тип, и значение — `nil` |
| Нет ошибки | `return nil`, а не типизированный nil-указатель |

```go
package main

import "fmt"

type MyErr struct{}

func (*MyErr) Error() string { return "my error" }

type List struct{ n int }

func (l *List) Len() int { // nil-безопасный метод
	if l == nil {
		return 0
	}
	return l.n
}

func inc(p *int) { *p++ }

func resetTo(pp **int, v int) { *pp = &v }

func bad() error {
	var e *MyErr // nil-указатель
	return e     // интерфейс (тип=*MyErr, значение=nil) != nil
}

func main() {
	x := 42
	p := &x
	*p = 100
	inc(&x)
	fmt.Println(x, *p) // 101 101

	q := new(int)       // *int на нулевое значение
	r := new(7)         // Go 1.26+: new(выражение)
	fmt.Println(*q, *r) // 0 7

	var pp *int
	resetTo(&pp, 5)
	fmt.Println(*pp) // 5

	var l *List
	fmt.Println(l.Len()) // 0 — вызов на nil-получателе

	err := bad()
	fmt.Println(err == nil, err != nil) // false true

	s := []int{1, 2, 3}
	func(s []int) { s[0] = 99 }(s)
	func(s []int) { s = append(s, 4) }(s)
	fmt.Println(s) // [99 2 3] — элементы общие, append не виден
}
```

## Ловушки

Подробно: [06_use_cases.md](./01_theory/06_use_cases.md).

- ⚠️ Разыменование nil → panic; проверять указатели из ненадёжных источников (map указателей, «не нашли»).
- ⚠️ Возврат типизированного nil (`var e *MyErr; return e`) как `error` → вызывающий видит `err != nil`.
- ⚠️ `append` внутри функции не виден снаружи, если массив переаллоцирован.
- ⚠️ Value receiver у типа с `sync.Mutex` копирует мьютекс (`go vet` — `copylocks`).
- ⚠️ Смешивать `T`- и `*T`-receivers в одном типе — путаница с интерфейсами.
- ⚠️ `*T` для мелких значений «ради скорости» — лишние аллокации в куче и нагрузка на GC.
- ⚠️ Поле `*T` без документации, что значит `nil` («не задано»? «по умолчанию»?) — угадайка.
