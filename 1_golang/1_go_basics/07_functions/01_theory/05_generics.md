# Дженерики (Generics) в Go - Содержание

> Дженерики или Type Parameters — это, пожалуй, самое крупное обновление в истории Go (появились в версии 1.18). Они позволяют писать функции и структуры, которые работают с разными типами данных, не теряя при этом строгую типизацию и не уходя в медленную рефлексию.

## Основные темы:

### 1. **Параметры типа (Type Parameters)**
Основа синтаксиса: как объявить, что функция «всеядная».

- **Синтаксис квадратных скобок**
  - Базовый синтаксис: `func MyFunc[T any](arg T) T`
  - Несколько параметров типа: `func Process[K comparable, V any](key K, value V)`
  - Параметры типа в сигнатуре функции
  - Возвращаемые типы с параметрами

- **Идентификаторы типов**
  - Конвенции именования: `T`, `V`, `K` (Type, Value, Key)
  - Можно использовать любые имена: `Element`, `Item`, `Data`
  - Рекомендации по выбору понятных имен

- **Инстанцирование (Instantiation)**
  - Процесс замены параметра `T` на конкретный тип
  - Автоматический вывод типов: `MyFunc(42)` вместо `MyFunc[int](42)`
  - Явное указание типа: `MyFunc[string]("hello")`
  - Когда компилятор требует явного указания
  - Момент инстанцирования (compile-time)

- **Синтаксис вызова**
  - Вывод типов из аргументов
  - Явная спецификация типов
  - Комбинация выведенных и явных типов

### 2. **Ограничения (Constraints)**
Мы не всегда хотим принимать любой тип. Иногда нам нужно только то, что можно сравнивать или складывать.

- **Интерфейсы как ограничения**
  - Использование интерфейсов в квадратных скобках
  - Определение собственных constraint интерфейсов
  - Встроенные ограничения: `any`, `comparable`
  - Методы в constraint интерфейсах

- **Пакет constraints**
  - `constraints.Ordered` - числа и строки, которые можно сравнивать
  - `constraints.Integer` - все целочисленные типы
  - `constraints.Float` - все типы с плавающей точкой
  - `constraints.Signed` - знаковые целые числа
  - `constraints.Unsigned` - беззнаковые целые числа
  - `constraints.Complex` - комплексные числа
  - Импорт: `golang.org/x/exp/constraints`

- **Аппроксимация типов (тильда `~`)**
  - Синтаксис: `~int` вместо просто `int`
  - Зачем нужна: разрешение пользовательских типов
  - Пример: `type MyInt int` будет соответствовать `~int`
  - Применение для underlying types
  - Нельзя использовать с интерфейсами: `~io.Reader` запрещено

- **Объединение типов (Type Sets / Union)**
  - Синтаксис вертикальной черты: `int | float64`
  - Создание union constraints: `Integer | Float`
  - Комбинация с тильдой: `~int | ~float64`
  - Сложные constraint выражения
  - Пересечение (intersection) через embedding

- **Определение собственных constraints**
  - Создание переиспользуемых ограничений
  - Комбинирование методов и типов
  - Best practices именования constraints

### 3. **Обобщенные типы данных (Generic Types)**
Дженерики нужны не только функциям, но и структурам.

- **Generic Structs (Обобщенные структуры)**
  - Синтаксис: `type Stack[T any] struct { items []T }`
  - Создание универсальных контейнеров
  - Примеры: стеки, очереди, деревья, связанные списки
  - Методы для generic структур
  - Инстанцирование: `Stack[int]{}`, `Stack[string]{}`

- **Generic Interfaces (Обобщенные интерфейсы)**
  - Интерфейсы с параметрами типа
  - Пример: `type Container[T any] interface { Get() T; Set(T) }`
  - Комбинация с constraint интерфейсами
  - Использование в качестве типов полей

- **Generic Type Aliases**
  - Создание псевдонимов с параметрами типа
  - Использование для упрощения сложных сигнатур

- **Встраивание (Embedding) с дженериками**
  - Embedding generic структур
  - Наследование параметров типа

### 4. **Специфические ключевые слова**

- **`any`**
  - Полный синоним для `interface{}`
  - Введен в Go 1.18 вместе с дженериками
  - Использование для чистоты и читаемости кода
  - `any` vs `interface{}` - нет разницы, только стиль
  - Применение как ограничение по умолчанию

- **`comparable`**
  - Встроенный constraint интерфейс
  - Для типов, которые можно сравнивать через `==` и `!=`
  - Необходим, если тип используется как ключ в `map`
  - Включает: базовые типы, указатели, каналы, массивы comparable типов
  - Исключает: слайсы, мапы, функции
  - Использование: `func FindIndex[T comparable](slice []T, value T) int`

### 5. **Продвинутые концепции**

- **Вложенные параметры типа**
  - `func Process[T []E, E any](items T)`
  - Ограничения между параметрами типа
  - Зависимости типов

- **Type Inference (Вывод типов)**
  - Унификация типов
  - Когда компилятор может вывести типы
  - Когда нужно явное указание
  - Проблемы с циклическими зависимостями

- **Generic Functions возвращающие generic функции**
  - Higher-order функции с дженериками
  - Частичное применение

### 6. **Под капотом и реализация (Implementation)**
Go выбрал компромиссный путь реализации.

- **Monomorphization vs GCShape**
  - **Monomorphization** (как в C++/Rust)
    - Генерация отдельного кода для каждого типа
    - Быстро, но раздувает бинарник
  - **Boxing** (как в Java/C#)
    - Один код, работа через интерфейсы
    - Медленно из-за косвенности
  - **GCShape stenciling** (подход Go)
    - Компромисс: группировка типов по "форме" для GC
    - Типы с одинаковой памятной моделью используют один код
    - Примеры, указатели, интерфейсы имеют одну shape
    - Разные числовые типы - разные shapes
  - Балансировка между скоростью и размером бинарника
  - Оптимизации компилятора

- **Производительность**
  - Сравнение с interface{} + type assertion
  - Сравнение с рефлексией
  - Overhead дженериков (обычно минимален)
  - Zero-cost abstractions в большинстве случаев

### 7. **Ограничения дженериков (Limitations)**
Чего **НЕЛЬЗЯ** делать с дженериками в Go:

- **Нельзя создавать generic методы**
  - ❌ `func (r *Receiver) Method[T any](arg T)` - запрещено
  - ✅ Параметр типа должен быть на уровне структуры
  - Обходные пути через вспомогательные функции

- **Нельзя использовать type parameters в методах**
  - Методы не могут иметь собственные параметры типа
  - Только параметры типа структуры-получателя

- **Нет специализации**
  - Нельзя написать разные реализации для разных типов
  - Нет перегрузки (overloading) по типам

- **Нельзя использовать с константами**
  - Параметры типа только для типов, не для значений
  - Нет compile-time вычислений на основе типов

- **Ограничения с операторами**
  - Нельзя напрямую использовать операторы без constraints
  - Нужно явно указывать constraints для арифметики

- **Нет variadic type parameters**
  - `func F[T... any]()` - запрещено
  - Фиксированное количество параметров типа

### 8. **Практические паттерны и best practices**

- **Когда использовать дженерики**
  - Контейнеры и коллекции (List, Set, Map, Stack, Queue)
  - Функции работы со слайсами (Map, Filter, Reduce)
  - Алгоритмы, не зависящие от типа (Sort, Search, Min, Max)
  - Утилитарные функции (Pointer, Zero, Equal)

- **Когда НЕ использовать дженерики**
  - Если интерфейсы решают задачу проще
  - Если нужно только несколько типов - лучше написать явно
  - Для простых случаев с `interface{}`
  - Когда усложняют читаемость без выгоды

- **Рекомендации по дизайну**
  - Начинать с конкретных типов, обобщать при необходимости
  - Минимизировать количество параметров типа
  - Давать осмысленные имена constraints
  - Документировать ограничения и ожидания

- **Распространенные паттерны**
  - Option/Result типы
  - Tuple типы (Pair, Triple)
  - Generic builders
  - Type-safe wrappers

### 9. **Стандартная библиотека и дженерики**

- **Пакеты с дженериками (Go 1.21+)**
  - `slices` - функции для работы со слайсами
  - `maps` - функции для работы с мапами
  - `cmp` - утилиты сравнения

- **Функции из slices**
  - `slices.Sort[T cmp.Ordered](slice []T)`
  - `slices.BinarySearch[T cmp.Ordered](slice []T, target T)`
  - `slices.Contains[T comparable](slice []T, value T)`
  - `slices.Index`, `slices.Equal`, `slices.Clone`

- **Функции из maps**
  - `maps.Clone[M ~map[K]V, K comparable, V any](m M)`
  - `maps.Equal[M1, M2 ~map[K]V, K, V comparable](m1 M1, m2 M2)`
  - `maps.Keys`, `maps.Values`

### 10. **Миграция на дженерики**

- **Замена interface{} на дженерики**
  - Когда стоит мигрировать
  - Обратная совместимость
  - Type assertions → Type parameters

- **Рефакторинг существующего кода**
  - Постепенный переход
  - Тестирование после миграции
  - Производительность до и после
