# Замыкания (Closures) в Go

Функции в Go — объекты первого класса (см. [03_first_class_functions.md](./03_first_class_functions.md)). На этой основе строятся замыкания.

## 1. Что такое замыкание

Замыкание — это функция, которая ссылается на переменные вне своего тела. Функция «захватывает» эти переменные и удерживает их живыми.

### Как это работает
- **Захват по ссылке**: замыкание хранит ссылку на переменную, а не её копию. Изменение переменной снаружи видно внутри замыкания, и наоборот.
- **Escape Analysis (утечка в кучу)**: если локальная переменная функции захвачена замыканием, компилятор во время escape-анализа определяет, что она переживёт кадр стека, и переносит её со стека в кучу (heap escape), чтобы состояние сохранилось после выхода из функции.

### Пример: аккумулятор
```go
func createAccumulator() (func(int) int, func()) {
    sum := 0 // из-за замыкания эта переменная будет жить в куче

    add := func(x int) int {
        sum += x // изменяем внешнюю переменную
        return sum
    }

    reset := func() {
        sum = 0 // сбрасываем ту же самую переменную
    }

    return add, reset
}
```

Оба возвращаемых замыкания (`add` и `reset`) захватывают одну и ту же переменную `sum`, поэтому работают с общим состоянием.

## 2. Множественное присваивание в замыканиях

В Go удобно обновлять состояние внутри замыканий (например, последовательность Фибоначчи) через атомарное присваивание:

```go
f1, f2 = f2, f1 + f2
```

### Как это работает
1. Сначала вычисляются все значения справа.
2. Затем вычисленные результаты присваиваются переменным слева.
3. Это избавляет от временной переменной (`temp`).

## 3. Жизненный цикл переменных в замыканиях

### Что происходит с памятью
- **Ссылка на функцию**: пока есть ссылка на функцию-замыкание,
- **захваченная переменная** остаётся в памяти — сборщик мусора её не тронет.
- **Функция вышла из области видимости**: если в программе больше нет ссылок на функцию, она становится «недостижимой» (unreachable).

### Сборка мусора
На следующем цикле GC удаляет и саму функцию, и захваченные ею переменные.

**Важно**: ручное обнуление (`fn = nil`) обычно не требуется, кроме случаев с очень большими объёмами данных в долгоживущих процессах.

## 4. Основные правила и частые ошибки

### Shadowing (затенение)
Внутри замыкания используйте `=` вместо `:=`, если хотите изменить внешнюю переменную, а не создать новую локальную.

### Изоляция
Каждый вызов внешней функции (например, `createAccumulator()`) создаёт новое независимое состояние. Два разных счётчика не мешают друг другу.
