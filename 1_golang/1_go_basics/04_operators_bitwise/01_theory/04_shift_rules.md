# Правила сдвигов

## Синтаксис

```go
a << n  // сдвиг влево
a >> n  // сдвиг вправо
```

`a` — целый тип. `n` — беззнаковое целое или нетипизированная константа.

## Что делает

- `<< n` умножает на `2^n` (для целых).
- `>> n` для unsigned — делит на `2^n`, для signed — арифметический сдвиг (сохраняет знак).

```go
var a uint8 = 0b0001_0000
a << 2  // 0b0100_0000
a >> 2  // 0b0000_0100

var b int8 = -8 // 0b1111_1000
b >> 1         // -4 (знак сохранён)
```

## Переполнение

В Go переполнение не panic — старшие биты просто отбрасываются (для unsigned) или дают wrap-around (для signed).

```go
var x uint8 = 0x80
x << 1 // 0 (старший бит ушёл)
```

## Сдвиг на большое значение

Сдвигать на количество бит `≥` размера типа — корректно и даёт 0 (или -1 для арифметического).

```go
var y uint32 = 1
y << 40 // 0
```

## n как выражение

`n` может быть любым integer-выражением, не только константой. С Go 1.13 позволено использовать signed `n` при условии, что оно неотрицательно:

```go
shift := 3
_ = 1 << shift
```

Если `n` отрицательное — рантайм-паника.

> ⚠️ Частый вопрос на собеседовании: до Go 1.13 число сдвигаемых позиций `n` должно было быть беззнаковым целым типом (или нетипизированной константой). Сейчас допускается signed `n`, но отрицательное значение вызывает панику в рантайме, а слишком большая константа даёт ошибку компиляции:
>
> ```go
> var x int32 = 1
> // y := x << 32 // ошибка компиляции: shift count too large
> ```

## Константы

Нетипизированные константы сдвигаются по типу левого операнда:

```go
const mask = 1 << 20 // untyped, берётся int
var u32 uint32 = 1 << 20 // uint32
```

## Типичные use-cases

- Вычисление размеров: `1 << 20 // 1 MiB`.
- Построение масок (`01_theory/03_bitwise_masks.md`).
- Кодирование/декодирование упакованных полей.

Сдвиг — дешёвая операция в CPU, но злоупотреблять ей «ради перформанса» на обычном коде смысла нет: компилятор и так хорошо умеет преобразовывать `* 2` → сдвиг, если выгодно.
