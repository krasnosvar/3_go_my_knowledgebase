# Память и `delete`: почему память не возвращается ОС

Когда вы удаляете элементы из мапы с помощью `delete(m, key)`, Go **не освобождает память**, занятую бакетами. Бакеты просто помечаются как пустые, но остаются аллоцированными. (В Go 1.24+ вместо бакетов — группы и таблицы Swiss tables, см. [02_internals_hmap.md](./02_internals_hmap.md); поведение то же: мапа не сжимается.)

```go
m := make(map[int][1000]int) // Огромная структура
// Добавляем 1 000 000 элементов -> мапа выделила сотни мегабайт бакетов
// Удаляем все элементы:
for i := 0; i < 1_000_000; i++ {
    delete(m, i)
}
// Память процесса осталась на том же уровне! Мапа все еще держит все бакеты.
```

## Как решить: ручная усадка пересозданием

Если мапа выросла до огромных размеров, а затем большинство элементов удалили, единственный способ вернуть память ОС — **пересоздать мапу**:

```go
newMap := make(map[int][1000]int, len(m)) // Создаем мапу нужного размера
for k, v := range m {
    newMap[k] = v
}
m = newMap // Старая мапа с пустыми бакетами отправится в Garbage Collector
```

> ⚠️ Частый вопрос на собеседовании: возвращает ли `delete` память после удаления всех ключей? Ответ — нет, бакеты остаются аллоцированными; для усадки нужно пересоздать мапу.
