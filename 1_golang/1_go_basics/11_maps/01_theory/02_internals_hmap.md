# Внутреннее устройство: структура `hmap`

Под капотом мапа в Go — это указатель на структуру `hmap` из пакета `runtime`:

```
              hmap struct
         +-------------------+
         | count  (int)      |
         | flags  (uint8)    |
         | B      (uint8)    | ---> Количество бакетов = 2^B
         | buckets (pointer) | -+
         +-------------------+  |
                                |
                                v
                       Массив Buckets (bmap)
         +-------------------------------------------------+
         | Bucket 0: [tophash0..7][key0..7][val0..7][next] |
         | Bucket 1: [tophash0..7][key0..7][val0..7][next] |
         | ...                                             |
         +-------------------------------------------------+
```

## Основные элементы

*   **Buckets (Бакеты)**: массив структур `bmap`. Каждый бакет вмещает ровно **8 пар ключ-значение**.
*   **Tophash**: массив из 8 байт (high-order bits of hash value) для быстрого пред-поиска ключей внутри бакета.
*   **Overflow Buckets**: если в бакет пытается записаться 9-й ключ с тем же хэшем, аллоцируется дополнительный связанный бакет (overflow bucket), указатель на который записывается в конец текущего бакета.
*   **Эвакуация (Rehashing)**: когда среднее заполнение бакетов превышает 6.5 элементов (load factor > 6.5), Go аллоцирует новый массив бакетов в 2 раза большего размера и плавно переносит данные (эвакуирует бакеты) при операциях чтения/записи.

## Рандомизация обхода (Map Iteration Order)

Go специально рандомизирует порядок обхода элементов в цикле `for range`.
При каждом запуске итератора Go выбирает случайный бакет и случайное смещение внутри него в качестве стартовой точки.

**Зачем это сделано?**
1. Физический порядок элементов в памяти меняется во время роста мапы и рехэшинга.
2. Чтобы разработчики не закладывались на порядок элементов в мапе (как это часто происходило в языках, где обход детерминирован).

> ⚠️ Частый вопрос на собеседовании: сколько пар ключ-значение вмещает один бакет и что происходит при переполнении? Ответ — 8 пар, далее аллоцируется overflow bucket.
