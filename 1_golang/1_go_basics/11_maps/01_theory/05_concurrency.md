# Конкурентный доступ (Thread Safety)

Обычная мапа в Go **небезопасна для конкурентного доступа**. Одновременная запись и чтение или две записи из разных горутин вызовут невосстановимый крах приложения:

```
fatal error: concurrent map read and map write
```

## Способы защиты

1. **`sync.RWMutex`** (Рекомендуется для 90% случаев): оборачиваем мапу в структуру с мьютексом.
2. **`sync.Map`**: оптимизированное решение из стандартной библиотеки, подходящее только для двух сценариев:
   *   Ключ записывается один раз, а читается многократно (например, кэш конфигураций).
   *   Разные горутины работают с непересекающимися наборами ключей.

## Пример: обёртка с `sync.RWMutex`

```go
type SafeMap struct {
    mu sync.RWMutex
    m  map[string]int
}

func (s *SafeMap) Get(key string) (int, bool) {
    s.mu.RLock()
    defer s.mu.RUnlock()
    v, ok := s.m[key]
    return v, ok
}

func (s *SafeMap) Set(key string, val int) {
    s.mu.Lock()
    defer s.mu.Unlock()
    s.m[key] = val
}
```

> ⚠️ Частый вопрос на собеседовании: что произойдёт при одновременном чтении и записи обычной мапы из разных горутин и когда стоит выбирать `sync.Map` вместо `sync.RWMutex`? Ответ — `fatal error: concurrent map read and map write`; `sync.Map` уместен лишь для «записал один раз — читаю много» или непересекающихся наборов ключей.
