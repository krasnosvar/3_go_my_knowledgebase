# Мапы — шпаргалка

Подробности и объяснения — в [01_theory/](./01_theory/). ⚠️ — частая ловушка.
Версии указаны там, где поведение зависит от них.

## Операции

Подробно: [01_basics_operations.md](./01_theory/01_basics_operations.md).

| Задача | Код |
| :--- | :--- |
| Создать | `m := make(map[string]int)`; с запасом — `make(map[string]int, n)` |
| Литерал | `m := map[string]int{"alice": 20, "bob": 30}` |
| Нулевое значение | `var m map[string]int` → `nil` |
| Записать / прочитать | `m["alice"] = 20`, `age := m["alice"]` |
| Отсутствующий ключ | вернёт нулевое значение типа значения (`0`, `""`, `nil`) |
| Есть ли ключ (comma-ok) | `v, ok := m[key]` |
| Удалить | `delete(m, key)` — для отсутствующего ключа безопасно |
| Размер | `len(m)` |
| Очистить все ключи (Go 1.21+) | `clear(m)` |
| Обход | `for k, v := range m {}` — порядок случайный |
| Тип ключа | любой `comparable`: числа, строки, указатели, каналы, массивы, структуры из сравнимых; не `slice`/`map`/`func` |

| Операция над `nil`-мапой | Результат |
| :--- | :--- |
| `m[k]`, `v, ok := m[k]`, `len(m)`, `range`, `delete` | работают (как пустая мапа) |
| `m[k] = v` | `panic: assignment to entry in nil map` |

## Сложность

| Операция | Сложность |
| :--- | :--- |
| Чтение, запись, `delete`, comma-ok | O(1) в среднем (амортизированно) |
| `len(m)` | O(1) |
| Обход `range`, `maps.Clone` | O(n) |
| Обход в порядке ключей | O(n log n): собрать ключи и отсортировать |

## Устройство: Swiss tables (Go 1.24+) и hmap (до 1.24)

Подробно: [02_internals_hmap.md](./01_theory/02_internals_hmap.md).

| | Go 1.24+ (Swiss tables) | до Go 1.24 (`hmap`/`bmap`) |
| :--- | :--- | :--- |
| Ячейка | группа: 8 слотов + control word (8 байт) | бакет: 8 пар + `tophash[8]` |
| Выбор места | `h1` (старшие 57 бит) → группа; `h2` (7 бит) — в control-байте | младшие `B` бит → бакет (всего `2^B`) |
| Поиск в ячейке | 8 control-байтов сравниваются с `h2` разом | перебор `tophash` |
| Переполнение | следующая группа (квадратичное пробирование) | overflow-бакет в цепочке |
| Рост | таблица при заполнении > 7/8: удвоение до 1024 слотов, дальше split на две; сразу во время вставки | load factor > 6.5 → массив ×2, постепенная эвакуация при записи/удалении |
| Маленькая мапа | ≤ 8 элементов — одна группа без таблиц | — |
| Откат | `GOEXPERIMENT=noswissmap` (только Go 1.24) | — |

Не изменилось: рандомизированный порядок обхода, неадресуемость значений, нет защиты от гонок, `delete` не сжимает мапу.

## Неадресуемость значений

Подробно: [03_unaddressability.md](./01_theory/03_unaddressability.md).

| Код | Результат |
| :--- | :--- |
| `m["alice"].Age = 21` | ошибка компиляции: `cannot assign to struct field ... in map` |
| `&m["alice"]` | ошибка компиляции: `cannot take the address of ...` |
| Решение 1 | `map[string]*User` → `m["alice"].Age = 21` работает |
| Решение 2 | `u := m["alice"]; u.Age = 21; m["alice"] = u` |
| Счётчик | `m[k]++` — можно (это чтение + запись, а не адрес) |

## Память и delete

Подробно: [04_memory_delete.md](./01_theory/04_memory_delete.md).

| Факт | Действие |
| :--- | :--- |
| `delete` и `clear` не уменьшают выделенную память | слоты лишь помечаются пустыми |
| Мапа выросла, потом большинство ключей удалили | пересоздать: `n := make(map[K]V, len(m)); for k, v := range m { n[k] = v }; m = n` |
| Большие значения | хранить указатели или пересоздавать мапу |

## Конкурентный доступ

Подробно: [05_concurrency.md](./01_theory/05_concurrency.md).

| Сценарий | Инструмент |
| :--- | :--- |
| Чтение + запись из разных горутин без защиты | `fatal error: concurrent map read and map write` — не ловится `recover` |
| Общий случай (~90%) | структура с `sync.RWMutex`: `RLock` на чтение, `Lock` на запись |
| Записал один раз — читают много | `sync.Map` |
| Горутины с непересекающимися наборами ключей | `sync.Map` |
| Только чтение после инициализации | защита не нужна |

## Пакет maps и приёмы

Подробно: [06_use_cases.md](./01_theory/06_use_cases.md).

| Задача | Код |
| :--- | :--- |
| Копия / сравнение (1.21+) | `maps.Clone(m)`, `maps.Equal(a, b)` |
| Удалить по условию (1.21+) | `maps.DeleteFunc(m, func(k K, v V) bool { return v > 25 })` |
| Ключи в порядке (1.23+) | `for _, k := range slices.Sorted(maps.Keys(m)) {}` |
| Ключи / значения как итератор (1.23+) | `maps.Keys(m)`, `maps.Values(m)` → `iter.Seq` |
| Множество | `set := map[string]struct{}{}`; `set[k] = struct{}{}`; `_, ok := set[k]` |
| Dispatch | `map[string]func(args []string) error` |
| Подсчёт | `counts[word]++` (ноль по умолчанию) |
| LRU-кэш | `map[K]*list.Element` + `container/list` |

## Ловушки

- ⚠️ Запись в `nil`-мапу (например, поле структуры без `make`) → panic.
- ⚠️ Нельзя отличить «нет ключа» от «значение ноль» без comma-ok.
- ⚠️ Нельзя полагаться на порядок `range` — даже два обхода подряд дают разный порядок.
- ⚠️ Конкурентная запись → `fatal error`, процесс падает целиком; проверять `go test -race`.
- ⚠️ `delete` не возвращает память; долгоживущие мапы-кэши пересоздавать.
- ⚠️ Мапа — ссылочный тип: копия переменной указывает на те же данные; нужна копия — `maps.Clone`.
- ⚠️ Ключ `float64` с `NaN` нельзя найти и удалить через `delete` (`NaN != NaN`); убирает только `clear`.
