# Композиция вместо наследования (Embedding)

В Go нет наследования классов. Вместо этого используется **встраивание полей** (embedding) — механизм композиции.

```go
type User struct {
    ID   int
    Name string
}

type Admin struct {
    User  // встроенное анонимное поле
    Role  string
}
```

## Делегирование полей и методов

Благодаря встраиванию поля и методы структуры `User` «проксируются» (продвигаются) на уровень `Admin`, и к ним можно обращаться напрямую:

```go
a := Admin{Role: "Super"}
a.Name = "Иван" // доступ напрямую, эквивалентно a.User.Name
```

Это же правило действует и для методов: метод, объявленный на `User`, можно вызвать прямо на `Admin`.

## Конфликт имён (Shadowing)

Если у `Admin` и у встроенной `User` есть поле с одинаковым именем `Name`, то обращение `a.Name` вернёт поле самой структуры `Admin` (внешний уровень затеняет вложенный). Чтобы обратиться к полю встроенной структуры, нужно указать полный путь:

```go
a.User.Name
```

> ⚠️ Частый вопрос на собеседовании: чем embedding отличается от наследования? Встраивание — это композиция: внешний тип содержит вложенный и получает доступ к его полям/методам за счёт продвижения имён, но при этом остаётся отдельным типом и не образует иерархии классов.
