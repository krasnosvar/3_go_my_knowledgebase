# Выравнивание структур в памяти (Struct Alignment)

Процессор считывает память не побайтово, а машинными словами (word) — блоками по 4 байта (на 32-битных системах) или 8 байт (на 64-битных системах). Чтобы читать данные эффективно, Go выравнивает поля структур в памяти. Это может приводить к неожиданным размерам структур.

## Пример 1. Неоптимальная структура (bad alignment)

```go
type BadStruct struct {
    a bool  // 1 байт
    b int64 // 8 байт
    c bool  // 1 байт
}
```

Хотя сумма байтов равна 10, `unsafe.Sizeof(BadStruct{})` вернёт **24 байта**.

Схема памяти (24 байта):

```text
| a (1B) | padding (7B)                 |  <- выравнивание до границы 8 байт
| b (8B)                                |  <- целое 8-байтовое слово
| c (1B) | padding (7B)                 |  <- выравнивание до границы 8 байт
```

## Пример 2. Оптимальная структура (good alignment)

Сгруппируем поля по убыванию их размера:

```go
type GoodStruct struct {
    b int64 // 8 байт
    a bool  // 1 байт
    c bool  // 1 байт
}
```

Размер структуры уменьшился до **16 байт**.

Схема памяти (16 байт):

```text
| b (8B)                                |  <- целое 8-байтовое слово
| a (1B) | c (1B) | padding (6B)        |  <- два bool лежат в одном слове!
```

## Правило порядка полей

Располагайте поля в структуре по убыванию их размера (сначала `int64`, указатели, затем `int32`, `string`, в конце `bool` и `byte`). Это позволяет экономить память при создании миллионов структур.

> ⚠️ Частый вопрос на собеседовании: почему структура из трёх маленьких полей может занимать 24 байта? Из-за padding — компилятор добавляет пустые байты, чтобы каждое поле начиналось на границе, кратной его размеру, а весь размер структуры был кратен размеру самого крупного поля.
