# Подслайсы: общий backing array и ловушки

## Совместное использование backing array

Когда вы создаёте новый слайс путём нарезки другого слайса (`s2 := s1[1:3]`), они делят **один и тот же backing array**.

```go
s1 := []int{10, 20, 30, 40}
s2 := s1[1:3] // s2 указывает на [20, 30], len=2, cap=3
s2[0] = 99    // Изменение s2 изменит и s1! Теперь s1[1] == 99
```

```
s1: [ 10 | 20 | 30 | 40 ]
          ^         ^
          |         |
s2:      [ 20 | 30 ]        (общая память с s1)
```

## Ловушка: append в подслайс перезаписывает соседа

Поскольку у подслайса ёмкость тянется до конца исходного backing array, `append` в подслайс (пока `len < cap`) молча перезаписывает элементы, которые «принадлежат» исходному слайсу.

```go
s1 := []int{10, 20, 30, 40}
s2 := s1[1:3]        // len=2, cap=3
s2 = append(s2, 99)  // len<cap: запись в существующий массив
// Теперь s1 == [10, 20, 30, 99] — четвёртый элемент затёрт!
```

> ⚠️ Частый вопрос на собеседовании: что произойдёт с исходным слайсом при `append` в подслайс? Пока хватает ёмкости — исходные данные за границей `len` подслайса будут перезаписаны, так как backing array общий.

Чтобы `append` в подслайс не влиял на исходный слайс, нужно либо предварительно скопировать данные через `copy`, либо ограничить ёмкость подслайса (см. three-index slice в главе об удержании памяти).
