# Утечки памяти при слайсинге и их предотвращение

Так как слайс удерживает **весь** backing array в памяти, нарезка огромного массива может привести к утечке памяти: маленький слайс не даёт сборщику мусора освободить большой массив.

## Проблема

```go
var hugeData []byte // Слайс на 100 Мегабайт

func getSmallClip() []byte {
    hugeData = readHugeFile()
    return hugeData[:2] // Возвращаем всего 2 байта
}
```

Что произошло: возвращённый слайс размером 2 байта ссылается на исходный массив размером 100 МБ. Сборщик мусора (GC) **не сможет очистить эти 100 МБ**, пока жив маленький слайс, ведь его указатель по-прежнему адресует тот большой массив.

```
returned slice (len=2)
     |
     v
[ b0 | b1 | ...................... 100 MB ...................... ]
                     удерживается в памяти целиком
```

## Решение: copy в новый массив

Используйте копирование данных через встроенную функцию `copy()`, чтобы отвязать данные от большого backing array:

```go
func getSmallClip() []byte {
    hugeData = readHugeFile()
    clip := make([]byte, 2)
    copy(clip, hugeData[:2]) // Копируем данные в новый независимый массив
    return clip              // hugeData теперь может быть собран сборщиком мусора!
}
```

> ⚠️ Частый вопрос на собеседовании: почему возврат маленького подслайса от большого массива — это утечка памяти, и как её избежать? Потому что слайс удерживает весь backing array; лечится копированием нужной части в новый слайс через `copy`.
