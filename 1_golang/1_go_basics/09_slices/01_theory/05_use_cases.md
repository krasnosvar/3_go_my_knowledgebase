# Практические сценарии

Теория слайсов напрямую применяется в примерах (`02_examples/`) и упражнениях (`03_exercises/`) этой главы.

## Защита данных при нарезке аргументов

Изменение элементов нарезанного слайса видно в исходном слайсе, так как backing array общий. Если функция нарезает внешние данные (например, аргументы командной строки) и меняет их, это даёт побочный эффект. Защита — копирование через `copy()` в независимый слайс перед изменением.

*(см. `02_examples/01_cli_utilities`)*

## Удержание большого массива и замер памяти

Возврат маленького подслайса от большого backing array удерживает весь массив в памяти. Разницу использования памяти до и после сборки мусора можно наблюдать в симуляции утечки; лечится копированием нужной части.

*(см. `02_examples/02_system_infrastructure`, упражнение `07_memory_retention`)*

## Фильтрация in-place

Приём `nums[:0]` переиспользует существующий backing array: новый слайс имеет нулевую длину, но ту же ёмкость, поэтому фильтрация выполняется без выделения новой памяти.

*(см. упражнение `06_in_place_ops`)*

## Удаление элемента с сохранением порядка

Удаление элемента по индексу без нарушения порядка выполняется сдвигом «хвоста» через `copy()`:

```go
copy(s[i:], s[i+1:])
s = s[:len(s)-1]
```

*(см. упражнение `03_copy_delete`)*

## Конкурентная безопасность

Slice Header и его backing array не защищены от состояния гонки. Конкурентное накопление в общий слайс требует синхронизации, например через `sync.Mutex`.

*(см. упражнение `08_concurrency_safety`)*
