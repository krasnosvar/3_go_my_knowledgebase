# Wrapping: %w, errors.Is, errors.As

С Go 1.13 у ошибок появилась явная цепочка через обёртки. Это решает две задачи: «добавить контекст» и «сохранить оригинальную ошибку для проверки».

## Оборачивание через %w

```go
if err := repo.Save(u); err != nil {
    return fmt.Errorf("save user %d: %w", u.ID, err)
}
```

- `%w` сохраняет исходный `err` в цепочке.
- Одна обёртка на уровень — больше обычно мешает читать.
- Текст — техничный контекст, без эмоций: какой слой, какая операция, какой ID.

⚠️ Частый вопрос на собеседовании: в чём разница между `errors.Is` и `errors.As`. Кратко: `Is` сравнивает с конкретным значением-ошибкой (sentinel), `As` ищет в цепочке значение нужного типа и присваивает его. Обе идут по цепочке `Unwrap()`, поэтому работают даже с обёрнутыми ошибками.

## errors.Is — проверка по цепочке

`errors.Is(err, target)` идёт по цепочке `Unwrap()` и сравнивает с `target`.

```go
if errors.Is(err, sql.ErrNoRows) {
    return nil, ErrNotFound
}
```

Это правильный способ проверять sentinel-ошибки, а не `err == sql.ErrNoRows`: последнее сломается при оборачивании.

## errors.As — извлечение типа

`errors.As(err, &target)` ищет в цепочке значение конкретного типа и присваивает его `target`.

```go
var pgErr *pgconn.PgError
if errors.As(err, &pgErr) {
    if pgErr.Code == "23505" { // unique_violation
        return ErrDuplicate
    }
}
```

## Multi-error

Go 1.20 добавил `errors.Join(err1, err2)` — объединение нескольких ошибок в одну. Полезно при параллельных операциях.

## Правила

- Оборачивай только при смене контекста (новый слой, новый смысл).
- Не логируй и не возвращай одну и ту же ошибку дважды — или лог, или возврат.
- Пользовательский текст формируй на границе (handler), а не внутри каждой функции.
