# Сложные и абстрактные типы данных (Non-Basic Data Types)

В этом разделе рассматриваются структуры данных, которые выходят за рамки базовых примитивов Go. Они делятся на встроенные составные типы и абстрактные структуры данных (ADT).

---

## 🏗️ Классификация

### 1. Встроенные составные типы (Composite Types)
Эти типы встроены в язык «из коробки» и используются повсеместно:
- **`slice`** — динамические массивы.
- **`map`** — хеш-таблицы (ключ-значение).
- **`struct`** — структуры для объединения разнородных данных.

### 2. Сложные структуры данных (ADT)
Это логические способы организации данных, которые реализуются на базе встроенных типов или стандартных пакетов:

| Структура | Описание | Реализация в Go |
| :--- | :--- | :--- |
| **Связанный список** | Узлы, связанные указателями | [`container/list`](./container_list/) |
| **Stack (Стек)** | LIFO (Last In, First Out) | Срез (`[]T`) или `list` |
| **Queue (Очередь)** | FIFO (First In, First Out) | Срез (`[]T`) или `list` |
| **Heap (Куча)** | Приоритетная очередь | `container/heap` |
| **Set (Множество)** | Уникальные элементы | `map[T]struct{}` |
| **Tree / Graph** | Иерархические/связные данные | Вручную (структуры + указатели) |
| **Sync.Map** | Потокобезопасная мапа | `sync.Map` |

## 🧐 Как их различать?

1. **Базовые типы** (`int`, `string`, `bool`) — это «атомы» языка.
2. **Составные типы** (`slice`, `map`, `struct`) — «молекулы», встроенные в синтаксис для удобства.
3. **Абстрактные типы (ADT)** — это архитектурные решения. Мы сами решаем, как данные будут взаимодействовать (например, через интерфейсы или методы), используя примитивы и составные типы как строительный материал.

> **Важно:** В Go часто предпочитают простоту. Если задачу можно эффективно решить через `slice` или `map`, стоит использовать их, прежде чем внедрять сложные структуры вроде деревьев или списков.
