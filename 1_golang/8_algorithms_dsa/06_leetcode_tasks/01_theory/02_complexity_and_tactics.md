# Complexity и практическая тактика

## Таблица сложностей

| Сложность | n=1k | n=10k | n=100k | n=1M |
|---|---|---|---|---|
| O(1) | мгновенно |
| O(log n) | мгновенно |
| O(n) | мс | мс | 10–100 мс | сек |
| O(n log n) | мс | 10 мс | 100 мс | сек |
| O(n²) | 1 мс | 100 мс | 10 сек | TLE |
| O(2^n) | TLE | TLE | TLE | TLE |
| O(n!) | TLE | TLE | TLE | TLE |

LeetCode обычно даёт лимит ~1-2 сек. Это означает:

- 10⁶–10⁷ операций в секунду — комфортно.
- 10⁸ — на грани.
- 10⁹ — почти всегда TLE.

Если n = 10⁵, тебе нужен максимум O(n log n).

## Тактики оценки до кода

1. Перепиши задачу: «дано N=10⁶ элементов, найти X».
2. Какая допустимая сложность? `n log n` максимум.
3. Какие паттерны дают нужную сложность? (sort + two pointers, binary search, hash map).
4. Выбери паттерн, кодь.

## Признаки сложности по словам задачи

- «Find the minimum/maximum» → DP / greedy / binary search.
- «Number of ways» → DP.
- «Substring / subarray» → sliding window / two pointers.
- «Connected / paths in grid» → BFS/DFS/Union-find.
- «Top K» → heap.
- «Sorted» → binary search или two pointers.

## Практика на собеседованиях

### Поток

1. **Уточнить вход**: типы, диапазоны, edge cases (пустой массив, отрицательные, дубликаты).
2. **Привести пример** руками. Часто помогает увидеть паттерн.
3. **Озвучить brute-force**, потом улучшение. Не молчи.
4. **Закодить чистое решение**. Edge cases отдельно.
5. **Протестировать** на 2-3 примерах.
6. **Оценить сложность**.

### Что ценится

- Чистый, читаемый код.
- Правильно названные переменные (`l/r`, `a/b` ок для two pointers; `customerData` — нет в алгоритме).
- Обработка edge cases (пустой вход, n=1, дубликаты).
- Корректное знание сложности.

### Что НЕ ценится

- «Я видел эту задачу» без понимания.
- Списать с памяти, не объясняя.
- Игнорировать ошибки в коде.

## Подготовка

### Правильно

- 50–100 задач, разобранных глубоко (паттерн, edge cases, альтернативы).
- Каждую задачу — реализовать самостоятельно, потом сверить.
- Делать **review**: через неделю вернуться и переделать без подсматривания.

### Неправильно

- 500 задач, забытых через неделю.
- Списывать решение, выдавая за своё.
- Решать только easy без построения интуиции.

## Языковые особенности Go на LeetCode

- Нет встроенного set / heap with API — пиши через map / container/heap.
- `slices.Sort` (1.21+) или `sort.Slice` для сортировок.
- Знай `math.MaxInt`, `math.MinInt` для инициализации min/max.
- Для строк — помни, что `s[i]` — байт, а не rune. Для unicode — `[]rune(s)`.

## Правило

- Сначала анализ, потом код.
- Сначала корректность, потом оптимизация.
- Каждое решение — с явной оценкой O().
