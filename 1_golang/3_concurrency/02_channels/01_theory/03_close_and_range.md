# Close и range

## Закрытие канала

```go
close(ch)
```

- Отправка в закрытый канал — **panic**.
- Приём — возвращает zero-value и `ok=false`.
- Двойное закрытие — тоже **panic**.

Правило: **закрывает только владелец-отправитель**. Если писателей несколько, нужен отдельный синхронизатор (WaitGroup + одна горутина-закрыватель).

## Когда закрывать

Закрытие — это **сигнал «больше не будет данных»**, не «освобождение ресурса».

Закрывай, если:

- есть consumer с `for v := range ch`;
- хочешь транслировать «готово» сразу всем читателям (см. идиома `close(done)`).

Не закрывай, если:

- поток значений бесконечный;
- консьюмер сам знает, когда остановиться;
- не уверен, что никто больше не пишет — лучше не закрывать вовсе.

## range по каналу

```go
for v := range ch {
    use(v)
}
```

Цикл читает до тех пор, пока канал не закрыт и не пуст. Это самый чистый способ консьюмера.

## ok-идиома

```go
v, ok := <-ch
if !ok {
    // канал закрыт, больше ничего не придёт
    return
}
```

Полезно, когда `range` не подходит (например, есть select на несколько каналов).

## close как broadcast

```go
done := make(chan struct{})

// множество горутин
go func() {
    <-done // все проснутся одновременно
    cleanup()
}()

close(done)
```

Закрытие — один из немногих «multicast» механизмов в Go: все читатели мгновенно получают zero-value и идут дальше.

## Частые ошибки

- Закрывать канал из потребителя: легко приводит к panic в писателе.
- Несколько писателей закрывают один канал: легко двойное закрытие.
- Проверять «закрыт ли канал» без приёма — стандартного способа нет, только через `v, ok := <-ch`.
- `close` на nil-канале — panic.

## Альтернатива: ctx.Done()

Часто вместо собственного `done`-канала удобнее использовать `context.Context` — он даёт те же семантики «broadcast когда пора заканчивать», плюс таймауты и цепочку.
