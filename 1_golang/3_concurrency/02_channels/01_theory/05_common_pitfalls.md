# Частые ошибки с channels

## 1. Отправка в закрытый канал

```go
close(ch)
ch <- 1 // panic: send on closed channel
```

Гарантируй, что канал закрывает только один owner, и только после того, как все writes завершены.

## 2. Закрытие чужого канала

Закрывать канал — только у того, кто его создаёт и отправляет в него. Закрытие «из-под» потребителя — частая ошибка.

## 3. Забыть закрыть при использовании range

```go
ch := make(chan int)
go producer(ch) // без close
for v := range ch {
    use(v)
}
```

`range` не закончится — consumer висит. Всегда закрывай в producer'е (обычно через `defer close(ch)`).

## 4. Отправка без получателя

```go
ch := make(chan int)
ch <- 1 // блок навсегда, если никто не читает
```

Тот же баг в goroutine даёт leak:

```go
go func() { ch <- compute() }() // висит, если ch некому прочитать
```

Решение — буферизованный канал, `context`, `select` с таймаутом.

## 5. Деадлок в main

```go
func main() {
    ch := make(chan int)
    ch <- 1 // deadlock: в main нет другой горутины для чтения
}
```

Запусти producer в go-горутину, либо используй buffered-канал.

## 6. Гонка за закрытие

Если несколько горутин могут закрывать один канал — гонка и двойное закрытие. Решение: `sync.Once`:

```go
var once sync.Once
closeOnce := func() { once.Do(func() { close(ch) }) }
```

## 7. nil-канал

```go
var ch chan int
ch <- 1 // блок навсегда
<-ch    // блок навсегда
```

Используется намеренно в `select`, чтобы «отключить» ветку. В обычном коде — скорее всего, забытая инициализация.

## 8. Неправильный выбор буфера

- Слишком маленький → постоянные блокировки.
- Слишком большой → маскирует проблемы backpressure и съедает память.

Размер — осмысленный, из измерений нагрузки.

## 9. `select` + default когда его не ожидают

```go
select {
case ch <- v:
default: // теряем значение
}
```

Это «non-blocking send» — намеренный паттерн, но применять осторожно: легко молча терять данные.

## 10. Ожидание в несчастливый момент

Отправка с default — теряет значение. Отправка без default — блок. Подумай заранее, какой семантики ты хочешь.
