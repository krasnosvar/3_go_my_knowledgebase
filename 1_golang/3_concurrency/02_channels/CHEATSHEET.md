# Каналы — шпаргалка

Подробности и объяснения — в [01_theory/](./01_theory/). ⚠️ — частая ловушка.

## Синтаксис

Подробно: [01_basics.md](./01_theory/01_basics.md).

| Задача | Код |
| :--- | :--- |
| Небуферизованный канал | `ch := make(chan int)` |
| Буферизованный, ёмкость 10 | `ch := make(chan int, 10)` |
| Нулевое значение | `var ch chan int` → `nil` |
| Отправить / принять | `ch <- 42` / `v := <-ch` |
| Принять с признаком закрытия | `v, ok := <-ch` (`ok == false` — закрыт и пуст) |
| Закрыть | `close(ch)` — только отправитель |
| Читать до закрытия | `for v := range ch { ... }` |
| Сколько в буфере / ёмкость | `len(ch)` / `cap(ch)` (`len` устаревает сразу после вызова) |
| Сигнальный канал без данных | `chan struct{}` (`struct{}` — 0 байт) |

## Поведение по состоянию канала

Подробно: [03_close_and_range.md](./01_theory/03_close_and_range.md), [05_common_pitfalls.md](./01_theory/05_common_pitfalls.md).

| Операция | `nil`-канал | Открытый | Закрытый |
| :--- | :--- | :--- | :--- |
| Отправка `ch <- v` | блок навсегда | блок, пока нет получателя (unbuffered) / пока буфер полон | **panic**: send on closed channel |
| Приём `<-ch` | блок навсегда | блок, пока нет значения | остаток буфера, затем `zero, false` сразу |
| `close(ch)` | **panic**: close of nil channel | ок, все читатели просыпаются | **panic**: close of closed channel |
| В `select` | ветка никогда не готова (способ «отключить» ветку) | обычная ветка | приём всегда готов |
| `for range ch` | блок навсегда | читает значения | дочитывает буфер и выходит |

## Буфер: когда какой

Подробно: [02_buffered.md](./01_theory/02_buffered.md).

| Буфер | Когда |
| :--- | :--- |
| `0` (unbuffered) | точка встречи (handshake), передача владения, по умолчанию «если не знаешь зачем буфер» |
| `1` | результат, который может быть никому не нужен (читатель ушёл по таймауту) — горутина не утечёт |
| `N` (известный) | semaphore на N слотов; результаты `len(jobs)` горутин; сглаживание всплесков |
| «большой на всякий случай» | ⚠️ не решает backpressure, а только откладывает и прячет проблему |

## Направленные каналы

Подробно: [04_directional.md](./01_theory/04_directional.md).

| Тип | Можно |
| :--- | :--- |
| `chan T` | отправлять и принимать |
| `chan<- T` | только отправлять (и закрывать) |
| `<-chan T` | только принимать |
| `chan T` → `chan<- T` / `<-chan T` | неявное приведение — да |
| `chan<- T` → `chan T` | нет, ошибка компиляции |
| Конструктор/стадия pipeline | возвращать `<-chan T`, скрывая сторону записи |

```go
package main

import "fmt"

func producer(out chan<- int) { // только отправка
	defer close(out) // закрывает отправитель
	for i := range 3 {
		out <- i
	}
}

func main() {
	ch := make(chan int, 2)
	go producer(ch)
	for v := range ch { // выход, когда закрыт и пуст
		fmt.Print(v, " ")
	}
	v, ok := <-ch
	fmt.Println("|", v, ok) // 0 1 2 | 0 false

	b := make(chan string, 3)
	b <- "a"
	b <- "b"
	close(b)
	fmt.Println(len(b), cap(b)) // 2 3
	x, ok1 := <-b
	y, ok2 := <-b
	z, ok3 := <-b
	fmt.Printf("%q %v %q %v %q %v\n", x, ok1, y, ok2, z, ok3) // "a" true "b" true "" false
}
```

`range` по `int` (`for i := range 3`) — Go 1.22+.

## Закрытие: правила

Подробно: [03_close_and_range.md](./01_theory/03_close_and_range.md).

| Правило | Детали |
| :--- | :--- |
| Кто закрывает | единственный отправитель-владелец (`defer close(out)` в producer) |
| Несколько отправителей | `WaitGroup` + отдельная горутина: `go func() { wg.Wait(); close(out) }()` |
| Защита от двойного закрытия | `once.Do(func() { close(ch) })` |
| Смысл закрытия | сигнал «данных больше не будет», а не освобождение ресурса |
| Не закрывать | бесконечный поток; не уверен, что все писатели закончили |
| Broadcast всем ждущим | `close(done)` — все `<-done` просыпаются одновременно; часто удобнее `ctx.Done()` |
| Проверить «закрыт ли» | только приёмом `v, ok := <-ch`; отдельной функции нет |

## Канал или mutex

Подробно: [01_basics.md](./01_theory/01_basics.md), [06_use_cases.md](./01_theory/06_use_cases.md).

| Задача | Выбор |
| :--- | :--- |
| Защитить общее состояние (map, счётчик, структура) | `sync.Mutex` |
| Атомарный счётчик / флаг | `sync/atomic` |
| Передать значения / владение объектом | канал |
| Сигнал «готово» / «стоп» многим | `close(done)` или `ctx.Done()` |
| Producer → consumer, worker pool, pipeline, fan-out/fan-in | каналы (см. [07_patterns](../07_patterns/CHEATSHEET.md)) |
| Ограничить параллелизм | buffered-канал как semaphore |
| Межсервисная очередь, долговечные события | не go-каналы, а Kafka/NATS |

## Ловушки

- ⚠️ `ch <- 1` в `main` без читателя → `fatal error: all goroutines are asleep - deadlock!`.
- ⚠️ То же внутри горутины — не паника, а тихая утечка.
- ⚠️ Producer забыл `close` → `for range` у consumer висит вечно.
- ⚠️ Закрытие из потребителя → panic у писателя при следующей отправке.
- ⚠️ Несколько писателей закрывают один канал → двойное закрытие, panic.
- ⚠️ `var ch chan int` без `make` → любые операции блокируются навсегда.
- ⚠️ `select { case ch <- v: default: }` молча теряет значение — только для метрик/логов.
- ⚠️ Размер буфера — из измерений: слишком маленький → постоянные блокировки, слишком большой → память и спрятанный backpressure.
