# sync.Cond и sync.Pool

## sync.Cond

Условная переменная. Позволяет горутинам ждать, пока выполнится какое-то условие, и будить их.

```go
var (
    mu   sync.Mutex
    cond = sync.NewCond(&mu)
    done bool
)

go func() {
    mu.Lock()
    for !done {
        cond.Wait() // освобождает mu, ждёт сигнала
    }
    mu.Unlock()
}()

// в другой горутине
mu.Lock()
done = true
cond.Broadcast() // будим всех
mu.Unlock()
```

Методы:

- `Wait()` — освободить mutex и заблокироваться. При `Signal`/`Broadcast` снова захватит mutex.
- `Signal()` — разбудить одну ожидающую.
- `Broadcast()` — разбудить всех.

## Когда использовать

На практике в бизнес-коде почти никогда. Обычно те же задачи решают каналы и context.

`sync.Cond` полезен в:

- имплементации собственных примитивов;
- structures-heavy scenarios с hard-ожиданиями (например, bounded queue своими руками).

## Ловушки

- Всегда ждать в цикле `for !cond`, не в `if`. Spurious wakeup возможен.
- Держать mutex при `Wait()` обязательно — без него `fatal error: sync: unlock of unlocked mutex` (не паника: `recover` не перехватит, процесс завершится).
- Broadcast разбудит всех, все полезут за mutex — может быть storm.

## sync.Pool

Pool — пул объектов, которые можно переиспользовать вместо повторной аллокации.

```go
var bufPool = sync.Pool{
    New: func() any { return new(bytes.Buffer) },
}

b := bufPool.Get().(*bytes.Buffer)
defer bufPool.Put(b)

b.Reset()
// используем b
```

### Семантика

- Элементы пула могут быть вытеснены в любой момент GC.
- Пул — не «хранилище», а «быстрая аллокация».
- На пул нельзя рассчитывать как на стабильное хранилище состояния.

### Когда использовать

- Временные буферы в hot path (`bytes.Buffer`, `[]byte`).
- Короткоживущие вспомогательные структуры под каждым запросом.

### Когда НЕ использовать

- Долгоживущие объекты, разделяемые многими.
- Объекты, хранящие важный state между Get/Put.
- Простые случаи: сначала профиль, потом pool.

### Правила

- Перед Put — сбрасывать состояние (`b.Reset()`).
- Проверяй: pool помогает только если аллокаций действительно много.
- Не используй pool с объектами, содержащими большие ссылки: память может быстро расти.
