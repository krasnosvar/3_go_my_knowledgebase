# sync.Once

`sync.Once` гарантирует, что переданная функция выполнится **ровно один раз**, даже при параллельных вызовах.

## API

```go
var once sync.Once

once.Do(func() {
    // выполнится один раз
})
```

- Метод `Do` принимает функцию без аргументов.
- Повторные вызовы `Do` не вызывают функцию.
- Горутины, вызывающие `Do` одновременно, ждут завершения первой.

## Типовой use-case: ленивая инициализация

```go
var (
    cfgOnce sync.Once
    cfg     *Config
)

func GetConfig() *Config {
    cfgOnce.Do(func() {
        cfg = loadConfig()
    })
    return cfg
}
```

Гарантирует, что `loadConfig` выполнится один раз, и все параллельные вызовы увидят готовый `cfg`.

## Правила

- Нельзя «сбросить» Once. Если нужна повторная инициализация — заведи новый.
- Функция внутри Do должна быть потокобезопасной сама по себе.
- Если `f()` паникует, Go считает Once выполненным. Повторно `f()` не вызовет.
- Нельзя копировать `sync.Once` — держи его в одном месте (обычно поле структуры).

## sync.OnceFunc / OnceValue / OnceValues (Go 1.21)

```go
init := sync.OnceFunc(func() { /* ... */ })
init() // первый раз — вызывает
init() // второй раз — no-op

getCfg := sync.OnceValue(loadConfig)
cfg := getCfg()
```

Короче и типобезопаснее, чем вручную оборачивать `Once.Do`.

## Альтернативы

- `init()` функции пакета — если инициализация при старте всегда нужна и не зависит от рантайм-конфига.
- `lazy-pointer` через `atomic.Pointer` + CAS — для очень горячих путей.
- Simple mutex + bool flag — когда нужна более сложная проверка «выполнено или нет».

## Когда НЕ надо

- Если инициализация синхронная и дешёвая — делай явно в конструкторе.
- Если нужна переинициализация — `Once` не подходит.
- Если один раз выполнить надо, но с разным параметром — сделай мапу `map[K]*sync.Once` или `singleflight.Group`.
