# Compare-And-Swap (CAS)

CAS — операция «сравни ожидаемое значение и замени, если совпало». Базис многих lock-free алгоритмов.

## API

```go
var n atomic.Int64

ok := n.CompareAndSwap(expected, newValue)
```

- Если текущее `n == expected` — атомарно меняет на `newValue`, возвращает `true`.
- Иначе — ничего не меняет, возвращает `false`.

## Типичный паттерн: CAS-loop

Когда нужно обновление, зависящее от текущего значения:

```go
for {
    old := counter.Load()
    next := compute(old)
    if counter.CompareAndSwap(old, next) {
        break
    }
}
```

Смысл: «пробуем заменить; если кто-то успел раньше — повторяем».

## Где полезен

- Обновление по условию: «увеличь, если меньше лимита».
- «Ленивая инициализация» без mutex.
- Implementation lock-free структур: очереди, стеки, счётчики.

## Стоимость

CAS дороже обычного `Add`, но дешевле mutex. В hot path с низким contention это «бесплатно». При высоком contention CAS-loop может крутиться — иногда mutex окажется быстрее.

## С указателями

`atomic.Pointer[T]` даёт CAS над указателем:

```go
var cfg atomic.Pointer[Config]

oldCfg := cfg.Load()
newCfg := updateCopy(oldCfg)
cfg.CompareAndSwap(oldCfg, newCfg)
```

Это основа copy-on-write: читатели всегда видят согласованный snapshot.

## Ошибки

### ABA-проблема

Классика lock-free: значение сменилось с A на B и обратно на A. CAS не видит изменения. В Go это редко критично (нет явных free/reuse), но в алгоритмах с переиспользованием объектов стоит помнить.

### «Одно CAS — одна операция»

CAS атомарен только для одного слова. Нельзя атомарно сменить «два поля». Решается: обернуть в struct и менять указатель `atomic.Pointer`.

### Вечный CAS-loop

Если логика «вычислить новое значение» дорогая, а contention высокий — можно крутить CAS бесконечно. Bounded retry + fallback на mutex спасает.

## Практический совет

- Для простого `Inc` — `Add`, не CAS.
- CAS нужен, когда новое значение зависит от старого нетривиально.
- Без профайла не начинай делать «lock-free ради перформанса» — mutex часто быстрее на реальных нагрузках.
