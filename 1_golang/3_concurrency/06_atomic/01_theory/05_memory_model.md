# Go memory model кратко

Go Memory Model (GMM) описывает, какие гарантии ты имеешь при одновременном доступе к переменной из разных горутин. Полный текст — в [официальной документации](https://go.dev/ref/mem), здесь практическая выжимка.

## Ключевая идея

Без явной синхронизации **нет** гарантий, что одна горутина увидит запись, сделанную другой. Компилятор и CPU свободно переупорядочивают операции внутри одной горутины, если это не меняет её наблюдаемого поведения.

## «Happens before»

Отношение `happens before` (HB) — основа: если событие A HB B, то эффекты A видны в B.

HB устанавливают:

- запуск горутины (`go f()` HB перед первой инструкцией f);
- завершение функции HB возврат из неё в вызывающей горутине;
- отправка в канал HB соответствующий приём;
- закрытие канала HB любой приём после закрытия;
- `sync.Mutex.Unlock()` HB следующий `Lock()` того же mutex;
- `atomic.StoreX(v)` HB любой `atomic.LoadX` того же адреса, увидевший это значение.

Без какого-либо HB между операциями — **нет гарантий порядка и видимости**.

## Что это значит на практике

- Если одна горутина читает значение, а другая пишет — нужен либо mutex, либо atomic, либо канал. Обычный `=` — гонка.
- Гарантия «atomic.Store сделано» не включает автоматическую видимость других переменных, если они не синхронизированы отдельно. Но в Go 1.19+ atomic operations имеют sequential consistency по отношению к другим atomic'ам.

## Race detector — твой друг

```
go test -race ./...
go run -race
```

Инструмент находит ситуации, когда две горутины трогают одну переменную без синхронизации. Включай в CI, игнорировать репорты нельзя.

## Типовые ошибки видимости

### 1. Флаг «работа окончена»

```go
var done bool
go func() {
    done = true
}()
for !done {
    // может крутиться бесконечно — видимость не гарантирована
}
```

Исправить: `atomic.Bool`, канал или mutex.

### 2. Ленивая инициализация без sync

```go
var client *Client
if client == nil {
    client = New()
}
```

Опасно в многопоточном коде. Используй `sync.Once` или `atomic.Pointer`.

## Правило для практики

Если одна горутина пишет, другая читает — нужен один из:

- `sync.Mutex` / `sync.RWMutex`;
- `atomic` операция;
- канал;
- `sync.Once` / `sync.WaitGroup` — по ситуации.

Без этого — гонка, даже если кажется, что работает.
