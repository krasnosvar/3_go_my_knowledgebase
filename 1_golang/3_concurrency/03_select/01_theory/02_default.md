# default в select

Ветка `default` делает `select` **non-blocking**: если ни одна из основных веток не готова — выполняется `default`.

## Non-blocking receive

```go
select {
case v := <-ch:
    use(v)
default:
    // канал пуст — не ждём
}
```

Читаем, только если значение прямо сейчас есть.

## Non-blocking send

```go
select {
case ch <- v:
    // отправили
default:
    // канал полон — не ждём, теряем значение
}
```

Типичный паттерн для метрик/логов, где «пусть лучше потеряется, чем заблочит».

## Опасности

- Потеря данных. Non-blocking send молча выкидывает значение — это нужно **сознательно**.
- «Busy loop». Если `select + default` стоит в цикле без пауз, он крутится и жрёт CPU:

```go
for {
    select {
    case v := <-ch:
        use(v)
    default:
        // нет ожидания — постоянный busy loop
    }
}
```

Добавь `time.Sleep` или замени на blocking select.

## Когда default уместен

- Проверка «есть ли что-то в канале», не блокируя.
- Лёгкая защита от ошибочной блокировки в коде-клей.
- Счётчики/метрики, где потеря допустима.

## Когда default НЕ уместен

- Основная логика обработки данных — ты рискуешь тихо пропустить сообщение.
- Вместо timeout'а — используй `time.After` или `context`, а не `default + sleep`.

## Пример: периодический опрос с отменой

```go
ticker := time.NewTicker(time.Second)
defer ticker.Stop()

for {
    select {
    case <-ctx.Done():
        return
    case <-ticker.C:
        poll()
    }
}
```

Здесь `default` не нужен, ticker даёт естественную паузу.

## Правило

Если чувствуешь желание добавить `default`, спроси себя: «что произойдёт, если ничего не готово?» Если ответ — «я молча теряю данные» — подумай ещё раз.
