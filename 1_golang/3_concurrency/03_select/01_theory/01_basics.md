# select: основы

`select` — конструкция для работы с несколькими каналами одновременно. Синтаксически похож на `switch`, но каждая `case`-ветка — это канальная операция.

## Синтаксис

```go
select {
case v := <-ch1:
    use(v)
case ch2 <- 42:
    fmt.Println("sent")
case <-time.After(time.Second):
    fmt.Println("timeout")
}
```

Каждая case — отправка или приём. Выполняется первая готовая. Если готовых несколько — выбирается случайно. Если ни одна не готова — `select` блокируется (если нет `default`).

## Отправка / приём / таймер

- `v := <-ch` — приём.
- `ch <- x` — отправка.
- `case <-time.After(d)` — таймаут.
- `case <-ctx.Done()` — отмена через контекст.

## Без default

`select` блокируется до первой готовой ветки. Используется, когда нужно ждать «что первое придёт».

## С default

`select` становится «non-blocking»: если ни одна ветка не готова — сразу `default`:

```go
select {
case v := <-ch:
    use(v)
default:
    // канал пуст, ничего не ждём
}
```

## Общие паттерны

- ждать значение **или** таймаут;
- ждать значение **или** отмену контекста;
- мультиплексировать несколько источников;
- реализовать «non-blocking send/recv».

## Правила

- `case` должна содержать только канальную операцию, не произвольное выражение.
- `select {}` без веток блокирует навсегда — иногда используется для «keep main alive», но чаще это плохой знак.
- `break` внутри select выходит из select, не из внешнего цикла. Для выхода из for используй label.

## Чего не умеет

- Выбирать по приоритету (все ветки равноправны; если нужен приоритет — пиши вложенные select).
- Timeout «от начала select» без `time.After` — нужно явно.
- Не работает с обычными переменными, только каналы и timers/context (которые тоже каналы внутри).

## Idiom: select с ctx.Done

```go
for {
    select {
    case <-ctx.Done():
        return ctx.Err()
    case job := <-jobs:
        process(job)
    }
}
```

Каждая долгоживущая горутина должна уметь реагировать на отмену контекста.
