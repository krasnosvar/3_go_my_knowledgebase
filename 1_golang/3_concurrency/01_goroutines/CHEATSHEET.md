# Горутины — шпаргалка

Подробности и объяснения — в [01_theory/](./01_theory/). ⚠️ — частая ловушка.
Версии Go указаны там, где поведение зависит от них.

## Запуск и модель

Подробно: [01_basics.md](./01_theory/01_basics.md).

| Задача | Код / факт |
| :--- | :--- |
| Запустить функцию в горутине | `go doWork()` |
| Запустить замыкание с аргументом | `go func(x int) { ... }(42)` |
| Результат горутины | теряется: `go` — не future; возвращать через канал или общую структуру под синхронизацией |
| Модель планировщика | GMP: **G** — горутина, **M** — поток ОС, **P** — слот планирования; число P = `GOMAXPROCS` (обычно = число CPU) |
| Вытеснение | асинхронный preemption с Go 1.14: «вечный» цикл без вызовов не блокирует остальных |
| Стоимость | старт ~1–2 µs, стек ~2 КБ и растёт; миллион горутин — норма |
| Конец программы | возврат из `main` завершает процесс, остальные горутины убиваются |
| Отмена горутины | снаружи нельзя; только кооперативно — `ctx.Done()` / канал-сигнал |
| ID горутины | в публичном API нет |
| `panic` в горутине | роняет весь процесс; `recover` работает только внутри **той же** горутины |

## Ожидание

Подробно: [02_waiting.md](./01_theory/02_waiting.md).

| Нужно | Инструмент |
| :--- | :--- |
| Дождаться N горутин без результата | `sync.WaitGroup`: `Add` → `go` → `defer Done()` → `Wait()` |
| То же короче (Go 1.25+) | `wg.Go(func() { ... })` — сам делает `Add(1)` и `Done()` |
| Дождаться одну горутину | `done := make(chan struct{})`; в горутине `close(done)`; снаружи `<-done` |
| Результаты от N горутин | канал с буфером `len(jobs)` или срез с записью по своему индексу |
| Первая ошибка + отмена остальных | `g, ctx := errgroup.WithContext(ctx)`; `g.Go(func() error {...})`; `g.Wait()` (`golang.org/x/sync/errgroup`) |

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	jobs := []int{1, 2, 3, 4}
	results := make([]int, len(jobs)) // каждая горутина пишет в свой индекс — без гонки

	var wg sync.WaitGroup
	for i, j := range jobs { // Go 1.22+: i, j — новые на каждой итерации
		wg.Add(1) // до go, не внутри горутины
		go func() {
			defer wg.Done()
			results[i] = j * j
		}()
	}
	wg.Wait()
	fmt.Println(results) // [1 4 9 16]
}
```

## Захват переменной цикла

Подробно: [03_loop_capture.md](./01_theory/03_loop_capture.md).

| Версия / способ | Поведение |
| :--- | :--- |
| До Go 1.22 | одна переменная на весь цикл → замыкания видят последнее значение (`3 3 3`) |
| Go 1.22+ (`go 1.22` в `go.mod`) | переменная создаётся заново на каждой итерации (`0 1 2`) |
| Работает в любой версии | параметр: `go func(v Item) { ... }(v)` |
| Работает в любой версии | локальная копия: `v := v` перед `go func()` |
| `defer f.Close()` в цикле | все `Close` выполнятся после выхода из функции, а не в конце итерации → тело итерации в отдельную функцию |

## Утечки

Подробно: [04_leaks.md](./01_theory/04_leaks.md).

| Сценарий утечки | Исправление |
| :--- | :--- |
| Отправка в канал, который никто не читает | буфер 1 для «может быть никому не нужен» результата: `make(chan R, 1)` |
| Читатель ушёл по таймауту, горутина висит на `ch <- r` | тот же буфер 1 |
| Бесконечный `for` без условия выхода | `select` с веткой `<-ctx.Done()` → `return` |
| `for { select { case <-ticker.C: } }` без отмены | добавить `case <-ctx.Done(): return` |

## Когда горутина нужна / не нужна

Подробно: [06_use_cases.md](./01_theory/06_use_cases.md).

| Нужна | Не нужна |
| :--- | :--- |
| Независимые I/O-запросы параллельно (latency = max, а не сумма) | последовательный код без блокирующих операций |
| Фоновые задачи сервиса с `ctx` для graceful shutdown | одна короткая функция, результат которой ждут сразу |
| Batch-обработка кусками, pipeline, имитация нагрузки в тестах | накладные расходы синхронизации больше выигрыша |

## Ловушки

- ⚠️ `go f()` в конце `main` без ожидания — горутина не успеет выполниться.
- ⚠️ `time.Sleep` «чтобы успели» — не синхронизация, только нестабильные тесты.
- ⚠️ `runtime.Gosched()` не заменяет синхронизацию.
- ⚠️ `wg.Add(1)` внутри горутины — `Wait()` может вернуться раньше.
- ⚠️ `Done()` не в `defer` — пропустится при раннем `return`/panic, `Wait()` зависнет.
- ⚠️ Передача `sync.WaitGroup` по значению — копия, учёт ломается; передавать `*sync.WaitGroup`.
- ⚠️ Горутина без пути выхода (`ctx`, `done`, закрытие канала) = утечка.
- ⚠️ `go handle(msg)` на каждое сообщение без лимита → неограниченный рост горутин (см. [07_patterns](../07_patterns/CHEATSHEET.md)).
- ⚠️ Даже на Go 1.22+ явный параметр замыкания читается понятнее.
