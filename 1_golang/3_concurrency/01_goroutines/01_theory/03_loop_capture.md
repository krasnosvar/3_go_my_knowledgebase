# Loop capture (захват переменной цикла)

Классическая ошибка Go до версии 1.22.

## Проблема

```go
for _, v := range values {
    go func() {
        process(v) // все горутины видят одно и то же значение v
    }()
}
```

Переменная `v` до Go 1.22 — **одна на всё тело цикла**. Горутины запускаются асинхронно и к моменту выполнения `process(v)` переменная уже может содержать последнее значение.

## Исправления

### 1. Передавать как параметр

```go
for _, v := range values {
    go func(v Item) {
        process(v)
    }(v)
}
```

Самый надёжный способ. Работает во всех версиях Go.

### 2. Создавать локальную копию

```go
for _, v := range values {
    v := v // shadow: новая переменная в scope тела
    go func() {
        process(v)
    }()
}
```

Часто пишется короче и не требует менять сигнатуру замыкания.

### 3. Go 1.22+

С Go 1.22 переменная цикла создаётся **заново на каждой итерации**. Но:

- это работает только в Go 1.22+;
- включается через `go 1.22` в `go.mod`;
- нужно учитывать при миграции.

## Та же ошибка в defer

```go
for _, f := range files {
    f, err := open(f)
    if err != nil { return err }
    defer f.Close() // все close выполнятся ПОСЛЕ цикла
}
```

Правильно — вынести тело в отдельную функцию или явно вызывать `Close()` в конце итерации.

## Та же ошибка в goroutine + канал

```go
ch := make(chan int, len(xs))
for _, x := range xs {
    go func() { ch <- x }() // все отправят последнее значение
}
```

Решение то же — параметр или локальная копия.

## Проверка в тестах

Включай `-race` (см. race_conditions). Эта ошибка часто «залипает» и стреляет только под нагрузкой. Тесты с гонкой ловят её раньше.

## Правило

Любая горутина или defer внутри цикла, использующие переменную цикла, — повод внимательно подумать о захвате. Даже после Go 1.22 — явный параметр читается понятнее.
