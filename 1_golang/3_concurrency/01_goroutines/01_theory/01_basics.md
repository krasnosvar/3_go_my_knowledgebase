# Goroutines: основы

Goroutine — лёгкий поток выполнения, управляемый рантаймом Go. Она дешевле OS-thread, стартует в несколько килобайт стека и может расти динамически.

## Запуск

```go
go doWork()

go func(x int) {
    fmt.Println(x)
}(42)
```

Ключевое слово `go` перед вызовом — и функция начинает выполняться в отдельной goroutine. Возвращаемые значения теряются: это не `future`.

## Модель GMP

Рантайм Go использует три сущности:

- **G** (goroutine) — логическая задача.
- **M** (machine) — OS-thread.
- **P** (processor) — логический «слот» для планирования.

Количество `M` регулируется рантаймом. Количество `P` — по умолчанию равно `GOMAXPROCS` (обычно = число CPU).

## Невытесняющее vs вытесняющее планирование

С Go 1.14 планировщик умеет вытеснять горутины (асинхронный preemption). Это значит, что даже «вычислительная» горутина без блокирующих вызовов не заблокирует остальных.

## Стоимость

- Запуск — ~1-2 µs.
- Начальный стек — ~2 КБ, растёт по мере необходимости.
- Миллион горутин — норма для Go, в отличие от классических тредов.

## main-горутина

`main()` сам работает в горутине. Как только она завершится — процесс выйдет, даже если другие горутины ещё работают.

```go
func main() {
    go fmt.Println("never printed")
}
```

## Без блокировки — без результата

Go не помогает тебе дождаться завершения горутины. Это твоя задача — канал, `sync.WaitGroup`, `context`, `errgroup`.

## Детали, о которых часто забывают

- Нельзя «отменить» запущенную горутину. Отмена — через контекст или канал-сигнал.
- Горутина не имеет ID (в API).
- `panic` в горутине убивает весь процесс, если её не поймать через `recover` внутри той же горутины.
