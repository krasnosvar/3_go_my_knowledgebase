# Типы профилей

`pprof` поддерживает несколько типов данных. Полезно знать, что каждый показывает.

## CPU profile

- Эндпоинт: `/debug/pprof/profile?seconds=30`
- Что показывает: время CPU, потраченное на каждую функцию.
- Когда нужен: «приложение занимает много CPU».
- Метод сбора: семплирование (по умолчанию 100 раз/сек) — без заметного оверхеда.

В выводе ищем функции с большим `flat` или `cum`:

- `flat` — время в самой функции.
- `cum` — время в функции + всё, что она вызвала.

## Heap profile

- Эндпоинт: `/debug/pprof/heap`
- Показывает: где аллоцируется память.
- Snapshot текущего состояния, не накопленного с старта.

Два режима:

- `inuse_space` — что лежит сейчас (по умолчанию).
- `alloc_space` — сколько всего было выделено за время жизни.

Утечка → `inuse_space` растёт, `alloc_space` тоже. Просто горячий аллокатор → растёт `alloc_space`, `inuse_space` стабильный.

## Goroutine profile

- Эндпоинт: `/debug/pprof/goroutine`
- Показывает: стек-трейсы всех живых горутин.
- Когда нужен: подозрение на leak горутин, hang.

`?debug=1` — компактный вывод сгруппированный по стек-трейсу. `?debug=2` — полный stack каждой горутины.

Если при `runtime.NumGoroutine()` число растёт — снимай этот профиль и ищи общий стек, по которому застряли тысячи горутин.

## Mutex profile

- Эндпоинт: `/debug/pprof/mutex`
- Показывает: места contention'а (где горутины ждут lock).
- По умолчанию **отключён**. Включается через:

```go
runtime.SetMutexProfileFraction(1) // 1 = семплировать каждый
```

Полезно для locking-heavy сервисов.

## Block profile

- Эндпоинт: `/debug/pprof/block`
- Показывает: длительные блокировки (каналы, mutex'ы).
- Тоже отключён по умолчанию:

```go
runtime.SetBlockProfileRate(1)
```

## Allocs profile

- Эндпоинт: `/debug/pprof/allocs`
- Сколько аллокаций случалось — все, не только живые.
- Полезен, когда нужно найти hot allocator (например, в hot loop).

## Trace

Не профиль, а полная событийная запись:

```
go tool trace trace.out
```

Показывает планировщик, GC паузы, сетевые блокировки в визуальном таймлайне. Тяжелее для анализа, но даёт полную картину.

## Когда что использовать

- Тормозит CPU → profile.
- Растёт память → heap (inuse и alloc).
- Подвисло, не отвечает → goroutine.
- Низкая параллельность под нагрузкой → mutex / block.
- Странные паузы → trace (видно GC stop-the-world).

## Правило

Не угадывай — снимай профиль. Один pprof-сеанс показывает больше, чем час «оптимизации по интуиции».
