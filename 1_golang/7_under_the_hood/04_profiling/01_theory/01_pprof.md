# Профилирование в Go (pprof)

Профилирование — это анализ того, на что программа тратит системные ресурсы (процессор, оперативную память), а также отслеживание зависших горутин и проблем с конкурентным доступом (мьютексы, блокировки).

### Как работает профилирование (net/http/pprof)

В современных реальных приложениях и микросервисах профилировщик чаще всего подключают не через сохранение локальных файлов, а через **HTTP-стандартный пакет** — `net/http/pprof`. 
Если мы импортируем `_ "net/http/pprof"` и запускаем HTTP-сервер, Go автоматически регистрирует роутеры, которые начинают отдавать метрики профилировщика по адресу `/debug/pprof/`.

Мы подготовили отличный **наглядный полигон для новичков** в файле `main.go`. Скрипт симулирует 4 типовые проблемы, которые вы сможете найти с помощью профилировщика:
1. **CPU Intensive (`cpuHeavy`):** бесконечное рекурсивное вычисление чисел Фибоначчи.
2. **Memory Leak (`memoryLeaky`):** постоянное выделение и сохранение новых слайсов байт (настоящая утечка памяти в глобальную переменную, которая со временем убьет приложение (OOM)).
3. **Goroutine Leak (`goroutineLeak`):** запуск 100 горутин, которые навсегда зависают на чтении из пустого канала.
4. **Mutex Contention (`mutexContention`):** горутины бесконечно дерутся за один мьютекс и подолгу его держат, создавая очередь (одна горутина работает - остальные ждут).

*(Важно: В коде дополнительно вызваны встроенные функции `runtime.SetBlockProfileRate` и `runtime.SetMutexProfileFraction`, без них профили блокировок и мьютексов отключены по умолчанию, чтобы не тратить процессор).*

### 🚀 Запуск и Сбор Профилей

1. Запустите приложение:
```bash
go run main.go
```
*Оно "повиснет" в консоли — это абсолютно нормально, оно работает как бесконечный веб-сервер.*

2. Вы можете открыть браузер и посмотреть общую стартовую статистику глазами (сколько висит горутин, сколько выделено кучи):
[http://localhost:8080/debug/pprof/](http://localhost:8080/debug/pprof/)

3. **Сбор и анализ сырого профиля (откройте новую вкладку терминала!):**
Утилита `go tool pprof` умеет подключаться к запущенному серверу и скачивать требуемый ей профиль напрямую из сети.

**Анализ CPU (pprof будет собирать работу приложения ровно 5 секунд, подождите):**
```bash
go tool pprof http://localhost:8080/debug/pprof/profile?seconds=5
```

**Анализ Памяти (Куча / Heap):**
```bash
go tool pprof http://localhost:8080/debug/pprof/heap
```

**Просмотр зависших Горутин:**
```bash
go tool pprof http://localhost:8080/debug/pprof/goroutine
```

*Когда в терминале появится интерактивная оболочка `(pprof) >`, введите команду `top`, чтобы сразу увидеть "виновников" тормозов (наши симуляции из `main.go`).*

### 🌐 Просмотр в браузере (Web UI)

Для просмотра результатов в виде удобного цветного графа в обход скучной консоли, добавьте флаг `-http` к вызову `pprof`. 
Укажите любой другой свободный порт (например, `:8081`), чтобы веб-интерфейс pprof не попытался занять порт самого приложения (`8080`):

```bash
# Красивый браузерный Web UI для процессора (ждет 5 сек)
go tool pprof -http=:8081 http://localhost:8080/debug/pprof/profile?seconds=5

# Красивый браузерный Web UI для памяти
go tool pprof -http=:8081 http://localhost:8080/debug/pprof/heap
```

**Важно:** для отрисовки графов у вас должен быть установлен системный пакет **Graphviz**:
* **Fedora/RHEL/CentOS:** `sudo dnf install graphviz`
* **Ubuntu/Debian:** `sudo apt-get install graphviz`
* **macOS (Homebrew):** `brew install graphviz`

### 🧠 Как читать результаты профилирования?

Когда вы открываете графический интерфейс (или пишете команду в консоли), вы видите числа и метрики, главные из которых: **flat** и **cum** (cumulative).

#### Основные метрики:
1. **flat** — сколько ресурсов потребила **сама эта функция** (без учета функций, которые она вызывала внутри себя).
2. **flat%** — её доля (%) от общих затрат программы.
3. **cum (cumulative)** — сколько ресурсов потребила эта функция **И все остальные функции, которые она вызвала** (суммарно, накопительно).

*Пример:* функция `A` работает сама по себе 1 секунду, но вызывает функцию `B`, которая работает 9 секунд. Для функции `A`: `flat = 1s`, `cum = 10s`.

#### Главные команды (в консоли `pprof >`):
* `top` (или `top10`) — выводит список функций, наиболее жадно жрущих ресурсы. Это всегда ваш первый шаг!
* `list <название_функции>` — показывает **исходный код** с затратами ресурсов прямо по строчкам! Напишите `list cpuHeavy` или `list memoryLeaky` и посмотрите эту магию вживую!
* `traces` — показывает цепочки вызовов.

#### Как читать Граф (Web UI -> View -> Graph):
* **Крупные узлы (коробочки)** — самые тяжелые функции. Чем массивнее коробка, тем выше ее локальная доля `flat`.
* **Красный цвет** — большое значение `cum` (это корень выявленной проблемы или важная транзитная функция).
* **Стрелки (Edges)** — цифры на пунктирах показывают, какой объем ресурсов "протек" при вызове одной функции из другой.

#### Режимы просмотра Памяти (Web UI вкладка Sample):
В графическом интерфейсе для памяти (`heap`) вы можете переключать 4 режима метрик:
1. `inuse_space` — сколько пямяти было выделено и **до сих пор висит в памяти** (отличный режим для поиска утечек!).
2. `inuse_objects` — сколько именно *штук объектов* висит сейчас в памяти.
3. `alloc_space` — сколько памяти **в принципе запрашивалось** с момента старта (даже если GC уже успел всё подчистить). Ищет неоптимальные участки, которые слишком часто мусорят аллокациями и вешают Сборщик Мусора (GC).
4. `alloc_objects` — суммарное количество всех созданных объектов.

### 🕵️‍♂️ Практика: найдите остальные проблемы!

Вы запустили приложение (полигон). Попробуйте выполнить команды в консоли и через `top`, а затем через `list` обнаружить наши намеренно спрятанные проблемы `goroutineLeak` и `mutexContention`:

* **Ищем заблокированные мьютексы (Mutex Contention):**
  ```bash
  go tool pprof http://localhost:8080/debug/pprof/mutex
  ```
  *(Введите `top` — вы увидите функцию `mutexContention`. Затем введите `list mutexContention` — и обозреватель укажет прямо на ту самую строку с наглым `mu.Lock()!`).*
  
* **Ищем зависания в местах ожиданий (Block Profile):**
  ```bash
  go tool pprof http://localhost:8080/debug/pprof/block
  ```
