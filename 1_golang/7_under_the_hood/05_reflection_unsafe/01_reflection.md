# Рефлексия (Reflection) в Go - Содержание

> Рефлексия в Go — это мощный, но «опасный» инструмент, который позволяет программе исследовать собственную структуру во время выполнения. Это база для таких вещей, как JSON-сериализация, ORM или DI-контейнеры.

## Основные темы:

### 1. **Основы: Type и Value**
Два столпа, на которых держится пакет `reflect`:

- **reflect.Type** - интерфейс, описывающий тип переменной
  - Имя типа (`Name()`, `String()`)
  - Методы типа (`NumMethod()`, `Method()`)
  - Поля структуры (`NumField()`, `Field()`)
  - Типы аргументов и результатов функций
  - Получение: `reflect.TypeOf(value)`
  
- **reflect.Value** - структура, содержащая конкретное значение
  - Доступ к значению (`Int()`, `String()`, `Bool()`)
  - Манипуляция значением (`Set()`, `SetInt()`, `SetString()`)
  - Получение типа из Value: `value.Type()`
  - Получение: `reflect.ValueOf(value)`
  
- **Kind** - «биологический вид» типа
  - Базовые виды: `Int`, `String`, `Bool`, `Float64`
  - Композитные виды: `Struct`, `Slice`, `Array`, `Map`, `Chan`
  - Специальные: `Ptr`, `Interface`, `Func`, `UnsafePointer`
  - Отличие от Type: тип `User` имеет Kind `Struct`
  - Получение: `value.Kind()` или `typ.Kind()`

### 2. **Законы рефлексии (The Laws of Reflection)**
Три золотых правила, которые нужно понимать, чтобы не ловить паники:

#### Закон 1: Из интерфейса в объект рефлексии
- Как `interface{}` превращается в `reflect.Type` и `reflect.Value`
- `reflect.TypeOf(x)` принимает `interface{}`
- `reflect.ValueOf(x)` принимает `interface{}`
- Автоматическое преобразование любого значения в пустой интерфейс

#### Закон 2: Из объекта рефлексии в интерфейс
- Метод `.Interface()` для возврата к обычным типам
- Type assertion для получения конкретного типа
- Восстановление исходного значения: `v.Interface().(OriginalType)`

#### Закон 3: Изменяемость (Settability)
- Чтобы изменить значение через рефлексию, оно должно быть «устанавливаемым»
- Требуется передача указателя: `reflect.ValueOf(&x).Elem()`
- Проверка: `value.CanSet()`
- Адресуемость: `value.CanAddr()`
- Понимание разницы между значением и указателем

### 3. **Работа со структурами**

- **Обход полей структуры**
  - `NumField()` - количество полей
  - `Field(i)` - получение i-го поля
  - `FieldByName(name)` - поиск поля по имени
  - `FieldByIndex([]int)` - доступ к вложенным полям
  
- **Struct Tags (теги структур)**
  - Чтение метаданных: `field.Tag.Get("json")`
  - Парсинг тегов: `field.Tag.Lookup("db")`
  - Распространенные теги: `json`, `xml`, `db`, `yaml`, `validate`
  - Создание custom тегов для своих нужд
  
- **Работа с полями**
  - Получение типа поля: `field.Type`
  - Получение значения поля: `structValue.Field(i)`
  - Изменение значения поля: `structValue.Field(i).Set(newValue)`
  - Экспортируемые vs неэкспортируемые поля
  - Анонимные (embedded) поля

### 4. **Динамический вызов методов**

- **Поиск методов**
  - `NumMethod()` - количество методов
  - `Method(i)` - получение i-го метода
  - `MethodByName(name)` - поиск метода по имени
  
- **Вызов методов**
  - `method.Call(args)` - вызов метода с аргументами
  - Подготовка аргументов: `[]reflect.Value{...}`
  - Обработка результатов вызова
  - Вызов методов с variadic параметрами
  
- **Различие Pointer vs Value receivers**
  - Методы на указателе vs методы на значении
  - Автоматическое разыменование в рефлексии

### 5. **Динамическое создание типов (Make)**

Рефлексия позволяет создавать объекты типов, которые не были известны на этапе компиляции:

- **Создание слайсов**
  - `reflect.MakeSlice(typ, len, cap)` - создание слайса
  - Добавление элементов: `reflect.Append(slice, values...)`
  - `reflect.SliceOf(elemType)` - создание типа слайса
  
- **Создание map**
  - `reflect.MakeMap(typ)` - создание мапы
  - `map.SetMapIndex(key, value)` - установка значения
  - `map.MapIndex(key)` - получение значения
  - Итерация: `MapRange()` или `MapKeys()`
  - `reflect.MapOf(keyType, valueType)` - создание типа мапы
  
- **Создание новых экземпляров**
  - `reflect.New(typ)` - аналог `new(T)`, возвращает указатель
  - `reflect.Zero(typ)` - нулевое значение типа
  - Инициализация структур динамически
  
- **Создание каналов**
  - `reflect.MakeChan(typ, buffer)` - создание канала
  - `reflect.ChanOf(dir, elemType)` - создание типа канала
  - Отправка/получение через рефлексию: `Send()`, `Recv()`

### 6. **Работа с функциями**

- **Анализ сигнатуры функции**
  - `NumIn()` - количество входных параметров
  - `In(i)` - тип i-го параметра
  - `NumOut()` - количество возвращаемых значений
  - `Out(i)` - тип i-го возвращаемого значения
  - `IsVariadic()` - проверка variadic функции
  
- **Вызов функций**
  - `func.Call(args)` - вызов функции
  - `func.CallSlice(args)` - вызов variadic функции
  - Обработка паник и ошибок при вызове
  
- **Создание функций динамически**
  - `reflect.MakeFunc(typ, implementation)` - создание функции
  - Использование для proxy, mock, wrapper функций

### 7. **Работа с интерфейсами**

- **Проверка реализации интерфейса**
  - `typ.Implements(interfaceType)` - проверка реализации
  - `typ.AssignableTo(targetType)` - проверка присваиваемости
  - `typ.ConvertibleTo(targetType)` - проверка конвертируемости
  
- **Извлечение значения из интерфейса**
  - `value.Elem()` - разыменование интерфейса/указателя
  - Работа с пустым интерфейсом `any`

### 8. **Указатели и адресация**

- **Работа с указателями**
  - `reflect.PtrTo(typ)` - создание типа указателя
  - `value.Addr()` - получение адреса значения
  - `value.Elem()` - разыменование указателя
  - `value.IsNil()` - проверка на nil
  - `value.Pointer()` - получение uintptr адреса
  
- **Косвенная адресация (Indirect)**
  - `reflect.Indirect(value)` - автоматическое разыменование

### 9. **Производительность и безопасность**

Почему рефлексию называют «тяжелой артиллерией»:

- **Runtime Overhead (накладные расходы)**
  - Почему код на рефлексии в разы медленнее обычного
  - Отсутствие оптимизаций компилятора (инлайнинг, девиртуализация)
  - Много аллокаций в куче (boxing/unboxing)
  - Динамический поиск типов и методов
  - Бенчмарки: обычный код vs рефлексия (10x-100x разница)
  
- **Type Safety (безопасность типов)**
  - Как рефлексия обходит проверку типов на этапе компиляции
  - Почему это часто приводит к `panic` в runtime
  - Типичные паники: `reflect: call of X on Y Value`
  - Необходимость ручной проверки типов
  
- **Когда НЕ стоит использовать рефлексию**
  - Если можно решить через интерфейсы
  - Если можно использовать кодогенерацию
  - В hot paths (критичных по производительности местах)
  
- **Когда рефлексия оправдана**
  - Сериализация/десериализация (JSON, XML, YAML)
  - ORM и маппинг баз данных
  - Dependency Injection контейнеры
  - Валидация структур
  - Тестовые фреймворки и моки
  - CLI парсеры с автоматическим биндингом

### 10. **Практические паттерны**

- **Универсальный DeepEqual**
  - Сравнение любых структур рекурсивно
  - `reflect.DeepEqual(a, b)`
  
- **Автоматическая сериализация**
  - Обход полей с тегами для JSON/XML
  - Создание custom encoder/decoder
  
- **Валидация структур**
  - Проверка обязательных полей
  - Валидация по тегам `validate:"required,email"`
  
- **Копирование структур (Deep Copy)**
  - Рекурсивное клонирование значений
  - Обработка циклических ссылок
  
- **Динамический маппинг**
  - `map[string]interface{}` → struct
  - struct → `map[string]interface{}`

### 11. **Безопасная работа с рефлексией**

- **Проверки перед операциями**
  - `value.IsValid()` - валидность значения
  - `value.CanSet()` - возможность изменения
  - `value.CanAddr()` - возможность получения адреса
  - `value.CanInterface()` - возможность преобразования в interface{}
  
- **Обработка паник**
  - Использование `defer` + `recover` при работе с рефлексией
  - Валидация типов перед операциями
  
- **Избежание распространенных ошибок**
  - Работа с nil значениями
  - Попытка Set на неадресуемом значении
  - Некорректные type assertions

### 12. **Продвинутые техники**

- **Создание типов во время выполнения**
  - `reflect.StructOf()` - создание структур динамически (Go 1.7+)
  - Создание анонимных типов
  
- **Unsafe и рефлексия**
  - Комбинация `reflect` и `unsafe` для экстремальной производительности
  - Прямой доступ к памяти через рефлексию
  
- **Кеширование результатов рефлексии**
  - Сохранение Type и StructField для переиспользования
  - Уменьшение overhead через предварительный анализ
