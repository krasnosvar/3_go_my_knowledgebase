Escape Analysis
Это анализ, который делает компилятор Go, чтобы решить, где выделить память для переменной — на стеке или в куче.

Стек — быстрая память, автоматически очищается при выходе из функции. Выделение и освобождение почти бесплатны.
Куча — медленнее, требует работы сборщика мусора (GC). Используется когда переменная должна жить дольше, чем функция.

Когда переменная "убегает" в кучу:
Возвращается указатель на локальную переменную

gofunc bad() *int {
    x := 42  // убежит в кучу
    return &x
}

Сохраняется в структуру/слайс, которые живут дольше

govar global []int
func append() {
    x := 42  // убежит в кучу
    global = append(global, x)
}

Используется в горутине

gofunc launch() {
    x := 42  // убежит в кучу
    go func() {
        fmt.Println(x)
    }()
}

Слишком большая для стека

gofunc huge() {
    x := [1000000]int{}  // убежит в кучу
}

Как проверить:
bashgo build -gcflags='-m'  # покажет что и куда убегает
Почему важно:

Много аллокаций в куче → больше работы для GC → медленнее программа
В высоконагруженных системах стараются минимизировать escape
Но не нужно фанатично оптимизировать — компилятор умный, сначала профилируй!
